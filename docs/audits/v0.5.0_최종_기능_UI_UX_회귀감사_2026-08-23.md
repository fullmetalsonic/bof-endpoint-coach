## 2. 감사 방법

1. 문헌 모델·샘플 앵커·오차대장·계수추천·백업 구조를 소스와 단위테스트로 확인했습니다.
2. 합성 DEMO를 1920×1080에서 실제 버튼으로 조작했습니다.
3. 화면을 보기만 하지 않고 저장 결과, 다음 행동 변화, 예상값 변화, 이력 보존, 버튼 비활성을 확인했습니다.
4. 최종 화면을 `docs/manual/screenshots/v0.5.0/`에 보존하고 각각 다시 열어 잘림·정렬·문구를 검사했습니다.
5. 사용자가 제공한 1280×905 참조 시안과 동일 크기의 현재 G6 화면을 한 번의 비교 입력으로 함께 열어 정보구조를 비교했습니다.
6. 발견한 문제를 수정한 뒤 ESLint와 전체 Vitest를 다시 실행했습니다.

## 5. 참조 시안 대비 시각 감사

참조 시안과 현재 G6 화면은 모두 1280×905 상태로 비교했습니다.

### 유지한 강점

- 상단 요약, 좌측 G0~G8, 중앙 출강 검토, 우측 Data Ledger, 하단 6개 행동이라는 산업용 정보구조를 유지했습니다.
- 검은 실측점, 흰 예상점, 녹색 목표 범위의 빠른 판독 방식을 유지했습니다.
- 장식용 이모티콘 대신 동일한 선형 아이콘 체계와 텍스트 상태를 사용했습니다.
- 현재 구현은 참조보다 `현재 해야 할 일`, 진행 순서, 비활성 이유, 정정·복구 경계를 더 명확히 표시합니다.

### 허용한 차이

- 학습·도움말 메뉴와 동시차지 탭이 추가되어 상단 밀도가 높습니다.
- 중앙 안내가 커져 1280×905 한 화면에는 품질행 3개가 우선 보입니다. 회사 기준 1920×1080에서는 6개 행과 하단 행동을 함께 확인할 수 있고, 나머지는 세로 스크롤 가능합니다.
- P·Mn·Si·S까지 수치예상을 제공하므로 원본 4행보다 데이터가 많습니다.

## 7. 접근성·학습성 감사

### 확인한 강점

- 모든 주요 폼은 보이는 레이블과 단위를 가집니다.
- 필수·계산 핵심·정확도 권장·선택을 색만이 아니라 텍스트로 표시합니다.
- 버튼은 행동 동사를 사용하고 단계 전환은 `G3 → G4`처럼 결과를 먼저 보여 줍니다.
- 오류는 저장 뒤가 아니라 입력창 안에서 이유를 표시합니다.
- 회색 버튼에도 가능한 단계를 표시해 장식용 버튼처럼 보이지 않습니다.
- 정정·초기화·복구는 확인창과 사유를 요구합니다.
- 한쪽 목표만 있는 경우 `목표 상한/하한`으로 읽습니다.

### 남은 사용성 한계

- 계산계수 항목이 많아 처음 사용자는 모두 이해하기 어렵습니다. 기본 문헌값을 유지하고 현장 검토자가 필요한 항목만 수정해야 합니다.
- 금일 현황과 알림은 의도적으로 단순한 요약 화면입니다. 공식 생산 집계나 설비 알람이 아닙니다.
- 760px 화면은 확인용이며, 하단 작업과 많은 품질행을 동시에 보기에는 데스크톱이 적합합니다.

## 9. GitHub 게시 후 자동 회귀 재감사

### 발견·수정

- 최초 게시 커밋의 Chromium E2E는 22개 중 13개가 실패했다. 실제 화면 기능 고장이 아니라 초보자 화면의 주 행동을 `신규 차지`에서 `실제 수동 입력 시작`으로 명확히 바꾼 뒤 시험 선택자가 예전 문구에 고정된 회귀였다.
- 빈 작업 화면과 진행 차지 화면의 차지 입력 버튼을 함께 찾는 `openNewHeat` 시험 헬퍼를 추가하고, 중복된 `기준 정보` 버튼은 상단 주 메뉴 범위로 한정했다.
- 배포문서 자동검사를 v0.4.0 3종에서 v0.5.0 4종으로 교체하고 초상세 처음사용자 설명서를 포함했다.
- 첫 재실행은 전체 성공이었으나 CSV ZIP 복원 1건이 기본 5초를 넘겨 재시도에서 통과했다. 해시검증 복원의 허용 대기시간을 15초로 명시하고 완료 뒤 버튼이 다시 활성화되는지 검사해 간헐성을 제거했다.
