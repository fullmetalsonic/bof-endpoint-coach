## 3. 기능 안정성 감사

다음 흐름을 합성 DEMO 또는 시험용 수동값으로 실제 조작했다.

- 처음 실행 작업자 이름 입력, DEMO/빈 작업 선택
- 신규 차지 생성, G0 기초입력, kg·t 단위 환산
- G0부터 G8까지 단계 전환, 샘플·분석·체크포인트·재취련·출강 입력
- 여러 진행 차지 전환과 데이터 분리
- 방금 입력 수정·무효, 마지막 단계 전환 취소, 차지 취소·삭제·보관, 출강 후 정정
- JSON 저장, 앱 자체 재읽기·해시검증, 불러오기 비교, 전체 교체, 7일 되돌리기
- 호환 CSV ZIP, Excel 보고서, 작업공간 초기화와 복구점 복원
- 설정 화면의 강종·재료·설비·계수·버전 저장
- 학습 가능성 판정, 성분별 추천, 학습실행 해시와 최신·오래됨 상태

초기 전체 Chromium 회귀에서 23건 중 12건이 실패했다. 11건은 v0.6 문구와 안전 대기상태를 반영하지 못한 구형 E2E 선택자·DB 버전·복원 절차였고, 1건은 1280px에서 상단 메뉴가 실제로 넘치는 레이아웃 결함이었다. 시험만 완화하지 않고 다음과 같이 구분해 고쳤다.

- E2E IndexedDB 헬퍼를 스키마 v2로 갱신했다.
- `저장`과 `저장 중`이 섞이지 않도록 정확한 버튼 이름을 사용했다.
- 기본 JSON 전체 교체·되돌리기와 구형 ZIP 보조 경로를 각각 시험했다.
- 1280px 이하 상단을 두 줄로 재배치해 본문 가로 넘침을 제거했다.
- 760px 저장상태 버튼의 빈 아이콘처럼 보이는 문제를 실제 데이터베이스 아이콘으로 수정했다.
- 긴 신규 차지 입력창 하단 행동 버튼을 고정해 현재 스크롤 위치에서도 취소·차지 시작을 확인할 수 있게 했다.

수정 후 Chromium·Chrome·Edge에서 같은 23개 전체 흐름이 각각 재시도 없이 통과했다.

첫 원격 Linux CI에서는 고정된 한국시간 `11:03`을 기대한 JSON 파일명 시험 1건이 UTC 환경에서 `02:03`으로 계산되어 실패했다. 실제 파일명 생성 결함이 아니라 시험의 시간대 고정 문제였으므로, 날짜·시각 형식과 접두·확장자는 엄격히 유지하되 특정 시간대 숫자를 강제하지 않도록 수정했다. 로컬 전체검증과 원격 CI를 다시 실행해 최종 상태를 판정한다.

## 4. 저장·복구·데이터 손상 감사

- 작업공간과 복구점은 IndexedDB v2의 분리 저장소를 사용한다.
- 대량 상태의 저장이 끝나기 전에 같은 창에서 다음 변경이 생기는 경우를 독립 리뷰에서 발견해, 자동저장 요청을 한 줄로 직렬화했다. 초기화·복구·JSON 전체 교체도 진행 중 저장이 끝나고 revision이 확정된 뒤 실행한다.
- 여러 창이 같은 저장소를 사용할 때 최신 개정 번호와 다른 창 저장을 감지하고 오래된 창을 읽기 전용으로 전환한다.
- JSON은 최대 50 MiB, 중첩 120단계, `__proto__`·`constructor`·`prototype` 위험 키를 제한한다.
- 해시가 맞아도 거짓 건수, 잘못된 설정, 중복 복구점, 조작로그 시간, 모델·학습 중복본 불일치를 거부한다.
- 불러오기 실패는 현재 IndexedDB를 변경하지 않는다. 성공 교체도 기존 상태를 보호 복구점으로 남긴다.
- 1,000개 차지 작업공간의 JSON 생성·검증·복원은 시험 환경에서 1.606초에 왕복했고 50 MiB 제한보다 작았다. 이는 현장 PC 성능 보증이 아니라 기본 대량 경로의 회귀 증거다.

상세 계약은 [v0.6 JSON 백업·복구 계약](../domain/v0.6_JSON_백업복구_계약.md)에 분리했다.

## 5. UI·UX·초보자 학습성 감사

### 유지한 시각 언어

- 사용자가 선택한 전문 업무형 화면을 기준으로 흰색·회색 바탕, 청색 현재상태, 녹색 정상범위, 황색 주의, 적색 위험을 유지했다.
- 장식용 이모티콘을 쓰지 않고 실제 아이콘 라이브러리와 텍스트 라벨을 함께 사용했다.
- 대시보드에서 차지 전환, 현재 G단계, 지금 해야 할 일, 품질 막대, 최근 샘플, Data Ledger, 6개 입력 버튼의 위치를 유지했다.

### 보강한 학습 단서

- 처음 실행에서 작업자 이름과 DEMO/빈 작업의 차이를 먼저 설명한다.
- 각 단계는 `입력 → 확인 → 단계 전환` 순서를 표시하고 지금 눌러야 할 버튼에 `지금 입력`을 붙인다.
- 입력창은 필수·선택, 계산 핵심, 단위, 현재시각 기본값과 수정 가능 여부를 함께 표시한다.
- 6개 품질 막대는 현재 실측, 종점 예상, 목표범위, 문헌 시나리오 범위와 예상 근거를 같은 행에서 비교한다.
- 저장·복구 화면은 내부 자동저장과 외부 JSON의 역할을 분리하고, XLSX는 복원 불가임을 명시한다.
- 학습 화면은 데이터가 부족할 때 값을 꾸며내지 않고 몇 건이 더 필요한지와 자동 적용되지 않는 이유를 표시한다.

### 화면별 확인

- 1920×1080: 전문 업무형 3열 대시보드, 하단 행동버튼까지 정상.
- 1280px: 상단 두 줄 재배치, 본문 가로 페이지 넘침 0.
- 760px: 핵심 카드는 세로 재배치하고 넓은 표는 내부 스크롤. 현장 주 사용 화면은 아님.
- 기본 키보드: 모달 이름 연결, Escape 닫기, 포커스 복귀와 버튼 비활성 상태를 자동시험했다.

실제 초보 참여자의 무설명 과업 성공률, 화면낭독기, Windows 고대비, 장갑·거리·조명 평가는 현장 관찰 없이는 PASS로 올리지 않는다.

## 6. 보안·오프라인 감사

- `npm audit --audit-level=moderate`: 취약점 0건.
- 공개 소스와 배포파일에 실제 회사 차지, 작업자 개인정보, 사내 기준, 현장 계수, API 키·비밀번호를 넣지 않았다.

## 9. 최종 안전 문구

v0.6.0은 공개 문헌·합성 DEMO로 동작하는 **설명 가능한 오프라인 학습 보조도구**다. 설비 제어, 안전 인터록, 표준작업, 출강 승인 또는 취련사의 판단을 대체하지 않는다. 실제 데이터에서 정확도·오류범위·적용 기준을 검증하고 현장 승인을 받기 전에는 현장 정확도를 주장하지 않는다.
