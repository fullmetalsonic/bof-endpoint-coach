## 1. 결론

구현·자동검증·독립 소스 리뷰 범위에서 **배포 후보 PASS**다. CRITICAL/HIGH 미해결 이슈는 0건이다. 다만 이는 기능 동작과 데이터 안전성 판정이며 실제 BOF 종점 정확도, 실제 회사 PC 정책, 현장 작업자의 무설명 성공률을 검증했다는 뜻은 아니다.

## 3. 값과 데이터 정합성

### 핵심 6개

| 항목 | 단위 | 표시 정밀도 | 입력 한계 |
| --- | --- | ---: | ---: |
| C | %p | 5자리 | 절대값 100 이하 |
| 온도 | °C | 1자리 | 절대값 500 이하 |
| P | %p | 5자리 | 절대값 100 이하 |
| Mn | %p | 5자리 | 절대값 100 이하 |
| Si | %p | 5자리 | 절대값 100 이하 |
| S | %p | 5자리 | 절대값 100 이하 |

- `BOFRC1` 복구문자열은 프로필 ID, 원본 계수버전, 계산식, 기준지문, 핵심 6개와 확인코드를 포함한다.
- 기준지문은 프로필 ID·계산식·28개 실제 적용 기본값으로 만든 SHA-256의 앞 12자리다.
- 확인코드는 카드 핵심 내용으로 만든 SHA-256의 앞 8자리다.
- 두 값은 전자서명이 아니라 아날로그 전사 오류와 잘못된 카드 혼합을 잡기 위한 축약 검사값이다.
- 원본 카드 계수버전이 초기화 후 현재버전과 달라도 동일 프로필·식·기준지문·확인코드면 복구한다. 원본 버전 ID는 출처에 보존한다.
- 수동복구 출처의 핵심 6개가 현재 보정값과 달라진 JSON은 설정 정합성 검사에서 차단한다.

### 상세 18개

- 상세값은 성분별 `학습 당시값`, `추천 증감`, `추천 후보값`이다.
- 같은 그룹·현재 계수버전의 최신 실행을 성분별 하나씩 고르고 오래된 중복 실행은 선택하지 않는다.
- 일부 성분만 있으면 나머지는 `근거 없음`으로 표시하며 값을 만들지 않는다.
- 복구 입력값은 참고 메타데이터로만 보존하고 종점 계산에 직접 쓰지 않는다.

## 6. 검증에서 발견하고 수정한 문제

### A-01 백업 시험의 앱 버전 고정

- 증상: 앱을 0.6.1로 올리자 백업 시험 1건이 `APP_VERSION === 0.6.0`을 기대해 실패했다.
- 원인: 앱 버전과 백업 계약 버전을 하나로 취급한 오래된 시험 기대값이었다.
- 수정: 앱 `0.6.1`, JSON 스키마 `0.6.0`을 각각 검증하도록 분리했다.
- 재검증: 전체 Vitest 137건 PASS.

### A-02 카드 출처가 후속 직접수정 뒤 남는 문제

- 증상: 카드 복구 뒤 오프셋을 직접 수정하거나 새 학습 추천을 적용해도 이전 카드 출처가 현재값 출처처럼 남을 수 있었다.
- 원인: 보정값 변경 경로가 `manualRecoverySource`를 무효화하지 않았다.
- 수정: 직접 수정·새 추천 적용 시 이전 카드 출처를 지우고, JSON 설정 검증에서 카드 핵심 6개와 현재값 불일치를 차단했다.
- 재검증: 단위·컴포넌트 10건, 세 브라우저 카드 E2E, 전체 check와 전체 브라우저 회귀 PASS.

### A-03 화면 캡처 저장경쟁

- 증상: 처음 두 캡처 실행에서 합성 학습실행을 넣기 전에 IndexedDB 읽기가 끝나 상세 화면을 만들지 못했다.
- 원인: 브라우저 안 비동기 IndexedDB 완료를 기다리지 않는 캡처 자동화 경쟁이었다. 앱 기능 오류는 아니었다.
- 수정: 실제 트랜잭션 완료를 반복 확인한 뒤 화면을 여는 방식으로 변경했다.
- 재검증: 6장 캡처 완료, 각 화면 육안 확인 PASS.

## 7. 독립 리뷰 결과

- 모듈은 필드·단위, 문자열/지문, 카드 스냅샷, 수동복구 도메인, 보기·입력 UI로 분리되어 있다.
- 카드 복구는 현재 설정을 즉시 바꾸지 않으며 정상 설정 버전관리·복구점·자동저장 경로를 우회하지 않는다.
- JSON 필수 스키마를 올리지 않아 v0.6.0 백업 계약을 유지한다.
- 핵심 확인코드 변조, 빈값·범위, 상세 산식, 프로필·계산식·기준지문 불일치, 기존 차지 소급적용을 시험했다.
- 공개 산출물에는 실제 회사 차지·현장계수·개인정보를 넣지 않았고 화면은 합성 DEMO다.
- 검토 완료 후 CRITICAL/HIGH 미해결 이슈 0건이다.
