## 2. 감사 중 발견하고 기획에 반영한 사항

### A01. 복구점 중첩 증가 위험

- 증상 가능성: 전체 상태 안에 복구점 배열을 넣고 그 상태를 다시 복구점으로 저장하면 크기가 반복적으로 증가할 수 있다.
- 반영: 복구점 상태 사본에서 다른 복구점과 임시 화면 상태를 제외하도록 명시했다.

### A02. 새 계수의 과거 차지 소급 적용 위험

- 증상 가능성: 새 보정계수 적용 뒤 완료 차지 예상이 다시 계산되면 당시 판단과 학습 원장이 달라진다.
- 반영: 승인 계수는 활성화 이후 시작하는 새 차지에만 사용하고 과거 스냅샷을 바꾸지 않도록 명시했다.

### A03. SHA-256 범위 부족

- 증상 가능성: payload만 해시하면 앱·스키마·요약 메타데이터 변경을 탐지하지 못한다.
- 반영: `integrity`를 제외한 전체 canonical JSON을 해시하도록 넓혔다. SHA-256이 작성자 인증은 아니라는 경계도 추가했다.

### A04. JSON 객체 병합 보안 위험

- 증상 가능성: 외부 JSON을 기존 객체에 무조건 병합하면 위험 키나 예상하지 않은 구조가 상태에 들어갈 수 있다.
- 반영: 허용 필드로 새 객체를 만들고 위험 키를 병합하지 않도록 명시했다.

### A05. 대형 파일로 인한 브라우저 정지 위험

- 증상 가능성: 단일 HTML에서 지나치게 큰 JSON을 한 번에 파싱하면 회사 PC 화면이 멈출 수 있다.
- 반영: v0.6 최초 한도를 50MiB로 정하고 성능시험 뒤 조정하도록 명시했다.

## 5. 감사 결론

- v0.6 기획은 자동저장, 수동 JSON 저장·불러오기, 복구점, 학습 재현성, 설명 개선이라는 사용자 목표를 충족한다.
- 구현 전에 추가로 반드시 결정해야 앱 구조가 바뀌는 P0 항목은 없다.
- 회사 메일 JSON 허용 여부, 승인 백업 폴더, 실제 회사 PC 저장 유지 여부는 구현을 막는 설계 미정이 아니라 현장 검증 항목이다.
- 기획 상태는 **PASS**, 구현·배포 상태는 **N/A**다.
