## 2. 요구사항 감사

### PASS

- 투입 코치는 사용·조회·채택 여부와 무관하게 G단계를 차단하지 않습니다.
- 권고 조회 추가 입력은 0개이며 작업자 계획은 예상량·시점의 선택 입력입니다.
- 화면에는 주안 1개와 대안 최대 1개만 표시합니다.
- 작업자 계획, 코치 제안, 실제 투입은 서로 다른 객체·상태·버전으로 저장됩니다.
- Flux·냉각재/광석·합금/가탄재·산소·시점과 조정기를 독립 모듈로 구현했습니다.
- 기존 종점계수와 새 투입계수의 오차·후보·버전·복구카드를 분리했습니다.
- 투입모델 자료는 IndexedDB·전체 JSON·CSV·Excel과 설정버전에 포함됩니다.
- 투입계수 핵심 6개는 BOFARC1 비상복구 카드로 검증 후 설정 초안에만 들어갑니다.

### N/A

- 실제 재료 로트별 정확도, 실제 산소 효과, 현장 작업속도와 경보 적합성은 실제 회사 데이터가 없어 N/A입니다.
- v0.8 다중 재료·산소 동시 최적화와 자동제어는 승인 범위 밖입니다.

## 3. 기능·계산 감사

### 확인한 정상 경로

- 문헌 기본 프로필이 없는 구형 상태도 마이그레이션 후 한 개 이상 유지합니다.
- DEMO G6에서 추가 산소 참고안, 범위·시점·근거·문헌 ID를 표시합니다.
- 작업자 계획을 두 번 저장하면 첫 계획은 `superseded`, 최신 계획은 `active`로 보존됩니다.
- 코치안을 계획으로 복사해도 실제 투입 이벤트를 만들지 않습니다.
- 실제 투입 전·후 분석 연결, 효과 오차, 자료 제외 사유와 추천 후보를 계산합니다.
- 10/30/50/70건과 최신 20건 분할, 기간·작업자·량·시점 분포, 검증 MAE 개선을 별도 확인합니다.
- Flux, 냉각재, 합금·가탄재, 산소 모델이 부족자료·허용단계·현장한도·목표충돌에서 숫자를 억지로 만들지 않습니다.
- 투입계수 복구문자열은 프로필·버전·계산식·기준지문·확인코드·수치범위를 검사합니다.
- 앱 오류 경계가 모델 오류를 빈 화면 전체 중단으로 확대하지 않습니다.

### 감사 중 발견·수정

1. 저·고값이 반올림으로 같을 때 `10–10 Nm³`, 시작·종료 분이 같을 때 `10:18–10:18`처럼 보여 가짜 범위로 오해할 수 있었습니다. 같은 값은 `10 Nm³`, `10:18 시점 추정`으로 표시하고 회귀시험을 추가했습니다.
2. 한국어 설정·복구카드의 보정 단위가 `multiplier`, `min`으로 남아 있었습니다. `배`, `분`으로 표시하고 `1.000 배=무보정`, `1.050 배=5% 증가` 설명을 추가했습니다.
3. 투입계수 카드의 PROFILE·VERSION·FORMULA 라벨과 값 사이 시각 간격이 없어 붙어 보였습니다. 라벨·값을 세로 계층으로 분리했습니다.
4. 기존 5173 Vite 서버가 구형 작업공간을 제공해 최신 시험 코드와 화면 소스가 달라졌습니다. 코드를 다시 고치는 대신 서버 재사용을 금지하고 작업공간·버전·필수 표식·포트 사전검사를 자동화했습니다. 상세 기록은 `../governance/디버그_재발방지_대장.md`의 `DBG-2026-08-24-001`입니다.
