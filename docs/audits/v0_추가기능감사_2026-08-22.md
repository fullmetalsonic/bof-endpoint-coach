# 취련 코치 v0 추가 기능 감사

감사일: 2026-08-22  
감사 목적: 현재 확정된 v0 범위에서, 현장 입력을 줄이고 데이터 누락·오판·복구 실패를 줄이는 추가 기능을 찾는다. HTML 구현은 하지 않는다.

## 결론

현재 설계의 핵심 흐름(기준값 승인, G0~G8, 이벤트 이력, 단위 환산, CSV/XLSX 분리)은 충분하다. 추가 기능은 계산 모델을 복잡하게 만들기보다 다음 세 가지를 강화하는 쪽이 효과적이다.

1. **입력 누락 방지**: 샘플과 분석 결과, 게이트별 필수 행동을 놓치지 않게 한다.
2. **판단 근거 보존**: 왜 계산값이 나왔고 무엇이 바뀌었는지 빠르게 확인한다.
3. **공용 PC 복구성**: 백업이 실제로 복원 가능한지 확인한다.

## P1 — 초기 구현에 넣으면 효과가 큰 기능

| ID | 기능 | 구체적 동작 | 기대 효과 |
| --- | --- | --- | --- |
| A1 | 미결 샘플 큐 | 샘플 채취 후 분석 결과가 아직 없는 샘플을 상단에 표시. 분석 입력은 그 샘플을 선택해 연결 | 샘플 ID 오연결·분석 입력 누락 방지 |
| A2 | 차지 시작 전 준비 확인 | 새 차지 시작 시 강종군·승인 버전·목표·단위·필수 기준값을 한 번에 검사 | 기준 미승인 상태에서 진행하는 실수 감소 |
| A3 | 출강 전 요약 카드 | 최신 분석의 채취/수신 시각, 목표 대비, 예상값 상태, 미해결 확인 항목을 한 화면에 요약 | 출강 직전 정보 탐색 시간 감소 |
| A4 | 설정 버전 차이 보기 | 새 강종/재료 기준 초안에서 이전 승인본과 달라진 항목만 보여 줌 | 잘못된 기준 변경 검토 지원 |
| A5 | 정정 이벤트 도우미 | 완료 차지의 잘못된 값은 삭제 대신 `정정 대상 → 정정값 → 사유` 순서로 추가 | 원본 보존과 재현성 강화 |
| A6 | 백업 상태·복원 점검 | 마지막 CSV 백업 시각, 데이터 건수, 최근 백업의 읽기 검사 결과를 표시 | 백업 파일은 있으나 복원 불가한 상황 감소 |
| A7 | 이유 선택 템플릿 | 재취련·재샘플·수동 수정·예외에 짧은 표준 사유 + 자유 메모 제공 | 나중에 원인 분류와 비교 가능 |

## P2 — 이력 데이터가 쌓인 뒤 넣을 기능

| ID | 기능 | 조건 | 주의 |
| --- | --- | --- | --- |
| B1 | 유사 과거 차지 찾기 | 강종군·재료·조건·결과 이력이 충분할 때 | 과거값을 자동 투입하지 않고 참고용으로만 표시 |
| B2 | 예외 원인 분석 | 재취련/재샘플/목표 이탈 사유가 일정 형식으로 쌓인 뒤 | 원인과 상관관계를 혼동하지 않음 |
| B3 | 데이터 품질 대시보드 | 차지 수가 누적된 뒤 | 입력 누락률·분석 지연·단위 오류를 품질 지표로 표시 |
| B4 | 후공정 피드백 연결 | 승인된 범위에서 LF/RH/연주 결과를 수동 입력 가능할 때 | 전로 원인으로 단정하지 않음 |
| B5 | 교육·연습 모드 | 현장 교육에 사용할 필요가 생길 때 | 실데이터와 완전히 분리된 가상 데이터만 사용 |

## P3 — 정식 도입/연동 이후 검토할 기능

- 사내 계정과 역할별 권한
- MES/LIMS/계량/PLC/HMI 데이터 연동
- 센서·배가스 기반 동적 예측
- 모델 성능 모니터링, 재학습 승인, 결과 검증
- 사내망 데이터베이스와 중앙 백업

## 제외 또는 보류 권고

| 기능 | 보류 이유 |
| --- | --- |
| 단일 `위험 점수` 또는 신호등 하나 | 성분 이탈, 데이터 누락, 분석 지연, 설비 안전을 같은 의미로 오해하게 함 |
| 근거 없는 AI 투입/출강 자동 추천 | 초기에는 학습 데이터·검증·책임 경계가 없음 |
| 사용자가 계산식을 자유롭게 직접 수정 | 단위·수율·공정 기준 오류가 누적될 수 있음 |
| XLSX를 복원 입력으로 사용 | 서식·수식·열 변경으로 데이터 정합성이 깨질 수 있음 |
| 외부 클라우드 자동 동기화 | 회사 보안 제약과 v0 로컬 원칙에 맞지 않음 |

## 우선순위 권고

초기 HTML을 만들기 전에, A1~A7 중 최소한 **A1, A2, A3, A4, A6**은 v0 범위에 넣는 것을 권고한다. A5·A7은 입력 화면의 복잡도와 현장 의견을 확인한 뒤 결정한다.

## 감사 한계

- 실제 취련사의 입력 동선·PC 위치·분석 결과 전달 방식은 확인하지 못했다.
- 따라서 버튼 수, 한 화면의 항목 수, 알림 빈도는 가상 데이터 화면을 만든 뒤 현장 검토가 필요하다.
- 이 감사는 기능 필요성을 평가한 것이며, 공정 임계값·계산식·안전 절차를 정한 것은 아니다.
