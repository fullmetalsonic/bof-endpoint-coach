# 초기 종점계수 문헌 근거 감사

감사일: 2026-08-22  
대상: `app/src/data/demoState.js`, `app/src/calculation/endpoint.js`와 공개자료 S01~S44

## 감사 결론

현재 구현은 UI·저장·계산 흐름을 시험하는 합성 DEMO로서는 동작하지만, **연구 기반 초기 계산기라고 부르기에는 계산항 분리가 부족하다.** 연구자료를 반영한 다음 버전은 현재 계수를 조금 조정하는 방식이 아니라 산소수지와 열수지의 항을 분리해야 한다.

| 판정 | 결과 |
| --- | --- |
| 연구자료가 계산 구조에 반영됐는가 | 부분 반영 — 정적/반동적 구조와 주요 입력 선정에는 반영 |
| 현재 숫자계수가 연구에서 직접 정해졌는가 | 대부분 아니오 |
| 그대로 현장 초기값으로 쓸 수 있는가 | 아니오 |
| 이력 전에도 개선 가능한가 | 예 — 화학량론·열역학·문헌 시나리오 기반 참고범위 가능 |

## P0 — 코드 변경 전 반드시 해결

### P0-01. 승인되지 않은 DEMO 계수가 수치 예상으로 실행됨

프로필은 `approved: false`, `demo: true`이지만 계산 함수는 승인 여부를 관문으로 사용하지 않는다. 공개 DEMO에는 허용할 수 있으나, 현장용 차지와 DEMO 계수의 연결을 구조적으로 차단해야 한다.

권고:

- 실행 모드를 `DEMO`, `LITERATURE_SCENARIO`, `SITE_APPROVED`로 분리한다.
- `SITE_APPROVED`에서는 승인되지 않은 계수를 만나면 수치 계산을 중단한다.
- DEMO 프로필을 복제해 승인 상태로 바꾸지 못하게 한다.

### P0-02. `otherOxygenKg`가 고정 절대질량임

`19,175 kg`은 차지량, 초기 Si/Mn/P, 슬래그 FeO, 광석 투입과 무관하게 동일하게 빠진다. 열 크기가 달라지면 물리적으로 일관된 스케일을 유지하지 못한다.

권고:

- 원소별 산화 산소량, 미사용 산소, 후연소, 산화물 공급 산소를 별도 항으로 계산한다.
- 값이 없는 항은 시나리오 입력 또는 `계산 불가`로 처리한다.

### P0-03. 열수지가 단일 등가계수에 과도하게 의존

`heatPerNm3OxygenKj`, `scrapHeatKjPerKg`, `fluxHeatKjPerKg`, `fixedHeatLossKj`, `equivalentHeatCapacity`가 반응·재료·온도·상변화를 한 값으로 합친다. 이는 공개 열수지 연구의 구성과 맞지 않는다.

권고:

- 원소별 산화반응열, 재료별 현열·잠열, 슬래그/배가스 열, 열손실을 분리한다.
- 열손실은 최소한 총 열입력 비율과 조건 프로필로 관리한다.

### P0-04. 불확실성 숫자에 검증 근거가 없음

`±0.006%p C`, `±10 °C`는 이력 잔차나 검증 표본으로 계산된 값이 아니다. 화면에서 예측 범위로 표시되면 사용자가 정확도 근거로 오해할 수 있다.

권고:

- DEMO에서는 `시각화용 가상 폭`이라고 명시한다.
- 문헌 시나리오에서는 입력 가정 변화로 생긴 범위와 통계적 신뢰구간을 구분한다.
- 통계적 불확실성은 독립 검증 이력 전에는 표시하지 않는다.

## P1 — 연구 기반 초기 계산에 필요

### P1-01. Nm³ 기준조건 미정

`1.429 kg/Nm³`는 0 °C, 101.325 kPa 가정과 일치하지만 현재 설정에 그 조건이 없다. 0 °C, 100 kPa를 쓰면 값이 약 1.409 kg/Nm³로 달라진다.

### P1-02. `0.75`의 이름과 의미가 잘못 연결됨

이 값은 CO 생성의 이론 화학량론에 가깝다. 산소효율과 섞인 경험 보정계수로 두지 말고 CO/CO₂ 분율에서 계산해야 한다.

### P1-03. 샘플 이후 선형 보정식의 근거 부족

최신 샘플 우선은 타당하지만, 잔여 O₂에 일정 `γC`를 곱하는 방식과 일정 °C/Nm³·°C/min 계수는 현장 회귀나 승인 계산표가 필요하다.

### P1-04. 용강수율 고정

용강량을 `(용선+스크랩)×0.96`으로 계산하면 철 산화·슬래그·비산·잔탕·광석 환원 등을 설명하지 못한다. 실제 출강량이 있으면 그것을 검증값으로 쓰고, 예상 수율은 조건 프로필로 분리해야 한다.

## 코드 영향 범위 예상

실제 변경 시 최소 다음 모듈이 영향을 받는다.

- `app/src/calculation/endpoint.js`: 산소수지·열수지 분리
- `app/src/data/demoState.js`: 계수 프로필과 DEMO 값 교체
- 설정 저장/검증 모듈: 출처·등급·기준조건 필드 추가
- 대시보드: DEMO/문헌 시나리오/현장 승인 상태와 범위 종류 표시
- 테스트: 화학량론 손계산, Nm³ 기준조건, 열수지 시나리오, 승인 관문
- README·릴리스: 계산 경계와 숫자 의미 수정

코드 수정은 여러 파일에 영향을 주므로 이 감사에서는 시행하지 않는다. 사용자 승인 후 별도 구현 계획과 회귀검증 범위를 확정한다.
