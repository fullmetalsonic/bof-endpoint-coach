# 취련 코치 v0 디자인 기획안

상태: 화면 구현 전 기준선. 현장 검토로 바뀌면 변경 사유와 함께 버전을 남긴다.

## 1. 제품 역할

취련 코치는 공용 PC에서 취련사가 차지별 수동 입력과 분석 결과를 누적하고, 목표 대비 상태와 다음 확인 항목을 빠르게 읽도록 돕는 보조 도구다.

이 도구는 제어 화면이 아니다. 자동 제어·설비 지시·실시간 데이터 수신·AI 판단을 암시하지 않는다.

## 2. 기준 사용자와 사용 순간

| 구분 | 기준 |
| --- | --- |
| 주 사용자 | 취련사 또는 현장 기록 담당자 |
| 기기 | 공용 PC의 브라우저 |
| 가장 중요한 순간 | 샘플 분석값 입력 직후, 출강 검토 전 |
| 화면의 우선 행동 | 현재 차지의 누락 입력 확인, 목표 대비 확인, 이벤트 기록 |
| 사용자가 빠르게 알아야 할 것 | 현재 게이트, 최신 분석값과 시점, 목표 대비, 다음 확인 항목, 적용 기준 버전 |

## 3. 디자인 원칙

1. **전문적인 정보 밀도**: 상단 요약, 단계 흐름, 품질 범위표, 최근 분석 표, 우측 근거 패널을 한 화면에 유지한다.
2. **판단 근거를 함께 표시**: 숫자만 보여 주지 않고 샘플/입력 시점, 기준 버전, 단위를 가까이 둔다.
3. **수동 입력의 정직성**: 모든 값의 출처를 수동 입력·분석 입력·승인 기준으로 구분한다.
4. **색상만으로 결론 내리지 않기**: 색과 함께 `범위 내`, `상한 접근`, `입력 확인` 같은 텍스트와 수치를 표시한다.
5. **꾸며진 관제화면 금지**: 의미 없는 KPI, 대형 게이지, 가짜 스트리밍 차트, 네온 효과를 쓰지 않는다.
6. **아이콘 절제**: 이모티콘·그림문자·아이콘 전용 버튼을 쓰지 않는다. 버튼은 텍스트로 의미를 완결한다.

## 4. 기준 화면 구조

```text
상단 공통 바: 제품명 | 현재 차지 | 차지 이력 | 기준값 설정 | 백업·보고서 | 도움말
상단 차지 요약: 차지 ID | 강종군 | 목표/현재 게이트 | 경과 시간 | 다음 확인 항목

좌측: G0~G8 단계 목록
중앙: 출강/현재 게이트 검토 요약 → 기본 품질 범위 막대(최대 6행) → 성분 상세 → 최근 샘플·분석 표
우측: 입력 시점 → 확인 필요 → 적용 기준
하단: 자재 투입 기록 | 샘플 채취 기록 | 분석 결과 입력 | 체크포인트 기록 | 재취련 기록 | 출강 기록
```

화면 폭이 부족할 경우 우측 패널을 중앙 표 아래로 이동한다. 핵심 품질 범위표와 최근 분석 표를 카드형 요약만 남기고 제거하지 않는다.

## 5. 각 영역의 고정 역할

| 영역 | 반드시 보이는 정보 | 표시하지 않을 것 |
| --- | --- | --- |
| 상단 차지 요약 | 차지 ID, 강종군, 현재 게이트, 경과 시간, 다음 확인 | 실시간 연동 상태 |
| 좌측 단계 | G0~G8, 현재 단계, 완료/확인 필요 상태 | 설비 제어 버튼 |
| 검토 요약 | 다음 기록/확인 행동, 필요한 이유 | 자동 작업 지시 |
| 품질 범위표 | 기본 품질 6개(C·온도·P·S·Mn·Si), 단위·실제값·참고 예상값·목표 범위·시점 | 서로 다른 단위의 합산 점수 |
| 성분 상세 | 강종 특화 합금·잔류·청정도 항목과 입력 상태 | 목표 없는 항목의 억지 범위 막대 |
| 최근 분석 표 | 샘플 ID, 채취 시각, 입력 시각, 분석값, 비고 | 근거 없는 추세 결론 |
| 우측 패널 | 입력 시점, 미결 확인, 적용 기준 버전 | AI/모델/설비 상태 |
| 하단 버튼 | 기록 행동을 뜻하는 텍스트 | 아이콘만 있는 행동 |

## 6. 목표 범위 막대

- 항목 하나당 막대 하나를 사용한다. C, 온도, P, Mn처럼 단위가 다른 항목을 한 축에 섞지 않는다.
- 실제 분석값은 채워진 원, `참고 예상(입력값 기준)`은 빈 원으로 표시한다.
- 최소/최대와 목표 범위를 수치와 기준선으로 함께 표시한다.
- 실제값이 범위를 벗어나면 막대에서 자르지 말고, 벗어난 방향과 수치를 보여 준다.
- 승인된 기준이 없거나 수동 입력이 부족하거나 데이터가 오래되면 예상값을 숨기고 사유를 표시한다.

## 8. 문구 규칙

| 상황 | 사용 문구 예 | 피할 문구 |
| --- | --- | --- |
| 데이터 시점 | 샘플 채취 10:18 / 분석 입력 10:24 / 마지막 저장 10:25 | 실시간 갱신 / 데이터 수신 |
| 예상 | 참고 예상(입력값 기준) | AI 예측 / 모델 권고 |
| 부족한 정보 | 분석 결과 입력 필요 / 적용 기준 미승인 | 오류 / 위험 점수 82 |
| 상태 | 목표 범위 내 / 상한 접근 / 하한 접근 / 범위 이탈 / 미확인 | 안정권 단독 표시 |
| 행동 | 출강 전 최종 샘플 채취 / 기준값 확인 | 즉시 출강 / 산소 투입 |

`출강 검토 가능`은 필수 목표, 데이터 시점, 게이트 확인 조건이 모두 충족될 때만 쓰며, 출강 지시를 뜻하지 않는다.

## 9. 구현 전 화면 수용 기준

| 확인 항목 | 통과 조건 |
| --- | --- |
| 정보 구조 | 상단 요약·단계·범위표·최근 분석·우측 패널·하단 행동이 모두 존재 |
| 수동 입력 경계 | 화면에 실시간/AI/PLC/HMI/자동 제어 표현이 없음 |
| 상태 전달 | 색상 이외에 텍스트·수치·단위·기준을 함께 표시 |
| 가독성 | 본문 15px 이상, 표 헤더 12px 이상, 과도한 카드/그림자 없음 |
| 예상값 정직성 | 계산 불가·미승인·오래된 데이터에서 예상값을 숨기고 사유 표시 |
| 확장성 | 기본 품질 6개와 강종군별 추가 관리 항목이 구분되며, 추가 항목은 성분 상세에서 확인 가능 |

## 10. 변경 관리

- 화면 구조를 단순화하거나 상태 의미를 바꾸는 변경은 현장 검토 전 확정하지 않는다.
- 색·문구·버튼 위치 변경도 이 문서와 상충하면 이유를 남긴다.
- 계산식·임계값·수율값은 디자인 문서에 임의 기본값으로 넣지 않는다.
- 검토 결과와 최종 결정은 `../governance/누적이력관리.md`에 추가한다.
