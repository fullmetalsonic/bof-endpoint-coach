# CSV 백업·복원·이력 계약 v0 초안

상태: 개발 기본안. 공용 PC의 수동 입력 데이터를 안전하게 보존·복원하기 위한 규칙이다. XLSX는 보고서용이며 이 계약의 복원 입력으로 쓰지 않는다.

## 1. 기본 원칙

- 복원 원본은 **CSV 백업 묶음**이다. 사용자가 파일 하나만 선택할 수 있도록, 여러 CSV와 `manifest.csv`를 하나의 ZIP 파일로 묶는다. ZIP은 전달용 포장이고 원본 데이터 형식은 CSV다.
- 복원 가능한 백업은 항상 전체 데이터 묶음이다. 여러 차지·샘플·기준 버전 사이의 관계를 잃지 않기 위해 선택 차지 1건만으로 복원하지 않는다.
- 선택 차지의 CSV/XLSX 내보내기는 열람·보고용이며 복원 입력으로 사용하지 않는다.
- 브라우저 저장소는 작업 편의용이고, 검증된 백업 묶음만 복구 수단으로 본다.
- 기존 이력을 덮어쓰거나 자동 병합하지 않는다.

## 2. 백업 묶음 구성

모든 CSV는 UTF-8, 쉼표 구분자, 첫 행 고정 열 이름, LF 줄바꿈을 사용한다.

| 파일 | 필수 열 또는 역할 |
| --- | --- |
| `manifest.csv` | 묶음 ID, 스키마 버전, 앱 버전, 생성 시각, 파일명, 행 수, SHA-256, 인코딩, 구분자 |
| `heats.csv` | 차지 ID, 상태, 강종군, 시작/완료/취소 시각, 적용 기준 묶음 ID |
| `events.csv` | 이벤트 ID, 차지 ID, 유형, 유효/정정/무효 상태, 발생/기록 시각, 시간대, 대상 이벤트, 사유, 메모, 단위·환산 규칙 참조 |
| `samples.csv` | 샘플 ID, 차지 ID, 채취 시각, 상태 |
| `analysis_results.csv` | 분석 ID, 샘플 ID, 결과 상태, 입력 시각, 채택 여부, 채택 사유, 분석 방법/출처(선택) |
| `analysis_values.csv` | 분석 ID, 항목 코드, 원본값/단위, 환산값/단위, 환산 규칙 ID |
| `reference_values.csv` | 강종군·재료·게이트·환산 규칙의 버전, 항목, 값, 단위, 상태, 적용 기간 |
| `operation_log.csv` | 백업·복원·정정·승인 관련 작업 이력 |

`manifest.csv`에 없는 파일, 해시가 다른 파일, 필수 열이 다른 파일, 참조 대상이 없는 행은 복원하지 않는다.

## 3. 백업 이벤트 이력

백업 행위와 파일 검증 결과를 `operation_log.csv`와 화면 이력에 남긴다.

| 이벤트 코드 | 의미 | 자동으로 알 수 있는 사실 |
| --- | --- | --- |
| `backup_requested` | 사용자가 전체 백업을 시작 | 시작 시각·대상 데이터 건수 |
| `backup_generated` | CSV 묶음 생성과 내부 해시 검사가 완료 | 생성된 묶음 ID·파일 수·행 수·해시 |
| `backup_downloaded` | 브라우저 다운로드 요청을 보냄 | 다운로드 요청 시각. 외부 폴더 저장 성공의 증거는 아님 |
| `backup_storage_confirmed` | 사용자가 승인 폴더 보관 완료를 확인 | 사용자 확인 기록. 파일 존재를 앱이 직접 증명하지는 못함 |
| `backup_verified` | 사용자가 백업 묶음을 다시 선택해 구조·해시 검사를 통과 | 실제 선택 파일의 검증 결과 |
| `backup_failed` | 생성·해시 검사·다운로드 요청 중 실패 | 실패 단계와 사유 |

화면에는 `마지막 저장`, `마지막 백업 생성`, `마지막 검증 백업`을 별도 표시한다. 셋을 같은 상태로 표시하지 않는다.

## 4. 백업 흐름

```text
전체 백업 만들기
→ 현재 데이터 건수·범위 표시
→ CSV 묶음 생성
→ manifest/행 수/SHA-256 내부 검사
→ 다운로드 요청
→ 사용자가 승인 폴더에 보관
→ 필요 시 같은 파일을 다시 선택해 백업 검증
```

- 차지 하나가 `출강 완료`가 되면 전체 백업 만들기를 안내한다.
- 진행 중 차지가 있더라도 전체 묶음으로 백업한다.
- 브라우저 종료 시 자동 파일 저장을 보장할 수 없으므로, 정기 백업은 사용자의 명시적 동작으로 한다.

## 5. 복원 흐름

v0의 복원은 **비어 있는 새 브라우저 저장소**에만 허용한다. 이미 로컬 데이터가 있으면 검증·미리보기만 하고 쓰기 복원을 하지 않는다. 이 제한은 덮어쓰기·자동 병합을 막기 위한 것이다.

```text
백업 묶음 선택
→ manifest/스키마/해시/행 수/참조 관계 검사
→ 차지·이벤트·샘플·분석·기준 버전 건수 미리보기
→ 오류 없음 확인
→ 전부 복원 또는 취소
→ 복원 후 저장소의 행 수·해시 재검사
→ restore_completed 또는 restore_failed 기록
```

- 오류·중복·스키마 불일치·참조 오류가 하나라도 있으면 쓰기 복원을 시작하지 않는다.
- 부분 복원, 기존 데이터 덮어쓰기, 자동 중복 해결, XLSX 복원은 v0 범위 밖이다.
- 복원 전 로컬 데이터가 비어 있지 않으면 `새 브라우저 프로필 또는 승인된 빈 환경에서 복원` 안내만 표시한다. 도구가 로컬 데이터를 삭제하지 않는다.

## 6. 복원 이벤트 이력

| 이벤트 코드 | 의미 |
| --- | --- |
| `restore_requested` | 사용자가 묶음을 선택 |
| `restore_precheck_failed` | 스키마·해시·행 수·참조 검사 실패 |
| `restore_cancelled` | 사용자가 미리보기 후 취소 |
| `restore_completed` | 전체 데이터 복원과 복원 후 검증 완료 |
| `restore_failed` | 복원 중 실패. 로컬 저장소는 변경 전 상태 유지 |

## 7. Excel 안전성·문자 처리

- 복원 파서는 CSV 값을 데이터 문자열로만 처리하고, 수식으로 실행하지 않는다.
- 보고용 CSV/XLSX에서 사용자 입력 텍스트가 `=`, `+`, `-`, `@`로 시작하면 Excel 텍스트 이스케이프 규칙을 적용한다.
- 백업 묶음의 이스케이프 방식은 `manifest.csv`에 버전으로 기록하고, 복원 시 같은 방식으로 원문을 재현한다.
- 쉼표·따옴표·줄바꿈이 있는 메모는 RFC 4180 방식으로 인용하며, 임의의 열 분할을 허용하지 않는다.

## 8. 구현 수용 기준

- [ ] 전체 데이터 백업 묶음에 모든 필수 CSV와 `manifest.csv`가 있다.
- [ ] 생성 직후 파일별 행 수·SHA-256을 검사한다.
- [ ] 다운로드 요청과 실제 선택 파일 검증 상태를 구분해 기록한다.
- [ ] 잘못된 해시·스키마·참조의 파일은 로컬 데이터 변경 없이 거부한다.
- [ ] 빈 저장소 복원 후 행 수·참조 관계·해시를 다시 검사한다.
- [ ] 기존 데이터가 있는 환경에서는 자동 병합·덮어쓰기·삭제를 하지 않는다.
