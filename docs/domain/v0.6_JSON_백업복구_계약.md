# v0.6 JSON 백업·복구 계약

상태: v0.6.0 구현 기준  
목적: 단일 HTML의 IndexedDB 작업공간을 파일 하나로 안전하게 이동·복원한다.

## 1. 기본 원칙

- 평상시 작업은 IndexedDB에 자동 저장한다.
- 외부 이동·장기 보존은 작업자가 버튼을 눌러 생성한 단일 JSON을 사용한다.
- JSON은 전체 작업공간 교체용이다. 일부 차지만 조용히 합치지 않는다.
- XLSX는 열람·보고용이며 복원 원본이 아니다.
- CSV ZIP은 v0.5 호환 보조 형식이다.

## 2. 봉투 구조

| 필드 | 의미 |
| --- | --- |
| `format` | `BOF_ENDPOINT_COACH_BACKUP` 고정 식별자 |
| `schemaVersion` | 백업 계약 버전 `0.6.0` |
| `createdAt` | ISO 8601 생성 시각 |
| `appVersion` | 생성한 앱 버전 |
| `payload` | 설정, 차지, 이벤트, 학습실행, 복구 메타데이터를 포함한 전체 작업공간 |
| `recoveryPoints` | 유효성 검사를 통과한 내부 복구점 |
| `integrity` | 정규화된 내용의 SHA-256과 건수 요약 |

키 순서를 정규화한 JSON으로 해시를 계산하므로 같은 내용은 같은 무결성 값을 만든다.

## 3. 저장 검증

1. 현재 상태와 복구점을 메모리에서 읽는다.
2. 스키마·필수 배열·식별자·시간·수치 범위를 검사한다.
3. 구형 정합성 오류가 있는 복구점은 운영 상태에서 삭제하지 않고 외부 백업 대상에서 격리한다.
4. SHA-256을 계산하여 봉투에 기록한다.
5. 생성한 파일을 앱이 다시 읽고 동일한 검사와 해시 검증을 수행한다.
6. 성공 시 파일명, 크기, 해시 앞부분, 검증 시각을 화면에 표시한다.

## 4. 불러오기 검증과 교체

- 최대 파일 크기는 50 MiB이다.
- 중첩 깊이, 위험한 객체 키, 필수 스키마, 중복 ID, 참조 관계, 시간과 수치 정합성을 검사한다.
- 가져온 데이터의 건수·버전·생성 시각·해시를 현재 상태와 비교하는 확인창을 먼저 표시한다.
- 작업자가 전체 교체를 승인하면 현재 상태를 보호 복구점으로 저장한 뒤 한 트랜잭션에서 상태와 복구점을 교체한다.
- 교체 직후 7일 유효의 `되돌리기` 동작을 표시한다.
- 복원 실패 시 기존 작업공간은 유지한다.

## 5. 내부 복구점

- 단계 전환, 전체 교체, 초기화처럼 영향이 큰 작업 전에 자동 생성한다.
- 일반 복구점은 최근 20개와 30일 보존을 기본으로 정리한다.
- 보호 복구점은 일반 자동 정리에서 제외한다.
- 각 복구점은 복원 직전에 다시 검증한다. 구형 정합성 오류가 있는 항목은 목록에 사유를 표시하고 복원 버튼을 비활성화한다.

## 6. 보안과 운영 경계

- JSON은 암호화 파일이 아니다. 실제 회사 데이터는 승인된 PC·폴더·메일 정책 안에서만 보관한다.
- 프로그램은 사용자의 동작 없이 임의의 폴더를 계속 덮어쓰거나 앱 종료 후 백업할 수 없다.
- 파일 확장자를 바꾸는 방식으로 보안 정책을 우회하지 않는다.
- 백업 무결성 검증은 파일 훼손 탐지이며, 실제 조업값의 공정 타당성이나 현장 승인을 보증하지 않는다.

## 7. 호환성

- v0.6 JSON은 v0.5 프로그램에서 읽을 수 없다.
- v0.6은 v0.5 CSV ZIP 불러오기를 호환 경로로 유지한다.
- 장기 호환 종료 시점은 회사 PC 시험과 운영 담당자 합의 후 별도 결정한다.
