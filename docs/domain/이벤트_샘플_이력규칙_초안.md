# 이벤트·샘플·분석 이력 규칙 초안

상태: v0.3.0 정정·이력 데이터 모델 기준. 실제 분석 방법·품질 승인 절차는 현장 확인이 필요하다.

## 1. 공통 이벤트 규칙

모든 기록은 삭제·덮어쓰기보다 추가 이력을 우선한다.

| 필드 | 규칙 |
| --- | --- |
| `event_id` | 로컬에서 고유한 값. CSV 복원 시 중복 판단 기준 |
| `heat_id` | 차지 식별자. 같은 PC에서는 진행 중 차지와 중복 금지 |
| `event_type` | 장입/투입, 샘플 채취, 분석 결과, 체크포인트, 재취련, 출강, 정정, 무효 처리 |
| `occurred_at` | 실제 발생 시각 |
| `recorded_at` | 화면에 기록한 시각 |
| `recorded_timezone` | 기록 시각의 시간대 정보 |
| `entry_role` | 입력한 역할명. 인증 정보가 아님 |
| `reason_code` / `memo` | 정정·취소·시간 순서 확인에 필요한 사유 |
| `status` | 유효 / 정정됨 / 무효. 원본 행을 물리 삭제하지 않음 |

## 2. 정정·무효 처리

- 오입력은 원본 이벤트를 물리 삭제하지 않고 원본을 `정정됨`으로 바꾼 뒤 대체 이벤트를 새로 추가한다.
- 정정 이벤트에는 `target_event_id`, 정정한 필드, 정정값, 사유를 필수로 둔다.
- 잘못 기록됐지만 남겨야 하는 행은 `무효`로 표시하고 사유를 남긴다.
- 현재 화면과 CSV 내보내기는 유효한 최신 정정 결과를 보여 주되, 원본과 정정 관계도 열람 가능해야 한다.

## 3. 샘플 규칙

| 항목 | 기준 |
| --- | --- |
| 샘플 ID | 같은 차지 안에서 중복 금지 |
| 샘플 채취 | 샘플 ID와 채취 시각을 먼저 기록 |
| 분석 연결 | 분석 결과는 반드시 기존 샘플 ID에 연결 |
| 미결 샘플 | 분석 결과가 없으면 `분석 결과 대기`로 표시 |
| 뒤늦은 입력 | 채취 시각보다 기록 시각이 늦어도 허용하되 시점을 모두 표시 |

## 4. 분석 결과 규칙

- 하나의 샘플에는 재분석·정정 등 여러 분석 결과가 연결될 수 있다.
- 분석 결과마다 `analysis_id`, 연결 `sample_id`, 결과 입력 시각, 분석 성분/온도, 단위, 결과 상태를 저장한다.
- 분석 방법·입력 출처는 현장에서 실제로 구분할 수 있을 때만 선택 입력으로 둔다.
- 새 분석 결과를 입력하면 그 결과를 현재 채택값으로 사용하되, 기존 분석 결과는 지우지 않는다.
- 같은 샘플의 다른 유효 분석을 사용하려면 사용자가 `채택`을 선택하고 사유를 남긴다.
- 정정된 분석 원본은 `정정됨`, 대체 분석은 `유효`로 연결한다. 채택 결과를 무효 처리하면 같은 샘플의 가장 최근 유효 분석으로만 대체하며, 유효 분석이 없으면 해당 샘플의 채택을 해제한다.

## 5. 현재 품질값 선택 규칙

1. 무효·정정 전 결과는 제외한다.
2. 명시적으로 채택된 분석 결과만 후보로 사용한다.
3. 후보 중 가장 최근 `샘플 채취 시각`의 결과를 현재 품질값으로 표시한다.
4. 더 최근 샘플이 분석 대기 중이면, 기존 분석값은 표시하되 `더 최근 샘플 분석 대기`를 함께 표시한다.
5. 채취 시각이 같으면 채택 시각이 더 최근인 결과를 우선하고, 동일하면 수치를 선택하지 않고 확인을 요구한다.

## 6. 게이트 상태 규칙

- G0~G8은 선형 순서이며 다음 게이트 건너뛰기는 허용하지 않는다.
- 작업자는 `마지막 단계 전환 취소`로 정확히 한 단계만 돌아갈 수 있고 사유를 반드시 남긴다. G0·G7·G8에서는 일반 단계 복귀를 허용하지 않는다.
- 몇 단계 전 입력이 틀렸다면 공정 단계를 되감지 않고 전체 타임라인에서 그 기록만 정정한다.
- 마지막 전환을 취소하면 해당 전환과 복귀 대상 단계에서 새로 만든 이벤트·샘플·분석을 무효 상태로 보존하고, 이전 단계의 유효 기록으로 현재 상태와 예상값을 다시 계산한다.
- 출강 후에는 일반 단계 복귀 대신 `출강 기록 정정`으로 G6→G7 전환 시각과 출강 이벤트를 함께 정정한다.
- 게이트 완료는 설비 제어 허가가 아니라, 해당 게이트의 필수 입력·확인 기록이 존재함을 뜻한다.
- 필수 값이 나중에 무효 처리되면 해당 게이트는 `확인 필요`로 되돌린다.

## 7. CSV 복원 기본 규칙

- `event_id`와 `analysis_id`는 복원 중 중복 식별에 사용한다.
- 참조 대상 샘플/이벤트가 없는 분석·정정 행은 오류로 보고 전체 복원을 중단한다.
- CSV는 정정·무효 관계와 채택 결과 정보를 함께 보존해야 한다.

## 8. 예상 스냅샷과 차지 기준 고정

- 차지 생성 시 강종·설비·계수 프로필을 `referenceSnapshot`으로 복사해 보존한다.
- 공용 설정을 나중에 바꿔도 이미 시작한 차지의 참고 계산 기준은 자동으로 바뀌지 않는다.
- 차지 생성, 입력, 단계 전환, 정정, 무효, 채택, 출강 정정 뒤의 C·온도 참고예상과 계산 근거·버전을 `predictionSnapshots`에 추가한다.
- 출강 후 확정 분석을 `actualEndpointAnalysisId`로 지정하면 출강 시점 예상 스냅샷과 C·온도 오차를 비교한다.
- 예상 스냅샷은 검증 자료이며 현장 정확도 승인이나 모델 자동 학습을 뜻하지 않는다.
