## 2026-08-22 — 프로젝트 시작

### 배경

- 제강 취련사가 중간중간의 수동 입력을 누적하고, 샘플링·추출 포인트 판단을 보조받는 도구를 구상한다.
- 회사 보안상 기초 데이터를 자동 수신하거나 설비·회사 시스템과 직접 연동하기 어렵다.
- 공용 PC에는 CSV/Excel 파일 저장이 가능하고 HTML 파일은 회사 메일로 받을 수 있다.

### 결정

- **v0은 로컬 HTML 기반의 수동 입력 보조도구**로 한다.
- 외부 서버·클라우드·자동 PLC/MES/LIMS 연동·자동 제어는 v0 범위에서 제외한다.
- 개인/팀의 누적 이력은 로컬 브라우저 저장소와 사용자가 수동으로 내보낸 CSV로 관리하는 방향을 검토한다.
- 초기 효과는 추출 타이밍 자체의 정답률만이 아니라, 기록 일관성·판단 근거·재샘플/재취련 발생 추이로 평가한다.

### 근거

- 사용자가 밝힌 보안 제약과 공용 PC 사용 조건.
- 공개 BOF 공정제어 자료는 정적 물질·열수지 모델과 중간 측정값을 반영하는 반동적 모델을 구분한다. v0은 수동으로 얻을 수 있는 정보만 활용하는 정적/반동적 보조 수준으로 한정하는 것이 타당하다. 자세한 근거는 `../research/취련_기술조사_2026-08-22.md`에 기록했다.

### 미확정 사항

- 현장의 실제 전로 형식(상취/복합취련), 강종군, 차지 식별 방식.
- 입력 가능한 항목과 입력 주체, 분석 결과를 받을 수 있는 시점.
- CSV를 공용 PC의 어느 승인 저장 위치에 보관할지와 보존 기간.
- 계산 결과를 kg 단위 참고값, 범위, 또는 체크리스트 중 어떤 형식으로 보여줄지.

## 2026-08-22 — 파일 교환 형식 검토

### 관찰 또는 요청

- 향후 회사 PLC, HMI, SCC 등 제어·운영 시스템과의 데이터 교환 가능성을 고려해 CSV와 Excel(XLSX) 중 어떤 파일 형식을 우선할지 검토 요청이 있었다.

### 잠정 판단 (미확정)

- **초기 HTML 도구의 기계 교환용 표준 후보는 UTF-8 CSV**로 둔다.
- **Excel(XLSX)은 사람이 검토·보고·수정하는 보조 산출물**로만 고려한다.
- PLC/HMI/상위 시스템과의 정식 실시간 연동은 파일 교환을 기본 가정으로 하지 않는다. 시스템이 지원할 경우 OPC UA, 사내 DB, 제조 실행 시스템(MES) 인터페이스 등 해당 회사의 승인된 방식이 대상이다.

### 근거와 가정

- CSV는 표 구조가 단순하고 브라우저, Excel, 데이터베이스, 다수의 HMI/SCADA 내보내기 기능과 호환하기 쉽다.
- XLSX는 셀 서식, 여러 시트, 수식, 병합 셀 등 사람이 보기 좋은 요소를 담지만 자동 처리는 구조가 흔들리기 쉽고 PLC의 직접 입출력 형식으로는 일반적이지 않다.
- `SCC`의 정확한 제품/약어는 아직 확인되지 않았다. 지원 인터페이스와 파일 인코딩·구분자는 해당 시스템의 매뉴얼 또는 사내 자동화 담당자 확인이 필요하다.

### 후속 확인 항목

- 대상 HMI/SCC의 제품명·버전과 허용 인터페이스(파일, DB, OPC UA 등)
- 사내 CSV 정책: UTF-8 허용 여부, 구분자(쉼표/탭), 줄바꿈, 공유 폴더 위치
- 파일을 사람이 수동 교환하는지, 승인된 배치 프로그램이 교환하는지
- 회사 데이터에 적용할 차지 ID·시간·단위·권한 규칙

## 2026-08-22 — CSV/XLSX 역할 및 연구자료 수집 결정

### 관찰 또는 요청

- 초기 단계에서는 회사 시스템과 연동하지 않으므로 CSV를 사용하고, 작업자가 결과를 확인할 때는 Excel 형식으로 내보내며 백업 데이터는 가져오기로 복원하는 방향이 제안되었다.
- 전로 취련 관련 연구자료를 폭넓게 수집·보관해 향후 도구 설계에 활용하도록 요청받았다.

### 결정 또는 변경

- **v0의 데이터 교환 기준은 CSV**로 한다. HTML은 CSV 가져오기와 내보내기를 제공하는 방향으로 설계한다.
- **XLSX는 사람용 출력물**이다. 누적 이력의 원본 교환·복원 기준으로 사용하지 않는다.
- 공개 자료 30건을 원출처 링크, 접근 상태, 적용도를 포함한 카탈로그로 저장했다.
- 저작권·재배포 조건이 분명하지 않은 외부 자료 원문은 프로젝트에 내려받지 않고 서지·링크만 저장한다.

### 근거와 가정

- CSV는 구조가 단순해 초기 HTML의 백업·복원·추후 분석에 적합하다. XLSX는 보고/검토 시 사람이 읽기 쉽다.
- BOF 연구는 센서·배가스·대량 실적을 전제로 하는 경우가 많다. 초기 수동 입력 도구의 검증되지 않은 권고값에 논문의 조건별 수치를 직접 이식하지 않는다.

## 2026-08-22 — 원료·부원료 기준값 관리 필요성 확인

### 관찰 또는 요청

### 결정 또는 변경

- v0 설계에 **원료·부원료·스크랩 기준값 관리 화면**을 포함한다.
- 차지 화면은 재료 선택, 실제 투입 중량, 시각, 선택 로트 등 현장 이벤트 입력에 집중한다.
- 기준값 화면은 재료 코드·분류·단위·성분 기준·대표 조성 범위·수율·출처·적용일·버전을 관리한다.
- 기준값 수정 권한과 차지 기록 권한을 분리하는 방향으로 설계한다.

### 근거와 가정

- 조성·수분·분석 기준·단위·회수율은 같은 투입 중량이라도 계산 결과를 바꾼다.
- 대표 조성과 로트 실측값, 원소 함량과 공정 수율은 같은 값이 아니므로 별도 필드가 필요하다.
- 실제 활성 성분과 수율은 회사 승인값을 사용하며, 공개 자료의 수치를 기본값으로 쓰지 않는다.

## 2026-08-22 — 단위 선택 및 안전한 환산 원칙

### 관찰 또는 요청

### 결정 또는 변경

- 각 수치 입력에 원본 단위 선택을 제공하고, 계산에는 항목별 표준 단위로 환산한 값을 사용한다.
- 원본값·원본단위·환산값·표준단위·환산 규칙 버전·상태를 함께 저장한다.
- 단순 차원 변환(kg↔t, wt%↔ppm, °C↔K, 초↔분)만 자동 처리한다.
- 습식/건식, 원소/산화물, m³/Nm³, 질량분율/부피분율, 원소 함량/회수율은 추가 조건 또는 승인식 없이는 변환하지 않는다.

### 근거와 가정

- 단위 라벨만 바꾸면 분석 기준이 달라지는 항목이 있어 조용한 자동 변환은 오판 위험이 있다.
- 원본과 환산 결과를 함께 남겨야 과거 계산을 검토·재현할 수 있다.

- 현장에서 실제 입력 가능한 항목인지 확인한 뒤에만 `필수`를 확정한다.

## 2026-08-22 — 격외 방지 취련 관리 게이트 초안

### 관찰 또는 요청

- 취련사가 격외를 피하도록 차지 시작부터 출강까지 관리해야 할 포인트를 정하고, 그 포인트를 도구 계산의 입력·판단 기준으로 삼아야 한다는 요구가 있었다.

### 결정 또는 변경

- G0 데이터/설비 준비부터 G8 결과 확정·보정 학습까지 9개 관리 게이트를 정의했다.
- 각 게이트에 확인값, 계산/비교, 상태/경고, 기록 결과, 격외 예방 의미를 분리했다.
- v0은 `추출 검토/재샘플 검토/재취련 검토` 상태만 표시하고, 실제 산소·랜스·투입 설비 제어 또는 강제 출강 지시는 하지 않는다.

## 2026-08-22 — 강종군별 관리 항목 동적 표시 기준

## 2026-08-22 — 문헌 기본 시나리오와 현장 수정·승인 우선순위 구현

### 관찰 또는 요청

- 기존에 모은 공개 문헌을 계산 기본선으로 사용하고, 사용자가 현장 수정값이나 승인값을 입력하면 해당 값을 우선 사용하기로 결정했다.
- 승인 전 수정값도 계산에는 반영하되 현장 승인값과 혼동되지 않도록 상태를 구분해야 했다.

### 결정 또는 변경

- 계산 우선순위를 `현장 승인 수정값 → 사용자 수정값(미승인) → 문헌 원본값`으로 고정했다.
- 문헌 원본은 읽기 전용 `literatureValues`, 수정값은 별도 `overrideValues`로 저장해 원본을 보존한다.
- PCR, 열손실률, 종점 슬래그 FeO를 저·기준·고 문헌 시나리오로 계산하고, 출력 범위를 통계적 정확도가 아닌 문헌 민감도 범위로 표시한다.
- 기존 합성 상수식 대신 C·Si·Mn·P·Fe 산소수지와 용선·용강·슬래그·배가스의 축약 열수지를 모듈로 분리했다.
- 분석 입력 때 누적 산소 스냅샷을 저장하고, 실제 샘플에 문헌 모델의 샘플 시점→계획 종점 변화량을 더하도록 했다.
- 계수 설정에 문헌 원본·현장 수정값·실제 적용값·근거 ID와 승인자·승인 근거를 추가했다. 승인된 값을 다시 수정하면 승인을 자동 해제한다.
- 대시보드와 Data Ledger, XLSX에 계산 근거·문헌 ID·저/고 범위·수정 필드를 표시하고, CSV 백업에 샘플 공정 스냅샷을 추가했다.
- 설정 저장 작업 이력에는 당시 계수 프로필 전체 스냅샷을 남긴다.
- 오래된 로컬 상태나 변조된 백업이 화면 저장 검사를 우회하지 못하도록, 계산 직전 계수 검증과 백업 복원 설정 검증을 추가했다.
- 같은 프로필 변경 시 과거 차지 계산이 새 값으로 재계산되는 현재 한계를 공식 적용 전 보완 항목으로 기록했다.

## 2026-08-22 — v0.2.0 운영 흐름·삭제·고정값 재감사

### 관찰 또는 요청

- 진행 중 DEMO 차지를 개별 삭제할 수 없고, 우측 상단에 실제 사용자와 무관한 `설비기술팀`이 고정 표시된다는 사용자의 지적이 있었다.
- 신규 차지를 G0 장입부터 진행하려 해도 단계가 바뀌지 않고, Data Ledger의 회전 화살표가 실제 새로고침 기능이 아니라는 추가 지적이 있었다.
- 삭제 불가, 임의 기본값, 실제와 연결되지 않은 표시가 더 있는지 전체 확인을 요청받았다.

### 재현 결과와 정정

- 새 브라우저 저장소에서 DEMO 차지 2개 강제 생성과 `설비기술팀` 고정 표시를 재현했다.
- 신규 차지는 G0로 생성되지만 G1~G6으로 전환하는 상태기계가 없고 G8 후처리 완료 경로도 없다.
- 체크포인트 저장을 실제 시도했으나 모달이 닫히지 않았다. 자재 투입 외 5개 이벤트가 공통으로 `null.toLocaleString()` 오류 경로를 타는 코드를 확인했다.
- 좌측 완료 게이트 시각은 실제 이벤트가 아니라 산술식으로 만든 문자열이었다.
- 차지에는 삭제·취소·무효·보관이 없고, 강종·재료는 추가만 가능했다. 전체 초기화는 확인 없이 사용자 데이터를 지운 뒤 DEMO를 재생성했다.
- 알림·금일 현황에는 실제 상태와 무관한 고정 확인 문구가 있었다.
- 따라서 이전 기록의 `브라우저 주요 흐름 PASS`, `CRITICAL/HIGH 결함 0건` 평가는 이번 재현 결과로 정정한다. v0.2.0은 수정 전 현장 사용 금지 상태다.

### 확정 기준

- 오프라인 v0은 로그인 대신 사용자가 작업자 표시명을 입력·수정하고, 이벤트마다 입력 당시 이름을 보존한다.
- DEMO 체험과 빈 작업 시작을 분리하며 DEMO는 개별 삭제 가능하게 한다.
- DEMO·초안의 완전 삭제와 실제 진행/완료 차지의 취소·무효·보관을 구분한다.

- G0~G8 실제 전환과 여섯 이벤트 저장을 브라우저 회귀테스트로 통과하기 전에는 릴리스 완료로 판단하지 않는다.

## 2026-08-23 — v0.3.0 정정·이력 관리 P0 묶음

### 사용자 결정

- 최근 입력 수정·무효, 마지막 단계 전환 취소, 차지 취소, 출강 후 정정을 하나의 관리 묶음으로 적용한다.
- P0는 현재 버전에 구현하고, 나머지는 P1·P2 후속 목록에 남긴다.
- 권장 버튼 배치뿐 아니라 화면 흐름 감사 문서도 현재 구현에 맞춰 개정한다.

### 구현 기준

- 원본을 삭제하지 않고 `유효/정정됨/무효` 상태와 대체 관계·사유·작업자·시각을 보존한다.
- 공정 단계는 G1~G6에서 마지막 전환 한 번만 취소할 수 있다. 몇 단계 전 오입력은 단계 복귀 없이 해당 기록만 정정한다.
- 출강 이후에는 일반 복귀 대신 출강 이벤트와 G7 전환을 함께 정정한다.
- 한 샘플에 여러 분석 결과를 보존하고 사용자가 채택 결과를 정한다. 출강 후에는 종점 실제값을 별도로 지정해 예상 스냅샷과 비교한다.
- 차지 생성 당시 강종·설비·계수 설정을 차지별 스냅샷으로 고정한다.
- 정정·무효·단계 복귀·채택 뒤 C·온도 예상과 계산 근거를 새 스냅샷으로 누적한다.

### 검증 중 발견과 정정

- 분석값만 고쳐도 `datetime-local` 정밀도 손실로 분석 시각이 샘플보다 수백 ms 빨라지는 문제를 재현했다. 표시 시각을 바꾸지 않으면 원본 ISO 시각을 보존하고 실제 시각 입력을 초 단위로 통일했다.
- 비채택 과거 분석이 최근 표에서 Pending으로 보이는 회귀를 찾아, 이력 표시와 계산 채택 투영을 분리했다.
- 샘플 무효 시 연결 분석 이벤트가 남지 않도록 상태 전파와 참조 무결성 검사를 추가했다.

## 2026-08-23 — v0.4.0 운영 저장·사용성 통합 보강

### 사용자 결정

- 이전 감사의 대기 항목과 확장 사용성·복구 감사의 P0·P1을 따로 고치지 않고 하나의 수정 묶음으로 합쳐 진행하도록 승인했다.
- 실제 완료 차지가 필요한 유사 차지 통계·정확도 대시보드는 P2에 유지하고, 현재 코드와 합성 DEMO로 검증 가능한 저장·복구·사용성·신뢰 경계를 먼저 보강했다.
- GitHub 게시와 이메일 발송은 별도 지시 전까지 수행하지 않는다.

### 저장·복구 구현

- IndexedDB 상태에 `storageRevision`을 추가하고 읽기-쓰기 트랜잭션 안에서 기대 revision과 실제 revision을 비교한다. 오래된 창은 `storage_revision_conflict`로 중지해 최신 작업공간을 덮어쓰지 못한다.
- BroadcastChannel로 같은 작업공간의 새 저장 revision을 알리고, 이를 받은 창은 읽기 전용으로 전환한다. 비상 ZIP 백업 후 최신 저장소를 다시 읽는 두 단계 확인을 제공한다.
- 초기 IndexedDB 읽기 실패 시 빈 작업공간을 만들거나 저장하지 않고 오류 화면과 재시도를 표시한다. 쓰기 실패·충돌 중에는 새 조업 입력을 잠그고 저장 재시도·비상 백업·이탈 경고를 제공한다.
- 작업공간 초기화도 저장소 삭제 후 재생성이 아니라 현재 revision과 비교한 원자적 새 상태 저장으로 바꿨다.
- 신규 차지·이벤트·단계 전환·정정·설정 입력을 폼·차지·기준 버전별 localStorage 초안으로 보존하고, 복구 상태와 `초안 버리기`를 제공한다.

### 기준·근거·백업 구현

- 설정 저장은 실제 변경과 변경 사유가 있을 때만 가능하다. 저장할 때 `LOCAL-REF-*` 새 버전, 이전 버전, 작업자, 시각, 사유와 필드별 차이를 기록한다.
- 사용자 차지가 합성 강종·설비 기준을 쓰면 `DEMO 기준`, 합성 차지는 `DEMO 데이터`로 표시한다. 계획 산소가 없어 계산이 불가능해도 계수 근거·문헌 ID를 유지한다.
- CSV ZIP 백업을 다운로드하기 전에 같은 Blob을 복원 경로로 다시 읽어 SHA-256·행 수·참조·공정 정합성을 확인한다. 마지막 검증 시각·차지 수·해시를 operation log와 보고서 화면에 남긴다.
- 정정 사유에 기본 표준 목록과 자유 입력을 함께 제공한다.

### 화면·사용성 구현

- 진행 차지 탭에 최근 입력 시각, 확인 필요 수, 위험 수를 표시한다.

### ZIP 백업 관련 확인과 검토사항

- 현재 v0.5.0은 IndexedDB에 작업 상태를 자동 저장하고, 사용자가 버튼을 누르면 여러 CSV와 manifest를 ZIP으로 다운로드한다.
- 브라우저 보안상 단일 HTML이 사용자 동작이나 별도 폴더 권한 없이 임의의 PC 폴더에 ZIP을 지속적으로 자동 생성·갱신할 수는 없다.
- 회사 메일에서 ZIP이 차단될 가능성이 제기되어, ZIP을 유일한 이동·복원 형식으로 고정하지 않기로 검토한다.
- 다음 버전의 기본 후보는 스키마·데이터·계수·학습이력·무결성 정보를 담은 단일 JSON 백업이며, ZIP은 허용 환경용 선택 형식으로 유지하는 안이다.
- 단일 JSON 채택, 회사 PC 허용 확장자, 승인 저장경로와 백업 주기는 아직 운영 확인이 필요하며 구현 완료로 표시하지 않는다.

### HTML 자동저장 의미 확인

- 사용자가 묻는 자동관리는 ZIP 생성 여부보다, HTML을 사용하는 동안 데이터가 자동 저장되고 다음 실행에서 이어지는 프로그램형 동작을 의미한다고 확인했다.
- 현재 v0.5.0은 상태 변경 후 약 250ms 뒤 IndexedDB에 자동 저장하고 시작 시 마지막 상태를 읽는다.
- 이는 같은 브라우저 저장영역 안의 자동저장이며, 외부 JSON·ZIP 파일 자동갱신이나 앱 종료 후 예약 작업을 의미하지 않는다.
- JSON은 회사 메일에서 허용될 가능성이 높고 ZIP은 외부 클라우드 보관이 가능하다는 사용자 판단을 기록했다. 실제 회사 정책 확인 전에는 확정 PASS로 표시하지 않는다.
- 초기 권장 자동관리 수준은 IndexedDB 실시간 저장, 내부 세대별 복구점, 백업 필요 알림, 원클릭 JSON이다. 지정 폴더 자동갱신은 사용자 권한과 브라우저·회사 정책을 전제로 한 선택 기능으로 둔다.

### 구현 결과
