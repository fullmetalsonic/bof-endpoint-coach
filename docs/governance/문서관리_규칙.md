# 문서·자료·파일 관리 규칙

상태: v0 운영 규칙 초안. 프로젝트 규모가 커져도 찾기 쉽고, 과거 근거를 잃지 않게 하는 기준이다.

## 1. 분리 원칙

1. 누적 원장에는 **결정, 변경 이유, 검증 결과, 남은 위험**만 짧게 추가한다.
2. 상세 요구사항·화면 규칙·데이터 정의·연구 요약은 각각 책임 폴더의 독립 문서에 둔다.
3. 한 문서가 서로 다른 책임을 두 개 이상 가지면 분리한다. 단, 짧은 문서를 무의미하게 쪼개지는 않는다.
4. 중복 내용은 복사하지 않고 기준 문서로 링크한다.
5. 실제 회사 조업 수치, 차지 이력, 개인 정보, 기밀 기준은 프로젝트 문서와 예시에 넣지 않는다.

## 2. 파일 위치 규칙

| 대상 | 위치 | 규칙 |
| --- | --- | --- |
| 변경 이력·문서 운영 | `docs/governance/` | 날짜별 원장과 관리 규칙 |
| 제품 범위·승인 기준 | `docs/product/` | 기능과 비기능 요구사항을 분리 |
| 데이터·공정 도메인 | `docs/domain/` | 단위·기준값·게이트·입력 항목 |
| 화면 정의 | `docs/ui/` | 기능 구조와 시각 규칙을 분리 |
| 디자인 산출물 | `docs/design/` | 기획안과 재사용 템플릿 |
| 조사 자료 | `docs/research/` | 조사 요약과 카탈로그를 분리 |
| 감사 결과 | `docs/audits/` | 감사 일자와 범위를 파일명에 포함 |
| 가상 입력 예시 | `docs/templates/` | 실제 데이터 금지 |
| 실제/가상 데이터 파일 | `data/local/`, `data/exports/` | 승인된 위치·보존 규칙을 우선 |
| 외부 공개 원문 | `references/open-downloads/` | 재배포·보관이 허용된 자료만 |

## 3. 이름·버전 규칙

- 지속 기준 문서: `주제_초안.md`, `주제_v0.md`처럼 역할이 드러나는 이름을 쓴다.
- 날짜가 중요한 조사·감사·기록: `주제_YYYY-MM-DD.md` 또는 `.csv`를 쓴다.
- 같은 기준을 수정할 때는 문서를 덮어쓰지 않고, 필요하면 `v0.1`, `v0.2` 또는 새 날짜 파일을 만든다.
- 기준 문서에는 맨 위에 `상태: 초안 / 검토 중 / 승인 / 중지`를 표시한다.
- 파일명에는 개인명, 실제 차지 번호, 회사 기밀 강종명·수치를 넣지 않는다.

## 4. 변경 절차

1. 변경 대상의 기준 문서와 연결 문서를 먼저 확인한다.
2. 영향이 한 영역이면 해당 문서만 수정한다. 여러 영역이면 각 문서를 나누어 수정한다.
3. 새 문서·폴더·파일 이동·승인 상태 변경은 누적 원장에 기록한다.
4. 링크, 표, CSV 열 구조, 파일 존재 여부를 확인한다.
5. 실제 조업 적용 전에는 현장 담당자의 기준 검토를 별도로 받는다.

## 5. 데이터·자료 파일 규칙

- `data/local/`: 개발·검토용 비기밀 가상 데이터만 둔다.
- `data/exports/`: 실제 CSV가 저장될 수 있으므로 Git·개인 저장소·개인 메일에 올리지 않는다.
- CSV 예시는 `docs/templates/`에 두고, 열 정의의 기준은 `docs/domain/데이터정의_v0.md`로 연결한다.
- 외부 원문은 무단 복제하지 않는다. 원문 보관 가능 여부와 출처는 `references/README.md` 및 연구 카탈로그로 관리한다.

## 6. 완료 판단

문서·파일 구조 변경은 아래가 모두 충족돼야 완료다.

- [ ] 대상 파일이 새 위치에 존재한다.
- [ ] 이전 위치에 중복본이나 끊긴 링크가 없다.
- [ ] 루트 README와 `docs/README.md`에서 새 위치를 찾을 수 있다.
- [ ] 상대 경로 링크와 CSV 참조가 확인됐다.
- [ ] 누적 원장에 이동 이유와 검증 결과가 기록됐다.
