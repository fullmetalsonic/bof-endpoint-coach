# 취련 코치 v0.7.3 구두 기능 소개서

대상: 취련사, 교대자, 현장 관리자, 공정·품질·설비 담당자, 처음 보는 사용자  
권장 설명시간: 표준 7~10분, 짧은 소개 90초  
사용 방법: 아래의 **말할 내용**을 자연스럽게 읽고, 사진 아래의 **화면에서 짚을 곳**만 마우스로 가리킨다.

> **처음에 반드시 말할 경계:** 취련 코치는 전로를 자동으로 제어하는 시스템이 아닙니다. 작업자가 직접 입력한 값으로 종점과 투입량·시점을 참고 계산하고, 실제 결과가 쌓이면 보정계수 후보를 제안하는 오프라인 보조도구입니다. 실제 분석, 현장 기준, 안전 인터록과 취련사의 판단이 항상 우선합니다.

## 90초로 먼저 소개하기

### 화면에 띄울 문장

> 작업자의 기록을 한 차지의 흐름으로 연결하고, 종점과 선택형 투입 참고안을 계산하며, 실제 오차를 다음 차지의 보정자료로 되돌려 주는 오프라인 학습형 취련 보조도구

### 말할 내용

“이 프로그램의 이름은 **취련 코치**입니다.

취련사가 장입부터 출강까지 조업값, 샘플, 분석 결과와 실제 투입을 직접 기록하면, 현재 정보로 C·온도·P·Mn·Si·S의 종점 참고값을 계속 다시 계산합니다. 필요할 때는 부원료, 냉각재, 합금, 가탄재와 추가 산소의 참고량과 시점도 자신의 수기 계획과 비교할 수 있습니다.

차지가 끝나면 예상과 실제의 차이를 그냥 버리지 않고 강종·설비·계수버전별 오차로 남깁니다. 데이터가 충분히 쌓이면 반복되는 편향을 분석해 사람이 검토할 보정계수 후보를 제안합니다. 추천값은 자동 적용되지 않습니다.

현재 버전은 인터넷이나 제어시스템에 연결하지 않는 단일 HTML입니다. 자동저장은 PC 브라우저 안에서 하고, 전체 자료는 JSON으로 백업할 수 있습니다. 즉, 취련사의 판단을 대신하는 도구가 아니라 판단 근거와 오차를 체계적으로 남기는 **스마트 계산기이자 학습형 조업 보조도구**입니다.”

### 꼭 짚을 한 문장

> 처음에는 공개 문헌으로 계산하고, 사용할수록 현장 실제 오차를 근거로 사람이 승인할 보정값을 제안합니다.

## 표준 구두 소개 시작

## 1. 왜 이 도구를 만들었는가

### 화면에 보여줄 것

- 한 차지 안에서도 장입, 산소, 랜스, 자재, 샘플과 분석값이 계속 바뀝니다.
- 여러 차지를 동시에 진행하면 서로 다른 차지의 값이 섞일 위험이 있습니다.
- 예상이 빗나간 이유를 남기지 않으면 다음 차지에서 같은 편향을 반복할 수 있습니다.

### 말할 내용

“취련 작업에서는 처음 입력한 장입값만 보고 끝까지 갈 수 없습니다. 산소가 얼마나 들어갔는지, 랜스를 어떻게 운전했는지, 어떤 자재를 언제 넣었는지, 중간 샘플이 어떻게 나왔는지를 계속 함께 봐야 합니다.

또 여러 차지가 동시에 진행되면 메모나 기억만으로는 값이 섞이기 쉽습니다. 한 차지에서 예상과 실제가 달랐더라도 그 이유가 체계적으로 남지 않으면 다음 작업에서 활용하기 어렵습니다.

취련 코치는 이 문제를 해결하기 위해 각 차지의 입력을 시간순으로 묶고, 현재 예상과 실제 오차를 다음 보정 검토자료까지 연결합니다.”

### 꼭 짚을 한 문장

> 단순히 기록만 하는 프로그램이 아니라, 입력이 들어올 때마다 계산하고 오차를 다음 계산 개선자료로 남깁니다.

위쪽 차지 탭을 누르면 여러 진행 차지를 바꿔 볼 수 있고, 각 차지의 데이터는 따로 저장됩니다. 왼쪽 G0부터 G8까지는 현재 공정 단계입니다.

가운데에는 지금 무엇을 해야 하는지 큰 행동 버튼으로 안내합니다. 품질 막대는 현재 실측값과 종점 참고예상, 강종 목표 범위를 한 축에서 비교합니다. 오른쪽 원장은 마지막 입력·계산·자동저장 시각을 보여줍니다.

아래쪽 버튼은 실제로 발생한 자재 투입, 샘플 채취, 분석 결과, 체크포인트, 재취련과 출강을 기록하는 곳입니다.”

> 사용자는 중앙의 다음 행동을 따라가되, 실제로 일어난 값과 시각은 하단 입력창에 기록합니다.

## 3. 장입부터 출강까지 어떻게 사용하는가

### 화면에 띄울 흐름

```text
기준 정보 확인
      ↓
신규 차지 G0 입력
      ↓
실제 조업·자재·샘플·분석 기록
      ↓
입력할 때마다 종점 참고예상 갱신
      ↓
출강 전 예상 스냅샷 저장
      ↓
출강 후 확정 실제값 지정
      ↓
예상과 실제 오차 누적
```

### 말할 내용

“처음에는 기준 정보에서 강종 목표, 재료 조성, 설비 조건과 계산계수를 확인합니다. 신규 차지를 만들 때 용선·스크랩 질량과 성분, 초기 온도, 계획 산소 같은 G0 값을 입력합니다.

조업 중에는 실제로 발생한 시각과 값을 계속 기록합니다. 입력창은 현재 PC 시각을 기본으로 넣지만, 실제 발생시각이 다르면 바꿔 입력할 수 있습니다.

유효한 정보가 추가되면 화면의 종점 참고예상이 다시 계산됩니다. 출강 전에는 당시 예상값을 스냅샷으로 남기고, 출강 후 확정 분석을 실제 종점으로 지정합니다. 이 두 값을 비교한 오차가 다음 학습자료가 됩니다.”

### 꼭 짚을 한 문장

> 계획, 코치 참고안과 실제 기록은 서로 덮어쓰지 않고 별도 이력으로 남습니다.

## 3-1. 용존산소 값이 있으면 어떻게 기록하는가

![선택형 용존산소 입력](screenshots/v0.7.3/03-analysis-optional-filled.png)

### 말할 내용

“용존산소 값이 있는 경우에만 분석 결과의 추가 측정값을 펼쳐 `[O]`를 ppm으로 입력합니다. 값이 없으면 그냥 넘어가도 되고 미측정으로 저장됩니다.

이 값은 취련 중 공급한 누적 산소 Nm³와 다른 값입니다. 지금 버전에서는 계산에 넣지 않고 이력·정정·백업용으로만 쌓습니다. 처음부터 억지로 입력을 요구하지 않으면서 나중에 현장 특성을 검토할 자료는 잃지 않기 위한 기능입니다.”

### 꼭 짚을 한 문장

> 용존산소는 선택 기록이며, 공란이어도 기존 조업 흐름과 계산은 그대로 진행됩니다.

## 4. 종점 참고예상은 어떻게 바뀌는가

![종점 참고예상 근거](screenshots/v0.6.0/04-prediction-explanation.png)

### 화면에 띄울 식

> 표시 종점 참고예상 = 문헌 기본예상 + 최신 채택 샘플 보정 + 승인된 현장 보정값

### 말할 내용

“종점 예상은 한 번 계산하고 고정되는 값이 아닙니다.

처음에는 공개 문헌의 물질수지·열수지와 진행 시나리오를 기준으로 계산합니다. C와 온도는 장입 질량·성분, 산소와 시간의 영향을 참고하고, P·Mn·Si·S는 공개 문헌의 조업 진행 시나리오에서 시작합니다.

중간 샘플이 들어오면 같은 시점의 문헌 기대값과 실제 샘플의 차이를 계산합니다. 예를 들어 문헌 진행값보다 실제 C가 높으면 현재 차지가 문헌 궤적보다 높은 쪽으로 진행된 것으로 보고 종점 참고값을 다시 조정합니다.

두 번째 샘플이 들어오면 다시 비교합니다. 최신 채택 샘플은 현재 계산의 기준점이 되고, 이전 샘플은 삭제하지 않고 오차 흐름으로 남습니다.”

### 꼭 짚을 한 문장

> 화면의 저·고 범위는 통계적 신뢰구간이 아니라 입력과 문헌계수 변화에 따른 참고 시나리오입니다.

## 5. 투입 코치는 무엇을 도와주는가

### 화면에 띄울 흐름

```text
현재 차지 상태
      ↓
부원료·냉각재·합금·가탄재·추가 산소 참고안
      ↓
작업자의 수기 계획과 나란히 비교
      ↓
실제 투입은 별도 기록
      ↓
실제 효과와 모델 예상 효과의 오차 누적
```

### 말할 내용

“투입 코치는 작업자가 필요할 때만 여는 선택 기능입니다. 사용하지 않아도 G단계 진행은 막히지 않습니다.

현재 차지의 강종, 설비, 샘플, 산소와 조업상태를 이용해 부원료, 냉각재, 합금·가탄재와 추가 산소의 참고량과 시점을 계산합니다. 작업자는 자신이 수기로 예상한 양과 예정시각을 먼저 저장하고 코치안과 나란히 비교할 수 있습니다.

여기서 중요한 점은 코치안을 보는 것과 실제로 투입한 것이 다르다는 것입니다. 실제 투입은 자재 투입 또는 재송풍 기록으로 별도 저장해야 합니다. 그래야 나중에 작업자 계획, 코치 참고안, 실제 투입과 실제 효과를 정확하게 비교할 수 있습니다.”

### 꼭 짚을 한 문장

> 투입 코치의 값은 조업 지시가 아니라 작업자의 계산과 비교하는 참고안입니다.

## 6. 사용할수록 어떻게 현장에 맞아지는가

![종점·투입 오차학습 화면](screenshots/v0.7.2/03-addition-learning.png)

### 화면에 띄울 흐름

```text
문헌모델 예상
      ↓
완료 차지 실제 결과
      ↓
실제값 − 예상값 오차
      ↓
같은 강종·설비·계수버전끼리 분석
      ↓
보정계수 후보 제안
      ↓
사람 검토·승인·새 버전 저장
```

### 말할 내용

“취련 코치의 학습은 프로그램이 마음대로 기준을 바꾸는 방식이 아닙니다.

완료 차지의 확정 실제값에서 출강 전 예상값을 빼 종점 오차를 만듭니다. 실제 투입 전후의 유효한 분석이 있으면 실제 성분·온도 변화에서 모델이 예상한 변화를 빼 투입효과 오차도 별도로 만듭니다.

오차는 강종, 설비, 계산식과 계수버전이 같은 자료끼리 분석합니다. 데이터 수뿐 아니라 최근 검증자료, 기간, 작업자, 투입량과 시점 분포가 충분한지 확인한 뒤 보정계수 후보를 보여줍니다.

추천은 설정 초안으로만 전달됩니다. 작업자나 승인자가 단위 오류, 분석 이상, 설비변경과 성능을 확인하고 변경 사유와 함께 새 버전으로 저장해야 이후 신규 차지에 적용됩니다.”

### 꼭 짚을 한 문장

> 문헌 모델 → 실제 오차 축적 → 보정값 추천 → 사람 승인이라는 선순환이며 자동 적용은 하지 않습니다.

## 7. 잘못 입력했을 때 어떻게 바로잡는가

### 화면에 보여줄 표

| 작업자의 상황 | 처리 방법 |
| --- | --- |
| 방금 입력한 값이 틀림 | 해당 기록 수정 또는 무효 처리 |
| 마지막 단계 전환을 잘못 누름 | 마지막 단계 전환 취소로 한 단계 복귀 |
| 몇 단계 전 값이 틀림 | 단계는 유지하고 과거 기록 정정 후 계산 재검증 |
| 실제 조업을 중단함 | 차지 조업 취소 |
| 출강 뒤 오류를 발견함 | 별도 출강 기록 정정과 종점 실제값 재지정 |

### 말할 내용

“잘못 입력한 값을 조용히 덮어쓰거나 삭제하면 나중에 왜 계산이 달라졌는지 알 수 없습니다.

취련 코치는 원본과 정정값, 관계, 작업자, 사유, 실제 발생시각과 기록시각을 남깁니다. 방금 입력한 값은 수정하거나 무효 처리할 수 있습니다. 마지막 단계 전환을 잘못 누른 경우에만 한 단계 취소합니다.

몇 단계 전 값이 틀렸다면 공정을 억지로 되돌리지 않고 과거 기록만 정정한 뒤 이후 계산을 다시 확인합니다. 출강 이후 오류는 일반 되돌리기와 분리된 출강 정정 기능을 사용합니다.”

### 꼭 짚을 한 문장

> 데이터를 지우는 것보다 무엇을 왜 고쳤는지 남기는 것을 우선합니다.

## 8. 저장과 복구는 어떻게 하는가

![자동저장·JSON 복구 화면](screenshots/v0.6.0/01-storage-recovery.png)

### 화면에서 짚을 곳

| 방식 | 역할 |
| --- | --- |
| IndexedDB 자동저장 | 같은 PC·같은 브라우저에서 계속 작업 |
| 단일 JSON | 전체 차지·설정·오차·학습·복구점 백업과 복원 |
| 내부 복구점 | 단계 전환·출강·설정 변경 전 빠른 되돌리기 |
| CSV·Excel | 원시행 확인과 열람·보고, 전체 복원 기준은 JSON |
| 비상복구 카드 | JSON까지 잃었을 때 핵심 보정값만 수기 복원 |

### 말할 내용

“작업 중 자료는 같은 PC와 브라우저의 IndexedDB에 자동저장됩니다. 여러 창에서 같은 자료를 열었을 때 오래된 창이 최신 자료를 덮어쓰지 못하도록 revision 충돌도 확인합니다.

PC 이동이나 브라우저 초기화에 대비한 정상 백업은 단일 JSON입니다. JSON에는 차지, 이벤트, 설정, 오차, 학습실행과 복구점이 함께 들어갑니다. 불러오기 전에는 파일 크기, SHA-256, 스키마, ID 관계, 시각과 값의 정합성을 검사합니다.

CSV와 Excel은 사람이 내용을 확인하거나 보고할 때 사용합니다. 전체 복원 기준은 JSON입니다.”

### 꼭 짚을 한 문장

> 자동저장은 편의 기능이고, 교대·브라우저 정리·PC 이동 전에는 반드시 JSON을 따로 저장해야 합니다.

## 9. 보정값을 최후에 수기로 복구할 수 있는가

![종점 보정계수 비상복구 카드](screenshots/v0.6.1/02-recovery-card-core.png)

### 말할 내용

“IndexedDB와 JSON을 모두 잃는 최악의 상황을 대비해 비상복구 카드가 있습니다.

종점 C·온도·P·Mn·Si·S의 핵심 보정값 6개와 투입 코치의 핵심 보정값 6개를 각각 화면, 스크린샷, 인쇄물, 수기 메모와 복구문자열로 보관할 수 있습니다.

투입 코치의 6개는 Flux 양, 냉각재 양, 합금·가탄재 양, 산소량, 권장 시점 이동과 예상 효과 보정입니다. 양·효과의 `1.0000배`는 무보정이고 시점의 `0분`은 이동 없음입니다.

복구할 때는 프로필, 계수버전, 계산식, 기준지문, 확인코드와 값 범위를 검사합니다. 검사를 통과해도 바로 적용하지 않고 현재값과 비교하는 설정 초안으로 보냅니다.

다만 비상카드는 핵심 계수만 살리는 마지막 수단입니다. 사라진 차지, 샘플, 오차와 학습 근거까지 복구하지는 못합니다.”

### 꼭 짚을 한 문장

> 정상 복구는 JSON이고, 비상복구 카드는 핵심 보정계수만 되살리는 최후 수단입니다.

## 10. 이 도구가 하지 않는 일

### 화면에 띄울 문장

- PLC·HMI·SCC·MES와 실시간 통신하지 않습니다.
- 산소·랜스·부원료를 자동 제어하지 않습니다.
- 출강 가능 여부를 자동 승인하지 않습니다.
- 작업자 승인 없이 계수나 강종 목표를 바꾸지 않습니다.
- 실험실 분석, 표준작업, 안전 인터록과 취련사의 판단을 대신하지 않습니다.

### 말할 내용

“현재 취련 코치는 자동제어 시스템이 아닙니다. PLC나 HMI에서 값을 받지 않고, 산소·랜스·부원료를 직접 조작하지도 않습니다.

또한 화면의 참고값만으로 출강을 승인하거나 작업자 몰래 강종 기준과 계수를 바꾸지 않습니다. 실제 분석, 현장 기준, 인터록, 출강 승인과 취련사의 판단이 항상 우선입니다.

공개 문헌과 합성 DEMO로 프로그램 기능은 검증했지만 실제 사업소 정확도는 아직 주장하지 않습니다. 회사 PC 적합성, 모의조업과 완료 실제차지 그림자 운전으로 별도 검증해야 합니다.”

### 꼭 짚을 한 문장

> 현재 목표는 제어 자동화가 아니라, 작업자가 수동 입력으로 안전하게 비교·기록·학습하는 AI 취련 코치입니다.

## 11. 마지막으로 이렇게 설명하면 됩니다

### 30초 마무리 대본

“취련 코치는 취련사의 경험을 대신하지 않습니다. 장입부터 출강까지 흩어진 값을 차지별로 연결하고, 새 정보가 들어올 때마다 종점 참고예상을 갱신합니다. 필요하면 자신의 투입계획과 코치안을 비교하고, 실제 투입과 결과는 별도로 기록합니다. 차지가 끝난 뒤에는 종점오차와 투입효과 오차를 다음 차지의 보정자료로 남깁니다. 처음에는 공개 문헌으로 시작하지만 사용할수록 사업소·설비·강종별 반복오차를 찾아 사람이 검토할 보정값으로 돌려주는 오프라인 학습형 취련 보조도구입니다.”

### 소개 뒤 바로 보여줄 순서

1. 대시보드에서 차지 탭, G단계와 다음 행동을 보여줍니다.
2. 품질 막대에서 실측·종점 참고예상·목표 범위를 짚습니다.
3. 투입 코치 한 줄을 열어 선택 기능임을 설명합니다.
4. 학습·계수 화면에서 추천이 자동 적용되지 않는다고 설명합니다.
5. 분석·리포트에서 JSON 백업 위치를 보여줍니다.

## 사용자가 자주 묻는 질문에 구두로 답하기

### “이 값만 보고 출강하면 됩니까?”

“아닙니다. 모두 참고예상입니다. 실제 분석, 현장 기준, 안전 인터록, 출강 승인과 취련사의 판단이 우선입니다.”

### “실제 데이터가 없어도 숫자가 나옵니까?”

“공개 문헌 기본모델로 참고수치는 계산됩니다. 다만 사업소별 정확도는 실제 완료 차지의 예상과 실제 오차가 쌓이고 그림자 검증을 하기 전에는 주장할 수 없습니다.”

### “AI가 알아서 계속 계수를 바꿉니까?”

“아닙니다. 오차가 충분히 쌓이면 후보를 보여주지만, 사람이 검토하고 사유를 남겨 새 버전으로 저장해야 적용됩니다.”

### “투입 코치 값을 그대로 따르면 됩니까?”

“아닙니다. 공개 문헌 또는 승인된 보정값으로 계산한 비교용 참고안입니다. 현장 재료와 조업상태, 회사 기준과 작업자의 판단이 우선입니다.”

### “인터넷으로 회사 데이터가 전송됩니까?”

“현재 단일 HTML은 네트워크 통신이나 텔레메트리가 없습니다. 자료는 브라우저 IndexedDB와 사용자가 저장한 파일에 남습니다. 다만 JSON·Excel·복구카드에는 실제 현장자료가 들어갈 수 있으므로 회사 보안정책에 따라 보관해야 합니다.”

### “데이터가 사라지면 어떻게 합니까?”

“전체 복원은 JSON 백업으로 합니다. JSON도 없다면 비상복구 카드로 핵심 계수만 수동 복원할 수 있지만 차지와 학습 근거 전체를 되살리지는 못합니다.”

## 영어 60초 소개가 필요할 때

BOF Endpoint Coach is an offline, single-file operator-assistance tool. Operators manually record heat, oxygen, lance, addition, sample, analysis, reblow, and tapping data. The tool updates reference endpoint estimates for carbon, temperature, phosphorus, manganese, silicon, and sulfur. Its optional addition coach compares an operator's own plan with reference amount and timing suggestions for fluxes, coolants, alloys, carburizers, and additional oxygen. Confirmed endpoint and actual pre/post-addition results create separate residual evidence. When evidence is sufficient, the tool proposes explainable correction candidates, but nothing is applied without human review and a new approved version. It does not control the BOF or replace plant standards, laboratory results, safety interlocks, tap authorization, or operator judgment.
