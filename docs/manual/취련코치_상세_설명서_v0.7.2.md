# 취련 코치 v0.7.2 상세 설명서

이 문서는 취련 코치를 처음 보는 작업자가 **파일 실행, 기준 확인, 차지 입력, 종점 참고예상 해석, 투입 계획 비교, 잘못 입력한 기록의 정정, 두 종류의 오차학습, 보정계수 비상복구 카드, JSON 백업과 복구**까지 혼자 따라 할 수 있도록 만든 화면별 상세 설명서입니다.

제품을 사람에게 10~15분 동안 소개할 때는 [발표용 설명서](취련코치_발표용_설명서_v0.7.2.md)를 사용하십시오.

> **안전·품질 경계:** 이 도구의 C·온도·P·Mn·Si·S 값은 공개 문헌 시나리오와 사용자가 입력한 값으로 계산한 참고예상입니다. 실제 BOF 차지 정확도와 사업소 적합성은 아직 검증되지 않았습니다. PLC·HMI·SCC·MES·LIMS와 연결되지 않으며, 설비 제어·인터록·표준작업·실험실 분석·출강 승인·취련사의 판단을 대체하지 않습니다.

## 1. 3분 안에 전체 구조 이해하기

취련 코치는 아래 순환을 관리하는 오프라인 보조도구입니다.

1. 작업자가 강종·설비·계수 기준을 확인합니다.
2. G0 장입값과 조업 중 자재·산소·랜스·샘플·분석·재취련·출강을 수동 기록합니다.
3. 문헌 기본모델이 C·온도·P·Mn·Si·S 종점 참고예상을 계산합니다.
4. 채택한 중간 샘플이 들어오면 `실측 − 문헌 궤적값` 오차로 현재 차지의 종점값을 다시 보정합니다.
5. 출강 후 확정 분석을 종점 실제값으로 지정하면 `실제 − 종점예상` 오차를 누적합니다.
6. 같은 강종·설비·모델·계수버전의 실제 완료차지가 충분하면 검토용 보정계수 후보와 재현 가능한 학습 실행이 생깁니다.
7. 작업자가 검토·승인하여 새 계수버전으로 저장하기 전에는 어떤 추천도 자동 적용되지 않습니다.
8. 현재 적용 중인 보정계수 핵심 6개를 비상복구 카드로 남기고, 필요하면 선택한 학습 실행의 18개 상세값도 함께 기록합니다.
9. 평상시 데이터는 IndexedDB에 자동저장하고, 외부 보관은 단일 JSON으로 수동 저장합니다.
10. v0.7.2의 투입 코치는 문헌 시험 시나리오에서 자재·냉각재·합금·추가 산소의 양과 시점을 참고 계산하고, 작업자의 계획·실제 투입·결과 오차를 서로 덮어쓰지 않고 별도 원장으로 축적합니다.

## 2. 실행과 첫 화면

### 2.1 권장 환경

- 파일: `BOF_Endpoint_Coach_v0.7.2.html`
- 브라우저: Microsoft Edge 또는 Google Chrome
- 회사 PC 권장 화면: 1920×1080, 배율 100%
- 서버·설치·인터넷: 필요 없음
- 데이터 위치: 해당 브라우저 프로필의 로컬 IndexedDB

같은 HTML을 다른 폴더로 복사하거나 다른 브라우저 프로필에서 열면 저장소가 다르게 보일 수 있습니다. 실제 사용 전에는 사용할 브라우저와 파일 위치를 고정하십시오.

![첫 실행 작업자 설정](screenshots/v0.6.0/28-first-run.png)

### 2.2 처음 사용할 작업자 설정

`작업자 이름`은 로그인 계정이나 부서명이 아닙니다. 새 입력·단계 전환·정정·계수 승인 이력에 표시되는 로컬 이름입니다.

- `DEMO로 체험`: 공개 문헌 기반 합성 차지로 버튼과 단계 흐름을 연습합니다.
- `빈 작업으로 시작`: 실제 수동 기록을 위한 빈 작업공간을 만듭니다.
- 이름이 비어 있으면 두 시작 버튼을 사용할 수 없습니다.
- 우측 상단 `작업자 설정`에서 언제든 표시 이름을 바꿀 수 있습니다.

### 3.2 입력 중요도

| 표지 | 뜻 |
| --- | --- |
| 필수 | 식별 또는 저장에 반드시 필요 |
| 계산 핵심 | 비면 C·온도 또는 다성분 종점예상이 불가능하거나 크게 제한됨 |
| 정확도 권장 | 비어도 저장되지만 문헌 대체값이 늘어남 |
| 선택 | 알고 있을 때 입력하면 이력과 해석이 좋아짐 |

### 3.3 단위 사전

| 명칭 | 선택 단위 | 내부 저장 | 설명 |
| --- | --- | --- | --- |
| 질량 | kg, t, g | kg | `1 t = 1,000 kg`, `1 kg = 1,000 g` |
| 성분 농도 | %, wt%, ppm | % | `%`와 `wt%`는 질량비로 동일, `1% = 10,000 ppm` |
| 누적·계획 산소 | Nm³ | Nm³ | 표준상태 기체 체적; 실제 배관 체적 m³와 구분 |
| 산소 유량 | Nm³/min | Nm³/min | 1분당 표준상태 산소 체적 |
| 온도 | °C | °C | 섭씨 |
| 시간 | min | min | 분 단위 지속시간 |
| 랜스 높이 | m | m | 현장 기준점이 무엇인지는 사업소 표준을 따름 |
| 성분 보정 오프셋 | %p | %p | 상대 %가 아니라 percentage point |
| 온도 보정 오프셋 | °C | °C | 종점예상에 더하는 절대 온도차 |

단위 선택을 바꾸면 입력값은 내부 기준단위로 환산됩니다. 원래 값과 선택 단위도 입력 메타데이터에 남습니다.

### 4.1 여러 차지를 동시에 볼 때

- 각 차지의 공정값·샘플·예상·단계는 별도로 저장됩니다.

- 차지 삭제는 초안 또는 허용 상태만 가능하며, 중요한 변경 전에는 복구점이 생성됩니다.

## 5. 종점 참고예상과 근거 읽기

![예상 근거 펼침](screenshots/v0.6.0/04-prediction-explanation.png)

각 성분의 최종 표시값은 다음 세 층으로 설명됩니다.

`문헌 기본값 + 최신 채택 샘플 보정 + 승인된 현장 오프셋 = 표시 종점 참고예상`

근거 펼침에서 확인하는 항목은 다음과 같습니다.

| 항목 | 뜻 |
| --- | --- |
| 문헌 기본 | 공개 문헌 시나리오와 현재 장입·산소·시간으로 만든 기본값 |
| 샘플 보정 | 최신 채택 샘플의 `실측 − 궤적 기대값`을 현재 차지 종점에 반영한 값 |
| 현장 오프셋 | 현재 계수버전에 작업자가 승인해 저장한 성분별 편향 보정 |
| 최종 예상 | 위 세 값을 합친 화면 표시값 |
| 적용 그룹 | 강종·설비·계산식·계수버전·실제/DEMO 구분 |
| 학습 실행 | 같은 데이터셋으로 다시 만들 수 있는 SHA-256 식별 학습 결과 |
| 경고 | 문헌 대체값, 데이터 부족, 과거버전, DEMO, 승인 전 후보 등 |

P·Mn·Si·S도 숫자를 표시하지만 현장별 반응속도·슬래그·교반·원료 조성·회수율 의존성이 큽니다. 특히 S는 현재 문헌모델 신뢰도가 매우 낮으므로 실제 분석을 우선하십시오.

## 6. 중간 샘플 오차 읽기

표의 오차는 `실측 − 문헌 궤적 기대값`입니다.

- 양수: 실제값이 모델 궤적보다 높음
- 음수: 실제값이 모델 궤적보다 낮음
- `반영`: 최신 채택 분석이라 현재 종점예상 재고정에 사용
- `비교만`: 유효 이력에는 남지만 현재 종점 재고정에는 미사용
- 샘플 시점 누적 산소가 없으면 산소 진행률 기반 궤적 비교가 제한됩니다.
- 이전 샘플을 삭제해 오차를 숨기지 않고 수정·무효 관계를 남깁니다.

| 필드 | 단위 | 계산상 역할 |

## 8. 실제 입력창 6종

### 8.1 자재 투입

자재는 등록한 재료와 이번 투입량을 기록합니다. Alloy·Scrap은 등록 조성과 질량을 명목 원소수지에 반영하지만 별도 현장 수율계수가 없으므로 100% 회수를 가정한 참고값입니다.

### 8.2 샘플 채취

![샘플 채취](screenshots/v0.6.0/17-sample-entry.png)

- 샘플 ID: 차지 안에서 식별할 이름
- 채취 시각: 실제 채취 시각
- 단계: 채취 당시 G 단계
- 메모: 채취 위치·상태 등 현장 해석 보조

샘플을 만든 뒤 분석 결과를 별도로 입력합니다. 채취 자체에는 성분값을 넣지 않습니다.

### 8.3 분석 결과

![분석 결과 입력](screenshots/v0.6.0/18-analysis-entry.png)

| 필드 | 단위 | 뜻 |
| --- | --- | --- |
| 샘플 | – | 어느 채취 기록의 결과인지 선택 |
| 분석 시각 | 로컬 날짜·시각 | 결과가 확인된 실제 시각 |
| 분석 방법 | 예: OES | 사용한 분석법 기록 |
| 샘플 시점 누적 산소 | Nm³ | 궤적 기대값 계산 기준 |
| C·P·Mn·Si·S | %/wt%/ppm | 입력 단위를 확인해 내부 %로 환산 |
| T | °C | 샘플 온도 |
| 채택 | – | 현재 종점예상 재고정에 사용할 결과 |

같은 샘플에 재분석 결과를 추가할 수 있습니다. 채택 결과 하나만 샘플 대표값으로 사용하며 원본과 과거 결과는 남습니다.

### 8.4 체크포인트

![체크포인트 입력](screenshots/v0.6.0/19-checkpoint-entry.png)

- 누적 산소는 이전 유효 기록보다 작을 수 없습니다.
- 랜스 높이와 산소 유량은 그 시점의 실제값을 기록합니다.
- 기본 시각은 현재 PC 시각이고 실제 발생시각으로 수정할 수 있습니다.
- 미래시각과 단계 이력보다 앞선 역행시각은 저장이 막힙니다.

### 8.5 재취련

![재취련 입력](screenshots/v0.6.0/20-reblow-entry.png)

`추가 산소`는 누적값이 아니라 이번 재취련에서 더 공급한 양입니다. 지속시간을 입력하면 온도·시간 보정과 예상 이력에 사용됩니다. 재취련 입력 뒤 종점예상을 다시 확인하십시오.

### 8.6 출강

![출강 입력](screenshots/v0.6.0/21-tap-entry.png)

출강 버튼은 지시나 승인 버튼이 아닙니다. 실제 출강한 뒤 사실과 실제 시각을 기록하는 버튼입니다. 저장하면 G7로 이동하고 중요한 변경 직전 복구점이 자동 생성됩니다.

| 출강 시각 오류 | `출강 기록 정정` |
| 출강 후 확정 분석 변경 | 다른 분석을 `종점 실제값`으로 지정 |

## 13. 학습 · 계수 추천

![학습·계수 실행 화면](screenshots/v0.6.0/05-learning-coefficient-runs.png)

### 13.1 학습에 들어가는 차지

다음 조건을 모두 만족해야 합니다.

- 합성 DEMO가 아닌 실제 수동 차지
- 취소되지 않고 출강·완료된 차지
- 출강 전 종점예상 스냅샷 존재
- 출강 후 확정 종점 분석을 명시적으로 지정
- 해당 성분에 예상값과 실제값이 모두 존재
- 강종·설비·계산식·계수버전이 같은 그룹

제외된 차지와 이유도 숨기지 않고 표시합니다.

### 13.2 데이터 충분성 관문

| 같은 그룹 실제 오차 수 | 상태 |
| ---: | --- |
| 1~9 | 원장 축적 |
| 10~29 | 편향 방향 참고 |
| 30~49 | 임시 후보, 작업자 검토 필요 |
| 50~69 | 독립 검증표본 대기 |
| 70 이상 | 앞쪽 n−20 학습 + 최신 20 검증 가능 |

후보는 최신 20개 검증표본에서 MAE·편향·목표 적중률이 기존보다 좋아져야 승인 가능으로 표시됩니다. 70건은 충분한 정확도를 보장하는 숫자가 아니라 자동 추천을 시작하기 위한 최소 운영 관문입니다.

### 13.3 재현 가능한 학습 실행

학습 실행은 다음을 고정합니다.

- 데이터 행 ID와 차지 ID
- 제외 차지와 이유
- 데이터 기간
- 학습/검증 분할 수
- 현재·후보 MAE, 편향, 중앙절대오차, 목표 적중률
- 현재 오프셋, 추천 변화량, 후보 오프셋
- 계산식·계수버전·그룹키
- 데이터셋 SHA-256과 실행 SHA-256

같은 데이터로 다시 계산하면 같은 식별값을 얻습니다. 새 실제 차지, 실제값 정정, 강종·설비·계수 변경으로 데이터셋이 달라지면 이전 실행은 삭제하지 않고 `오래됨`으로 표시합니다.

### 13.4 승인 순서

1. 완료 실제차지와 확정 종점 분석을 점검합니다.
2. 후보가 현재 계수버전·같은 그룹인지 확인합니다.
3. 학습과 최신 20개 검증 성능을 비교합니다.
4. 이상치·정정·단위오류·설비변경 여부를 검토합니다.
5. 후보를 설정 초안으로 보냅니다.
6. 현장 승인자·사유와 함께 새 계수버전으로 저장합니다.
7. 다음 차지부터 새 버전을 명시적으로 선택합니다.

## 14. 보정계수 비상복구 카드

비상복구 카드는 전체 JSON을 대신하는 백업이 아니라, **현재 종점예상에 실제로 더해지는 보정계수 6개를 종이·사진·스크린샷으로 남기는 최후 수단**입니다. 브라우저 데이터와 JSON을 모두 잃어도 이 6개를 다시 넣으면 종점예상의 핵심 보정 상태를 어느 정도 복원할 수 있습니다.

> **복구 한계:** 카드로는 차지, 단계, 샘플, 분석, 오차대장, 학습실행 원본, 계수 버전이력, 설정 전체를 복원할 수 없습니다. 따라서 평상시에는 단일 JSON 백업을 사용하고, 카드는 JSON까지 쓸 수 없는 비상상황에만 사용합니다.

### 14.1 어디에서 여는가

![학습 화면의 비상복구 카드 진입점](screenshots/v0.6.1/01-learning-recovery-entry.png)

- `학습 · 계수` 화면 우측 상단의 `보정계수 비상복구 카드`를 누릅니다.
- 또는 `기준 정보 → 계산 · 보정 계수`의 `비상복구 카드`를 누릅니다.
- 카드 상단에서 계수 프로필을 선택합니다. 여러 프로필이 있으면 실제 복구 대상과 같은 프로필을 골라야 합니다.

### 14.2 핵심 6개 카드 읽기

![보정계수 핵심 6개 카드](screenshots/v0.6.1/02-recovery-card-core.png)

| 카드 항목 | 뜻 | 형식·단위 | 복구할 때 확인할 것 |
| --- | --- | --- | --- |
| 계수 프로필 | 어느 계수 묶음인지 식별 | 이름 + 프로필 ID | 복구 대상 프로필 ID와 같아야 함 |
| 계수 버전 | 카드 작성 당시 버전 | 버전 문자열 | 수기 기록 시 글자 하나도 빠뜨리지 않음 |
| 계산식 버전 | 보정값을 적용하는 계산 골격 | 예: `BOF-REF-CALC 0.3.0` | 현재 앱의 계산식과 같아야 함 |
| 기준지문 | 문헌 기본계수 28개의 SHA-256 축약값 | 영문·숫자 12자리 | 기본계수가 달라진 카드를 잘못 적용하지 않게 차단 |
| 핵심 확인코드 | 카드 메타데이터와 핵심 6개를 묶은 검사값 | 영문·숫자 8자리 | 수기 오탈자·일부 누락을 검사 |
| C | 종점 C 예상에 더하는 절대 오프셋 | `%p`, 소수 5자리 | `+`/`-` 부호 포함 |
| 온도 | 종점 온도 예상에 더하는 절대 오프셋 | `°C`, 소수 1자리 | 섭씨 절대 차이 |
| P·Mn·Si·S | 각 종점 성분 예상에 더하는 절대 오프셋 | `%p`, 소수 5자리 | 상대 `%`가 아님 |
| 복구문자열 | 위 핵심정보를 한 줄로 묶은 값 | `BOFRC1|...|CHECK=...` | 가능하면 수기보다 복사·붙여넣기 사용 |

예를 들어 종점 P 문헌예상이 `0.01500%`이고 P 오프셋이 `+0.00100%p`이면 화면 예상은 `0.01600%`가 됩니다. `+0.00100%p`를 `+0.00100%`의 상대증가율로 해석하면 안 됩니다.

### 14.3 핵심 6개만 기록하는 절차

1. 카드에서 대상 `계수 프로필`, `계수 버전`, `계산식 버전`을 확인합니다.
2. `핵심 6개`가 선택된 상태에서 카드 전체가 보이도록 스크린샷을 찍거나 `인쇄/PDF`를 누릅니다.
3. 수기로 적을 때는 `기준지문 12자리`, `핵심 확인코드 8자리`, C·온도·P·Mn·Si·S의 부호와 소수점을 모두 적습니다.
4. 가능하면 `복구문자열 복사`로 메모 파일에 함께 보관합니다.
5. 실제 회사 계수가 포함될 수 있으므로 공개 저장소·개인 메일·개인 클라우드에는 올리지 않습니다.

### 14.4 상세 최대 24개 보기

![선택 학습 실행을 포함한 상세 카드](screenshots/v0.6.1/03-recovery-card-detailed.png)

`상세 최대 24개`는 핵심 6개에 선택한 학습 실행의 값 18개를 더합니다. 성분마다 아래 세 값이 있으므로 `6성분 × 3개 = 18개`입니다.

| 상세값 | 뜻 | 관계 |
| --- | --- | --- |
| 학습 당시값 | 해당 학습 실행을 만들 때 사용한 적용 오프셋 | 당시 기준 |
| 추천 증감 | 실제 오차 자료가 제안한 변화량 | 후보 − 당시값 |
| 추천 후보값 | 검토 후 적용할 수 있는 후보 | 당시값 + 추천 증감 |

상세값은 **학습 상태를 재현하기 위한 참고자료**입니다. 상세 18개를 입력해도 학습 차지·잔차·검증표본이 되살아나지는 않으며, 카드 복구가 직접 적용하는 값은 핵심 6개뿐입니다. 학습 실행이 없으면 `상세 기록 없음`으로 표시되는 것이 정상입니다.

### 14.5 수동 복구 입력

![비상복구 수동 입력 첫 화면](screenshots/v0.6.1/04-recovery-card-manual-input.png)

1. 현재 작업공간을 JSON으로 저장할 수 있다면 먼저 저장합니다.
2. 카드의 `수동 복구 입력` 탭을 엽니다.
3. 복구문자열이 있으면 붙여넣고 `문자열 나누기`를 누릅니다. 문자열이 없을 때만 메타데이터와 핵심 6개를 직접 입력합니다.
4. 카드의 프로필 ID·계수 버전·계산식 버전·기준지문·확인코드를 그대로 입력합니다.
5. C·온도·P·Mn·Si·S의 부호, 소수점, 단위를 다시 확인합니다.
6. 상세 18개가 있으면 펼쳐 입력할 수 있지만, 핵심 복구에는 필수가 아닙니다.
7. 복구 작업자와 복구 사유를 입력합니다.
8. `값 검사하고 현재 계수와 비교`를 누릅니다.

다음은 적용 차단 조건입니다.

- 확인코드 불일치 또는 복구문자열 변조
- 프로필 ID·계수 버전·계산식 버전·기준지문 불일치
- 핵심 6개 중 빈 값, 숫자가 아닌 값, 허용범위를 벗어난 값
- 상세값에서 `학습 당시값 + 추천 증감 = 추천 후보값` 관계가 맞지 않음
- 작업자 또는 복구 사유가 비어 있음

### 14.6 검증·비교와 저장

![복구문자열 검증과 현재 계수 비교](screenshots/v0.6.1/05-recovery-card-validated-comparison.png)

검사에 통과하면 `카드값`, `현재값`, `차이`를 비교합니다. 이 단계에서는 아직 설정이 바뀌지 않습니다. 값이 맞을 때만 `검증된 값을 계수 초안에 반영`을 누릅니다.

![설정 저장 전 비상복구 초안](screenshots/v0.6.1/06-settings-recovery-draft.png)

초안 반영 후에도 자동 적용되지 않습니다.

1. 설정 화면 상단의 녹색 안내에서 대상 프로필과 확인코드를 재확인합니다.
2. 여섯 오프셋을 다시 읽고 변경 사유를 확인합니다.
3. `설정 저장`을 눌러야 새 계수버전과 변경 이력이 생성됩니다.
4. 저장을 원하지 않으면 `복구 초안 버리기`를 누릅니다.
5. 저장 후 카드를 다시 열어 새 계수 버전과 핵심 6개가 맞는지 확인합니다.
6. 최신 전체 JSON도 새로 저장합니다.

비상복구로 저장된 계수버전에는 카드 프로필·버전·계산식·기준지문·확인코드·복구 작업자·사유가 남습니다. 다만 잃어버린 학습 근거를 복원한 것처럼 꾸미지 않으며 `학습근거 복원 안 됨` 상태를 유지합니다.

## 15. 투입 코치와 투입계수 학습

투입 코치는 기존 종점예상과 별도로 동작하는 선택형 계산기입니다. 화면을 열지 않아도 G단계 진행을 막지 않으며, 표시된 값은 실제 투입 지시나 투입 이력이 아닙니다. 실제로 넣은 양·시각은 기존 `자재 투입 기록` 또는 `재송풍 기록`에서 별도로 저장해야 합니다.

### 15.1 대시보드 한 줄 읽기

![대시보드 투입 코치](screenshots/v0.7.2/01-dashboard-addition-coach.png)

| 표시 | 뜻 | 작업자가 할 일 |
| --- | --- | --- |
| 문헌 시험 | 공개 문헌 기반 기본계수이며 현장 승인 전 | 실제 기준보다 우선하지 않음 |
| 투입 검토 | 현재 목표·입력에서 검토할 주안이 있음 | 필요할 때만 `비교 보기` |
| 재료·조작 | Flux·냉각재·합금·가탄재 또는 추가 산소 | 실제 사용 가능 재료인지 확인 |
| 권장량 | kg 또는 Nm³의 한 값·범위 | 한 값이어도 확정 지시가 아님 |
| 시점 추정 | PC 로컬시각으로 환산한 보조 표시 | 단계·경과·누적 산소를 함께 확인 |
| 비교 보기 | 내 계획과 코치 참고안을 나란히 표시 | 선택 기능 |
| 내 계획 | 작업자 수기 계산값을 계획 원장에 저장 | 실제 투입으로 자동 전환되지 않음 |
| 이번 차지에서 접기 | 이 차지의 코치 줄을 접음 | G단계에는 영향 없음 |

한 값으로 표시되는 경우는 계산 저·고값을 현장 한도나 숫자 반올림으로 표시했을 때 둘이 같아진 경우입니다. 같은 숫자를 `10–10`처럼 반복하지 않고 `10 Nm³`로 표시합니다. 시각도 시작·끝 분이 같으면 `10:21 시점 추정`으로 표시합니다.

### 15.2 내 계획과 코치안 비교

![투입 계획 비교](screenshots/v0.7.2/02-addition-plan-comparison.png)

| 항목 | 내 계획 | 코치 참고안 |
| --- | --- | --- |
| 조작·재료 | 작업자가 선택한 실제 계획 | 모델이 고른 주안 1개 |
| 양 | kg 또는 추가 산소 Nm³ | 문헌·현장계수 계산 범위 |
| 시점 | 지금, 로컬 시각, 취련 경과 min, 누적 산소 Nm³ | 허용 G단계와 추정 시간대 |
| 비교 | 낮음·범위 안·높음·다른 조작 | 목표 충돌·미확인 상태 |

- `내 계획 저장`: 작업자 계획 버전을 저장합니다. 같은 차지에서 다시 저장하면 이전 계획은 삭제하지 않고 `superseded`로 남깁니다. 예정 기준을 `로컬 시각`, `취련 경과`, `누적 산소`로 고르면 그 기준값까지 유효해야 버튼이 활성화되며, 잘못된 값은 입력창 아래에 이유가 표시됩니다.
- `코치안을 계획으로 복사`: 코치안을 새 작업자 계획으로 저장하고 입력 중인 오래된 초안도 같은 값으로 정리합니다. 실제 투입은 만들지 않습니다. 같은 제안에서 복사가 완료되면 버튼이 `코치안 복사 기록됨`으로 바뀌어 중복 계획을 막습니다. 계획 저장은 성공했지만 비교 판단 이력만 실패하면 두 결과를 구분해 알려줍니다.
- `저장된 내 계획 채택`: 위 비교표에 이미 저장된 활성 계획이 있을 때만 사용할 수 있습니다. 입력 중인 초안을 저장하지 않고 비교 결정만 한 번 남기며, 기록 완료 여부를 화면에 표시합니다.
- `샘플 후 다시 보기`: 현재 제안을 보류하고 새 샘플 뒤 재검토하도록 결정 상태를 남깁니다. 기록에 실패하면 창을 닫지 않고 오류를 표시합니다.
- `닫기`: 아무 실제 이력도 만들지 않고 닫습니다.

비교창 아래쪽 판단 버튼은 입력 중인 초안을 저장하지 않습니다. 초안을 계획으로 확정하려면 먼저 `내 계획 저장`을 사용하십시오. 같은 제안·같은 판단의 중복 이력은 만들지 않습니다.

상단 `계산 근거와 한계`에는 목적, 계산식·투입계수 버전, 문헌 ID, 가정과 누락값이 표시됩니다. `C·온도·P·Mn·Si·S 목표`가 서로 충돌하거나 입력이 부족하면 숫자를 억지로 만들지 않고 계산 보류 이유를 표시합니다.

### 15.3 문헌 시험 모델과 단위

투입 모델은 `Flux`, `냉각재·광석`, `합금·가탄재`, `추가 산소`, `권장 시점`을 분리 계산하고 비교 계층이 주안 1개와 대안 최대 1개를 고릅니다.

| 값 | 단위·형식 | 뜻 |
| --- | --- | --- |
| Flux 염기도 낮음·기준·높음 | 무차원 비 | CaO/SiO₂ 총량 계산의 문헌 시나리오 범위 |
| 스크랩 냉각열 기준 | kJ/kg | 스크랩 1 kg의 문헌 냉각효과 기준 |
| 광석/스크랩 당량 | 무차원 배수 | 광석 냉각효과를 스크랩 기준과 비교한 시험 범위 |
| 회수율 | 0~1 비율 | 합금·가탄재 명목 성분 중 용강에 회수되는 시험 비율 |
| 문헌 용해속도 | kg/s | 투입 후 반응·용해 시간 범위 계산의 시험값 |
| 조작별 최소·최대 | 재료 kg, 산소 Nm³ | 현장 검토 한도. 공란은 현장 승인 한도가 없다는 뜻 |
| 허용 단계 | G0~G8 | 해당 조작 참고안을 계산할 수 있는 단계 |

냉각재는 최신 온도예상과 목표온도의 차이를 열량으로 바꾼 뒤 재료별 유효 냉각열로 나눕니다. 합금·가탄재는 목표 성분 부족량, 추정 용강질량, 재료 성분함량과 회수율로 명목 필요량을 계산합니다. 추가 산소는 최신 C와 목표 C 차이, 추정 용강질량과 산소효율 시험계수를 사용하며 부원료 부족을 자동 대체하지 않습니다.

### 15.4 투입계수 오차학습

![투입 코치 오차학습](screenshots/v0.7.2/03-addition-learning.png)

기존 `종점 오차학습`과 새 `투입 효과 오차학습`은 계수·버전·복구카드를 서로 섞지 않습니다.

학습 적격이 되려면 다음 자료가 연결되어야 합니다.

1. 제안 생성 직전 저장된 종점예상과 차지·단계·산소 상태
2. 제안과 연결된 실제 재료 투입 또는 실제 추가 산소
3. 투입 전 유효 분석과 투입 후 유효 분석
4. 같은 투입 모델·계수버전·재료·강종·설비 범위
5. DEMO가 아닌 실제 차지이며 수정·무효·오래된 연결이 아님

효과 오차는 `실제 변화 − 모델 예상 변화`입니다. 양 보정과 예상효과 보정은 이 오차를 사용하고, 시점 이동은 앞서 저장한 작업자 예정시각·코치 권장시각과 실제 투입시각의 차이를 별도 근거로 사용합니다.

| 실제 적격자료 수 | 상태 |
| ---: | --- |
| 1~9 | 오차 원장 축적 |
| 10~29 | 편향 방향 참고 |
| 30~49 | 임시 후보 |
| 50~69 | 검증표본 대기 |
| 70 이상 | 최신 20건 독립 검증 가능 |

70건만으로 자동 승인이 되지는 않습니다. 최소 10일, 작업자 3명, 투입량 3구간, 시점 3구간이 확보되고 최신 20건에서 기존 계수보다 MAE가 개선돼야 `승인 검토 가능` 후보가 됩니다. 합성 DEMO는 화면·계산 시험에는 쓰지만 승인 후보를 만들지 않습니다. 후보는 자동 적용되지 않고 설정 초안, 변경 사유, 사람의 승인 저장을 거쳐 새 버전이 됩니다.

### 15.5 투입계수 비상복구 카드

![투입계수 비상복구 카드](screenshots/v0.7.2/04-addition-recovery-card.png)

| 핵심값 | 단위 | 1.0000의 뜻 |
| --- | --- | --- |
| Flux 양 보정 | 배 | 계산량 무보정 |
| 냉각재 양 보정 | 배 | 계산량 무보정 |
| 합금·가탄재 양 보정 | 배 | 계산량 무보정 |

`1.0500 배`는 해당 계산량 또는 효과를 5% 늘리고 `0.9500 배`는 5% 줄이는 뜻입니다. 카드의 PROFILE, VERSION, FORMULA, BASE/CHECK와 `BOFARC1` 문자열을 함께 보관해야 합니다. 최신 추천 후보가 없으면 `–`가 정상입니다.

![투입계수 수동 복구](screenshots/v0.7.2/05-addition-manual-recovery.png)

수동 복구는 문자열과 최소 3자의 사유를 입력해 확인코드·문헌기반 지문·프로필·계산식·숫자범위를 검사합니다. 통과해도 즉시 적용하지 않고 `투입 모델` 설정 초안으로만 가져갑니다. 원본 조업·오차·학습 근거는 복원하지 않으며 전체 복원은 JSON을 사용합니다.

### 15.6 투입 모델 설정

![투입 모델 설정](screenshots/v0.7.2/06-addition-model-settings.png)

| 설정 구역 | 설명 | 주의 |
| --- | --- | --- |
| 적용 상태 | 문헌 시험, 사용자 수정·검증 전, 현장 검증·승인 | 실제 검증 없이 현장 승인으로 바꾸지 않음 |
| 강종·설비 범위 | 전체 또는 특정 코드 | 새 차지는 시작시점 설정 스냅샷을 사용 |
| 핵심 보정계수 6개 | 양·시점·효과 보정 | `배` 1.000은 무보정, `분` 0은 이동 없음 |
| 문헌 기본 시나리오 | 염기도·냉각·당량 범위 | 현장 계수가 아니라 공개 시험값 |
| 조작별 한도·단계 | 모델 사용 여부, 최소·최대, G단계 | 공란 한도를 승인값으로 해석하지 않음 |
| 재료별 고급값 | 냉각열, 주성분, 회수율, 용해속도 | 로트·수분·입도가 달라지면 새 재료코드나 버전 사용 |

설정을 바꾸면 상태는 `사용자 수정·검증 전`으로 내려가고 기존 승인정보는 지워집니다. 상단 변경 사유를 입력하고 `설정 저장`을 눌러야 새 설정·투입계수 버전이 생성됩니다. 진행 중 차지의 시작 스냅샷은 소급 변경하지 않습니다.

### 15.7 자동저장·JSON·Excel·오류 복구

- 작업자 계획, 제안·그림자 제안, 결정, 실제 연결, 효과 오차, 후보, 투입계수 버전과 복구 출처는 IndexedDB에 자동저장됩니다.
- 전체 JSON에는 위 자료와 투입 모델 설정이 포함됩니다. 구형 v0.6 JSON은 문헌 기본 투입 프로필을 생성해 읽습니다.
- Excel은 투입계수 버전·제안·계획·효과 오차·추천 후보를 사람이 확인하는 출력이며 복원 입력이 아닙니다.
- 실제 투입을 수정·무효하면 연결된 효과 근거는 다시 계산하거나 오래됨으로 표시해야 하며 원본 이력을 삭제하지 않습니다.
- 모델 한 개 계산 오류는 앱 전체를 빈 화면으로 만들지 않고 해당 모델을 계산 보류로 격리합니다.

## 16. 자동저장, 외부 JSON, 내부 복구점

![저장·복구·보고서](screenshots/v0.6.0/01-storage-recovery.png)

### 16.1 자동저장

- 상태가 바뀐 뒤 약 250ms 동안 추가 변경이 없으면 IndexedDB에 저장합니다.
- 우측 상단과 Data Ledger에 완료/저장 중/오류, 최근 저장시각, revision을 표시합니다.
- 브라우저를 닫았다 다시 열면 마지막 저장상태를 불러옵니다.
- 다른 창이 더 최신 revision을 저장하면 오래된 창은 쓰기를 막고 최신 상태 다시 읽기를 요구합니다.
- 자동저장은 같은 PC·브라우저 안의 편의 기능이며 외부 백업이 아닙니다.

### 16.2 단일 JSON 저장

`전체 데이터 JSON으로 저장`은 아래를 한 파일에 넣습니다.

- 모든 차지·단계·이벤트·샘플·분석·정정·예상 스냅샷
- 강종·재료·설비·관리게이트·단위·계수·버전 이력
- 오차대장·학습 실행·모델 레지스트리
- 작업자 표시 이름·운영로그·복구 메타데이터
- 유효한 내부 복구점

파일은 UTF-8 JSON이며 정렬된 내용에 SHA-256을 계산합니다. 생성 직후 다시 읽어 스키마·해시·행 참조·설정·조업시각·학습 실행을 검증한 뒤 다운로드합니다. 최대 불러오기 크기는 50 MiB입니다.

### 16.3 JSON 전체 불러오기

![JSON 비교·검증](screenshots/v0.6.0/02-json-restore-compare.png)

1. `JSON 백업 불러오기`를 누르고 파일을 선택합니다.
2. 해시·schema·app 버전과 현재/백업 차지·이벤트·오차·학습·복구점 수를 비교합니다.
3. 자동 병합하지 않고 전체 교체한다는 경고를 읽습니다.
4. 필요하면 `현재 데이터 JSON 저장`으로 현재 상태를 먼저 보관합니다.
5. 확인 체크 후 `검증된 백업으로 전체 교체`를 누릅니다.
6. 적용 직전 현재 작업공간은 보호 복구점으로 남습니다.
7. 7일 동안 `마지막 불러오기 취소`로 직전 작업공간을 되돌릴 수 있습니다.

해시가 맞아도 내부 상태·단위·참조·시각·설정·학습 구조가 틀리면 적용하지 않습니다. 구형 복구점 하나가 정합성에 실패하면 현재 작업공간 전체 백업을 막지 않고 그 복구점만 로컬에 보존한 채 외부 JSON에서 제외합니다. 해당 행은 복원 버튼도 비활성화됩니다.

### 16.4 내부 복구점

- 단계 전환, 출강, 계수 변경, 차지 취소·삭제, 전체 복원·초기화 등 중요 작업 직전에 자동 생성합니다.
- 일반 복구점은 최대 20개, 30일 순환 보관합니다.
- 보호 복구점은 자동 순환에서 제외합니다.
- 사용자가 현재 상태 복구점을 수동 생성하고 보호/해제할 수 있습니다.
- 복원은 다시 안전 복구점을 만든 뒤 원자적으로 작업공간과 복구점 목록을 교체합니다.

### 16.5 호환 ZIP과 Excel

- `호환용 CSV ZIP`: v0.5 계열 복원과 사람이 CSV를 확인할 때 사용
- `구형 ZIP 불러오기`: 빈 저장소 또는 DEMO 작업공간에서만 허용
- `Excel 보고서`: 열람·보고용 XLSX; 복원 입력으로 사용하지 않음
- Excel에는 차지요약, 이벤트, 분석, 정정, 예상, 오차대장, 계수후보, 계수버전, 경고 시트가 포함됩니다.

## 17. 백업 운영 권장

| 시점 | 권장 작업 |
| --- | --- |
| 매 차지 중 | IndexedDB 자동저장 상태 확인 |
| 교대 종료 | 전체 JSON 저장, 파일명·시각 확인 |
| 계수 변경 전후 | 각각 JSON 저장 + 내부 보호 복구점 확인 + 핵심 6개 카드 갱신 |
| 브라우저 데이터 정리 전 | 최신 JSON을 회사 허용 저장소에 복사 |
| PC 이동 | 원본 JSON 보관 후 새 PC에서 미리보기·전체 복원 |
| 복원 직후 | 차지 수·현재 단계·계수버전·학습 실행 수 확인 |

JSON 파일을 메모장으로 수정한 뒤 다시 쓰지 마십시오. 내용이 바뀌면 SHA-256 검증에서 차단됩니다.

## 18. 보안과 데이터 취급

- 네트워크 전송, 원격 분석, 클라우드 동기화는 없습니다.
- 회사 실제 차지·사내 기준·개인정보·현장 계수·자격증명을 공개 GitHub에 올리지 마십시오.
- JSON은 작업공간 전체를 포함하므로 사내 데이터 분류와 보관기간을 적용해야 합니다.
- 브라우저 프로필 삭제, 사이트 데이터 삭제, Windows 계정 교체 시 IndexedDB가 사라질 수 있습니다.
- 외부 JSON 저장 성공 여부는 실제 파일 존재·크기·수정시각으로 확인하십시오.
- 공용 PC에서는 승인되지 않은 USB·개인 클라우드·개인 메일로 백업하지 마십시오.
- 비상복구 카드에도 실제 현장 보정계수가 포함될 수 있으므로 사진·출력물·메모의 보관등급과 폐기절차를 적용하십시오.

## 21. 작업자 인수인계 점검표

- 현재 진행 차지 수와 선택 차지가 맞다.
- 각 차지의 현재 G 단계와 마지막 실제 입력시각이 맞다.
- 누적 산소의 단위가 Nm³이고 최근값보다 역행하지 않는다.
- 최신 채택 샘플과 분석 결과가 실제 결과와 맞다.
- C·온도·P·Mn·Si·S 목표와 종점예상 상태를 확인했다.
- 재취련·출강은 실행 사실을 기록한 것이며 지시로 오해하지 않았다.
- 자동저장 완료 revision을 확인했다.
- 최신 전체 JSON을 허용된 폴더에 저장했다.
- 현재 계수버전의 핵심 6개 비상복구 카드가 최신이며 확인코드가 보인다.
- JSON 저장 완료 메시지의 차지 수와 파일의 수정시각을 확인했다.
- 다음 작업자에게 정정·취소·복구·계수 후보 상태를 전달했다.
