# 오프라인 AI 취련 코치 제품 목표

## 1. 확정 목표

> 작업자가 수동으로 조업·샘플·종점 데이터를 입력하면, 사용할수록 사업소와 설비 특성에 맞게 종점예상과 설명이 개선되는 오프라인 AI 취련 코치

## 2. 제품의 역할

- 회사 시스템이나 제어계통에 연결하지 않는 독립형 HTML 보조도구로 시작한다.
- 작업자가 입력한 조업 이벤트, 공정조건, 샘플 분석값, 출강 전 예상, 실제 종점값을 차지별로 연결한다.
- 공개 문헌 기본모델에서 시작하고, 같은 사업소·설비·강종·계수버전의 완료 차지 오차를 분리해 누적한다.
- 최신 유효 샘플이 들어오면 해당 차지의 예상값과 설명을 다시 계산한다.
- 충분한 완료 이력이 쌓이면 계수 변경 후보와 근거를 추천한다. 작업자의 검토·승인 전에는 자동 적용하지 않는다.
- 목표 성분 범위와 현장 기준은 학습으로 자동 변경하지 않는다.
- v0.6.1은 현재 적용 중인 핵심 보정계수 6개를 사람이 읽고 다시 입력할 수 있는 비상복구 카드로 제공한다. 카드 복구는 검증·비교 후 설정 초안으로만 전달하며 정상 JSON 백업이나 학습 근거를 대신하지 않는다.
- v0.7.2는 Flux·냉각재·합금·가탄재·추가 산소의 양·시점을 독립 투입모델로 참고 계산하고, 작업자 계획·코치 제안·실제 투입을 분리해 비교한다. 실제 투입 전·후 효과 오차는 기존 종점 오차와 별도 원장·계수·버전으로 학습한다.
- 투입 코치는 선택사항이며 사용·확인·채택 여부로 G단계를 막지 않는다. 문헌 시험계수는 현장 승인값이 아니고, 투입계수 후보도 데이터 분포와 최신 독립검증을 거친 뒤 사람이 승인 저장하기 전에는 적용하지 않는다.

## 3. 초기 범위 밖

- PLC·HMI·SCC·MES와의 실시간 연동 또는 설비 자동제어
- 작업자 승인 없는 계수 자동 적용
- 강화학습을 이용한 조업 행동 자동 선택
- 실제 회사 데이터와 현장 계수의 공개 저장소 업로드
- 실제 차지 검증 전 현장 정확도 또는 출강 적합성 보증

## 4. 데이터 저장과 이동 원칙

### 4.1 작업 중 자동 저장

- 작업 중 상태는 브라우저의 IndexedDB에 자동 저장한다.
- v0.6.0은 상태 변경 후 약 250ms 동안 추가 변경이 없으면 저장하고, 다음 실행 때 마지막 저장 상태를 자동으로 불러온다. 저장 상태와 마지막 저장 시각은 상단과 Data Ledger에 함께 표시한다.
- 저장할 때마다 작업공간 개정 번호를 비교하여, 오래 열린 다른 창이 더 최신 상태를 조용히 덮어쓰지 못하게 막는다.
- 주요 교체·초기화·단계 전환 전에는 IndexedDB 내부 복구점을 만들고, 복구점마다 스키마·상태 정합성을 다시 확인한 뒤 복원한다.
- 자동저장은 앱이 열려 있는 동안 동작한다. 앱을 닫은 뒤 예약 저장을 수행하거나 외부 파일을 계속 관리하는 백그라운드 프로그램은 아니다.
- 같은 PC라도 Chrome과 Edge, 일반·시크릿 프로필은 저장소가 서로 다르며, 브라우저 데이터 삭제·회사 정책 초기화·HTML 위치 변경의 영향을 받을 수 있다.
- 단일 HTML은 브라우저 보안상 사용자의 동작이나 별도 권한 없이 임의의 PC 폴더에 ZIP·JSON 파일을 계속 덮어쓸 수 없다.
- IndexedDB는 편의용 작업 저장소이며 브라우저 초기화·회사 정책 변경에 대비한 외부 백업을 별도로 유지한다.

### 4.2 이동용 백업 형식

- v0.6.0의 기본 이동·복원 형식은 스키마 버전, 생성 시각, 차지·이벤트·샘플·종점·오차·설정·계수버전·학습실행·복구점과 무결성 정보를 담은 **단일 JSON**이다.
- JSON은 저장 직후 앱이 다시 읽어 스키마·SHA-256·관계 정합성을 확인한다. 불러올 때도 현재 데이터와 가져올 데이터의 건수·버전·생성시각을 먼저 비교하고 작업자가 명시적으로 전체 교체한다.
- 전체 교체 전에는 보호 복구점을 만들고, 교체 후 7일 동안 즉시 되돌리기 동작을 제공한다.
- 회사 메일이 ZIP 첨부를 차단할 수 있으므로 ZIP을 유일한 이동·복원 형식으로 고정하지 않는다.
- 기존 CSV ZIP은 회사 정책에서 허용될 때 사용하는 선택형 호환 보관 묶음으로 유지한다.
- CSV/XLSX는 사람이 열람·분석하는 출력으로 유지하고, XLSX는 복원 원본으로 사용하지 않는다.
- JSON 첨부도 차단되는 경우에는 보안정책을 우회해 확장자만 바꾸지 말고, 승인된 공용 폴더 또는 보안 담당자가 허용한 전송 형식을 확인한다.

### 4.3 자동관리 수준

| 기능 | 단일 HTML 가능 여부 | 기준 |
| --- | --- | --- |
| 입력 직후 작업상태 자동저장 | 가능 | IndexedDB 사용 |
| 재실행 시 마지막 상태 자동복구 | 가능 | 같은 브라우저·프로필·저장영역 기준 |
| 내부 세대별 복구점 자동보관 | 구현 | 중요 작업 전 보호·일반 스냅샷과 보존정책 적용 |
| JSON·ZIP 내려받기 | 가능 | 사용자 버튼 동작 필요 |
| 지정 폴더에 파일 자동갱신 | 조건부 | 사용자가 폴더·파일 권한을 부여하고 브라우저 정책이 허용할 때만 가능 |
| 앱 종료 후 예약 백업·클라우드 업로드 | 단일 HTML만으로 불가 | 설치형 프로그램·로컬 서비스 또는 승인된 동기화 기능 필요 |

v0.6.0은 `IndexedDB 실시간 자동저장 + IndexedDB 내부 복구점 + 필요할 때 수동 단일 JSON 저장·불러오기`를 구현했다. v0.6.1은 JSON과 브라우저 저장소를 함께 잃은 경우를 위한 `핵심 보정계수 6개 비상복구 카드 + 선택 학습 상세 18개`를 추가했다. 평상시에는 외부 저장이 필요 없고 JSON 백업 알림도 입력을 막지 않는다. 회사가 승인한 동기화 폴더가 있을 경우의 폴더 권한 기반 자동 JSON 저장은 후속 선택 기능으로 남긴다.

## 5. 학습 데이터 형식 원칙

- 앱의 운영 상태와 완전 복원은 관계가 있는 여러 데이터 묶음을 한 번에 검증할 수 있는 단일 JSON이 적합하다.
- 대용량 학습용 행 데이터나 외부 분석용 추출에는 JSONL 또는 CSV를 별도로 만들 수 있다.
- Markdown은 제품 기준, 모델 카드, 계수 변경 사유, 검증 결과처럼 사람이 읽는 문서에 사용하며 계산·학습 원본으로 사용하지 않는다.

## 6. 미확정 운영 항목

- 사용자는 JSON 첨부는 허용될 가능성이 높고 ZIP은 외부 클라우드로 보관할 수 있다고 판단했다. 회사 PC에서 실제 허용되는 첨부 확장자와 최대 용량은 아직 확인이 필요하다.
- 승인된 백업 폴더와 교대·일일·차지 완료별 백업 주기
- 기존 v0.5.0 CSV ZIP 백업과의 장기 호환 기간
- 보호 복구점의 현장 보존 기간과 공용 PC 교대 운영 책임

v0.6 기본 저장·복원 형식은 단일 JSON으로 구현했고 v0.7.2 투입계획·제안·효과오차·후보·모델버전도 같은 전체 백업에 포함한다. 스키마와 복원 규칙은 [v0.6 JSON 백업·복구 계약](../domain/v0.6_JSON_백업복구_계약.md), 상세 범위와 완료조건은 [v0.6 오프라인 AI 취련 코치 기획안](v0.6_오프라인_AI_취련코치_기획안_2026-08-23.md)과 [v0.7 선택형 투입 코치 기획안](v0.7_최소입력_선택형_투입코치_기획안_2026-08-24.md)을 따른다.
