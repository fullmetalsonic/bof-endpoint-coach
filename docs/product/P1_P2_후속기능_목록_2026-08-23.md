# 정정·운영 안정성 P1·P2 후속 기능 목록

상태: v0.4.0 후보에서 승격 P0와 연계 사용성 항목을 구현·검증함. 남은 승인 워크플로·현장 검증·대량 성능은 후속으로 유지함.  
원칙: P0 정정·이력 관리의 검증이 끝난 뒤 현장 우선순위에 따라 별도 묶음으로 진행한다.

## v0.6 반영 예정

- 자동저장 상태 강화, 내부 복구점, 단일 JSON 저장·불러오기, 백업 필요 알림, 학습 실행 재현성과 예상 설명 개선은 [v0.6 기획안](v0.6_오프라인_AI_취련코치_기획안_2026-08-23.md)의 P0로 승격했다.
- 승인 폴더 자동 JSON 갱신, 학습용 JSONL·CSV 추출, 유사 차지·데이터 품질 대시보드는 후속 후보로 유지한다.
- 아래 표의 기존 완료 상태는 과거 구현 이력으로 보존하며 v0.6 P0와 중복되는 항목을 삭제하지 않는다.

## 2026-08-23 확장 감사 승격 항목

다음 항목은 [확장 사용성·복구 감사](../audits/v0.3.0_확장_사용성_복구_감사_2026-08-23.md)에서 실제 재현 또는 코드 경로로 위험이 확인되어, 다음 유지보수의 `운영 저장·신뢰성 P0` 묶음으로 승격한다.

| 새 ID | 기존 연결 | 승격 이유 |
| --- | --- | --- |
| P0-A01 | 신규 | 복수 HTML 창의 마지막 저장이 최신 차지 전체를 덮어쓸 수 있음 |
| P0-A02·A04 | P1-04 확장 | 읽기 실패가 빈 상태·저장 완료로 보일 수 있고 쓰기 실패 복구 행동이 없음 |
| P0-A03 | 신규 | 신규 차지와 기준 설정의 미저장 초안이 경고 없이 소실됨 |
| P0-A05 | 신규 | DEMO·문헌·현장 승인 근거와 실제 입력 문구의 신뢰 경계가 약함 |

위 P0-A01~A06은 [v0.4.0 통합 검증](../audits/v0.4.0_통합_운영저장_사용성_검증_2026-08-23.md)에서 구현·자동검증 완료했다.

P1-01의 차이 보기와 P1-02의 발행·중지 전체 워크플로는 P1에 남긴다. 다만 설정 변경 시 새 버전·변경자·시각·사유를 남기는 최소 기능은 P0-A06에 포함한다.

## P0와의 경계

v0.4.0 후보는 각 차지에 시작 당시 설정 스냅샷을 보존하고 로컬 설정 변경의 새 버전·사유·필드 차이를 남긴다. 이후 공용 설정 변경은 진행·완료 차지 예상값을 소급 변경하지 않는다. 설정의 정식 발행·중지·다자 승인 워크플로는 P1이다.

P1·P2를 시작할 때는 이 문서에서 해당 항목을 별도 요구사항·검증 문서로 분리하고, 이 목록에는 상태와 연결 문서만 남긴다.
