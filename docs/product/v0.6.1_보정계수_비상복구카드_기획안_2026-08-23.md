# v0.6.1 보정계수 비상복구 카드 기획안

작성일: 2026-08-23  
상태: 구현 기준 확정  
대상 버전: v0.6.1

## 1. 목적

IndexedDB와 JSON 백업이 모두 없어졌을 때에도 작업자가 미리 캡처하거나 종이에 적어 둔 보정값을 이용해 **현재 적용 중이던 6개 종점 보정 오프셋을 부분 복구**할 수 있게 한다.

이 기능은 JSON 전체 백업을 대체하지 않는다. 차지·샘플·종점 실측·오차 대장·학습 실행 원본은 카드만으로 복구할 수 없다.

## 2. 버전 판단

- 엄격한 Semantic Versioning에서는 새 기능을 minor 버전으로 볼 수 있다.
- 이 프로젝트에서는 v0.6.0의 오프라인 저장·학습 운영 기반을 깨지 않고 보강하는 하위 호환 기능이므로 `v0.6.1`로 관리한다.
- 앱 버전은 `0.6.1`로 올리되 JSON 백업 계약은 새 필수 필드를 만들지 않으므로 `0.6.0`을 유지한다.

## 3. 숫자 구성

| 구분 | 성분별 숫자 | 전체 숫자 | 의미 |
| --- | ---: | ---: | --- |
| 핵심 | 현재 적용 보정값 1개 | 6개 | 실제 종점 참고예상에 더해지는 오프셋 |
| 상세 선택 | 학습 당시 현재값 | 6개 | 추천을 계산할 때의 시작 오프셋 |
| 상세 선택 | 추천 증감 | 6개 | 유효 오차에서 계산한 추가 보정 후보 |
| 상세 선택 | 추천 후보값 | 6개 | `학습 당시 현재값 + 추천 증감` |
| 합계 | 성분별 최대 4개 | 최대 24개 | 핵심 6개와 참고 18개 |

대상 성분은 `C`, `온도`, `P`, `Mn`, `Si`, `S`이다. C·P·Mn·Si·S 오프셋 단위는 상대 퍼센트가 아니라 종점 질량백분율 값에 직접 더하는 **퍼센트포인트(%p)**이고, 온도는 `°C`이다.

## 4. 혼합 금지 기준

적용 보정값은 계수 프로필에 속하고, 학습 후보는 다음 비교군에 속한다.

`강종 | 설비 프로필 | 계산식 버전 | 계수 버전 | DEMO/FIELD`

- 상세 카드에서 비교군을 하나 선택한다.
- 서로 다른 강종·설비·계수 버전의 후보를 한 카드에 섞지 않는다.
- 비교군에 해당 성분의 현재 학습 실행이 없으면 `근거 없음`으로 표시하고 0으로 만들지 않는다.
- 오래된 실행, DEMO 전용 실행, 다른 계수 버전의 실행은 경고 상태로만 표시하며 현장 후보처럼 보이지 않게 한다.

## 5. 카드 화면

### 5.1 진입 위치

- `학습 · 계수` 화면 상단: `비상복구 카드` 버튼
- `기준 정보 > 계산 · 보정 계수`의 학습 보정 오프셋 제목 옆: 동일 버튼
- 두 버튼은 하나의 공용 카드 창을 연다.

### 5.2 기본 화면

기본은 `핵심 6개` 모드이다. 전문 용어를 몰라도 캡처할 수 있도록 다음 정보를 한 화면에 고정한다.

- 카드 형식 버전
- 계수 프로필 이름·ID와 현재 계수 버전
- 계산식 버전
- 기준지문: 실제 적용 중인 28개 문헌·현장 수정 기준값의 SHA-256 앞 12자리
- 생성 시각과 작업자
- C·온도·P·Mn·Si·S 현재 적용 보정값과 단위
- 핵심 확인코드: 기준 식별정보와 핵심 6개 값의 SHA-256 앞 8자리
- `카드는 부분 복구용이며 JSON 전체 백업을 대체하지 않음` 경고
- 현장 계수일 수 있으므로 외부 공개·공개 저장소 커밋 금지 경고

### 5.3 상세 24개 화면

성분별 한 줄에 아래 열을 표시한다.

`성분 | 현재 적용(핵심) | 학습 당시값 | 추천 증감 | 추천 후보값 | 단위 | 근거 수·상태`

상세 18개는 학습 당시 상태를 사람이 참고하기 위한 값이다. 원본 차지와 오차 행이 없으면 다시 입력해도 학습 근거로 인정하지 않는다.

### 5.4 카드 동작

- `핵심 6개` / `상세 최대 24개` 전환
- 비교군 선택
- `큰 화면`으로 화면 캡처에 적합한 밀도 제공
- `인쇄/PDF`용 A4 가로 인쇄 스타일
- `핵심 복구문자열 복사`
- `표 복사`
- `수동 복구 입력`

PNG 자동 생성과 QR 코드는 v0.6.1 범위에서 제외한다. 운영체제 캡처와 브라우저 인쇄를 사용한다.

## 6. 수동 복구 흐름

1. 작업자가 복구 대상 계수 프로필을 선택한다.
2. 카드의 프로필 ID, 계산식 버전, 기준지문, 핵심 확인코드와 6개 값을 입력하거나 복구문자열을 붙여 넣는다.
3. 앱이 숫자, 단위, 허용 범위, 확인코드, 계산식 버전, 기준지문을 검사한다.
4. 선택 입력한 상세 18개는 `후보값 = 학습 당시값 + 추천 증감` 관계를 검사한다.
5. 현재값과 복구값의 차이, 영향을 받는 새 차지 범위를 표시한다.
6. 작업자명과 복구 사유를 반드시 입력한다.
7. `계수 초안에 반영`만 수행한다. 즉시 계산에 적용하거나 기존 값을 덮어쓰지 않는다.
8. 기존 `설정 저장`을 누르면 이전 계수는 버전 이력에 보관되고, `비상 수동복구` 출처를 가진 새 계수 버전이 생성된다.
9. 저장 후 JSON 전체 백업을 만들도록 안내한다.

진행 중이거나 완료된 기존 차지는 장입 시작 때 저장된 기준 스냅샷을 계속 사용한다. 복구한 새 계수는 이후 새로 만드는 차지부터 사용한다.

## 7. 검증·차단 규칙

### 7.1 필수 차단

- 빈 값, NaN, Infinity
- C·P·Mn·Si·S 절대값 100 %p 초과 또는 온도 절대값 500 °C 초과
- 계산식 버전 불일치
- 기준지문 불일치
- 핵심 확인코드 불일치
- 상세 모드에서 입력한 후보 산식 불일치
- 작업자명 또는 복구 사유 누락

기준지문이 다른 경우 오프셋만 적용하면 같은 종점예상을 재현할 수 없으므로 v0.6.1에서는 강제 적용을 제공하지 않는다.

### 7.2 안전한 저장

- 현재 계수를 직접 덮어쓰지 않는다.
- 새 설정 초안과 새 날짜형 계수 버전을 만든다.
- 복구 전 내부 안전 복구점을 만든다.
- 작업 로그·설정 변경 이력에 작업자, 시각, 사유, 카드 확인코드, 원래 계수 버전을 남긴다.
- 상세 18개는 `수동 입력 참고 스냅샷`으로만 보존하고 residual ledger나 training run을 생성하지 않는다.

## 8. 복구문자열

사람이 복사·붙여넣기 할 수 있는 한 줄 형식을 사용한다.

```text
BOFRC1|PROFILE=COEF-LIT-001|FORMULA=BOF-REF-CALC%200.3.0|BASE=12자리|C=+0.00200|TEMP=-5.0|P=+0.00100|MN=-0.01000|SI=+0.00000|S=+0.00050|CHECK=8자리
```

- `BOFRC1`은 복구문자열 형식 버전이다.
- 문자열 파서는 키 순서와 대소문자 차이를 허용하되, 중복 키와 알 수 없는 키는 차단한다.
- `CHECK`는 오입력 탐지용이지 전자서명이나 보안 인증이 아니다.

## 9. 데이터 구조

새 영구 저장소를 만들지 않는다. 기존 계수 프로필과 설정 버전 이력을 사용한다.

수동 복구 출처는 계수 프로필의 선택 메타데이터로 보존한다.

```json
{
  "manualRecoverySource": {
    "cardVersion": "BOFRC1",
    "enteredAt": "ISO-8601",
    "enteredBy": "작업자명",
    "reason": "복구 사유",
    "sourceProfileId": "COEF-LIT-001",
    "sourceCoefficientVersionId": "원래 버전",
    "formulaVersion": "BOF-REF-CALC 0.3.0",
    "baseFingerprint": "12자리",
    "coreCheckCode": "8자리",
    "referenceLearningValues": []
  }
}
```

이 필드는 선택 필드이므로 JSON 스키마 `0.6.0`의 필수 구조를 바꾸지 않는다. v0.6.1 앱에서 구조와 길이를 별도로 검증한다.

## 11. 시험 기준

### 단위 시험

- 6개 값 → 복구문자열 → 파싱 왕복 일치
- 공백·키 순서·소문자 허용, 중복·미지 키·누락 차단
- 숫자 변조·확인코드 변조 차단
- 기준값 한 개 변경 시 기준지문 변화
- 6성분 단위와 자릿수 고정
- 24개 표 생성과 빈 후보 `근거 없음` 처리
- 후보 산식 허용 오차 검사
- 새 계수 초안 생성, 이전 버전 보존, 수동 참고값이 학습 실행으로 변환되지 않음
- JSON 저장·복원 후 수동 복구 메타데이터 보존

### E2E·화면 시험

- 학습 화면과 설정 화면에서 같은 카드 열림
- 핵심/상세 전환, 비교군 선택, 복사
- 잘못된 코드·기준지문·계산식 버전·범위 입력 차단
- 올바른 6개 값 → 비교 → 설정 초안 → 사유 입력 → 새 버전 저장
- 기존 진행 차지 예상은 변하지 않고 새 차지에만 새 계수 적용
- 키보드 포커스·Escape 닫기·오류 연결
- 1920×1080, 1280 폭, 760 폭, 인쇄 미리보기 레이아웃 확인
- 한국어·영어 문구 확인

## 12. 완료 조건

- BUILD, LINT, UNIT, E2E, REQUIREMENT CHECK, REGRESSION CHECK, REVIEW가 PASS
- CRITICAL/HIGH 이슈 0개

- 상세 설명서, 빠른 설명서, README, 누적이력, 릴리스 노트가 v0.6.1과 일치
- 공개 문서와 스크린샷에는 합성 DEMO·0 보정값만 사용하고 실제 현장 계수를 넣지 않음
