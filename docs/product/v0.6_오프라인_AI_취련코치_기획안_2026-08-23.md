# v0.6 오프라인 AI 취련 코치 기획안

상태: **제품 기획 확정 / 구현 전**  
기준일: 2026-08-23  
상위 목표: [오프라인 AI 취련 코치 제품 목표](AI_취련코치_제품목표_2026-08-23.md)

## 1. v0.6 한 문장 목표

> v0.5의 문헌 종점예상·샘플 보정·오차학습 기능을 유지하면서, 작업자의 모든 입력과 학습 결과를 자동 보존하고 단일 JSON으로 안전하게 저장·불러오며, 예상값이 나온 근거와 현장 보정 상태를 이해할 수 있게 한다.

v0.6은 새로운 설비 제어나 무근거 고성능 AI를 추가하는 버전이 아니다. 데이터가 사라지거나 섞이지 않고, 같은 입력·기준·계수에서 같은 예상과 설명을 재현할 수 있게 만드는 **오프라인 학습 운영 기반 버전**이다.

## 1.1 저장 역할 확정

| 순서 | 저장 위치·형식 | 역할 |
| ---: | --- | --- |
| 1 | IndexedDB 현재 상태 | 평상시 작업 원본. 입력 때 자동저장하고 재실행 때 자동복구 |
| 2 | IndexedDB 내부 복구점 | 중요 작업 전 상태를 되돌리기 위한 세대별 안전장치 |
| 3 | 단일 JSON | 작업자가 필요할 때 만드는 수동 백업·PC 이동·복원 파일 |
| 4 | CSV ZIP·XLSX | 구형 호환 보관과 사람용 보고서 |

평상시 사용에는 외부 폴더·클라우드·JSON 파일이 필요하지 않다. JSON은 자동저장 파일이 아니라 브라우저 데이터 삭제, PC 이동, 장기 보관에 대비해 사용자가 만드는 수동 백업이다.

## 2. 현재 기준선

v0.5.0에서 이미 제공하는 다음 기능은 유지한다.

- C·온도·P·Mn·Si·S 문헌 기반 종점 참고예상
- 최신 유효 샘플을 이용한 차지 내 예상 보정
- 완료 차지 종점 오차대장과 비교군별 계수 추천
- 추천값 검토 후 새 계수버전 적용 및 과거 버전 복구
- 여러 진행 차지 전환, G0~G8 수동 기록, 정정·무효·단계 복귀
- IndexedDB 자동저장, CSV ZIP 백업·복원, XLSX 열람 보고서
- 저장 충돌·쓰기 실패 감지와 비상 백업

## 3. 확정 범위

### P0-01. 프로그램형 자동저장

- 상태가 변경되면 약 250ms 지연 후 IndexedDB에 저장한다.
- 평상시 작업자는 저장 버튼이나 외부 저장경로를 지정하지 않아도 된다.
- 저장 상태를 전 화면에서 `저장 중 / 자동저장 완료 / 저장 실패 / 다른 창 충돌`로 구분한다.
- 마지막 저장 시각과 저장 revision을 표시한다.
- 같은 브라우저·프로필에서 HTML을 다시 열면 마지막 정상 revision을 자동으로 불러온다.
- 신규 차지·설정 입력 중 미완료 양식도 초안으로 보존한다.
- 저장 실패·충돌 상태에서는 새 조업 입력을 막고 `다시 저장`, `비상 JSON 저장`, `최신 상태 다시 읽기`를 제공한다.

### P0-02. 내부 복구점

- 일반 입력마다 전체 상태 사본을 만들지 않는다. 다음 중요 시점에 복구점을 만든다.
  - 단계 전환 전
  - 차지 취소·초기화·전체 불러오기 전
  - 확정 종점 분석 지정·정정 전
  - 계수 새 버전 적용·과거 버전 복구 전
  - 사용자가 `현재 상태 복구점 만들기`를 누른 때
- 복구점은 `생성 시각, 생성 이유, 작업자, 저장 revision, 진행 차지 수, 완료 차지 수, 계수버전`을 표시한다.
- 최신 20개까지만 보존하고 30일이 지난 복구점은 정리한다. 보호 표시한 복구점은 자동 정리하지 않는다.
- 복구점 상태 사본에는 다른 복구점과 임시 화면 상태를 다시 포함하지 않는다. 복구점이 중첩되어 저장용량이 기하급수적으로 커지는 것을 막는다.
- 복구점 복원은 과거 레코드를 몰래 덮어쓰지 않는다. 복원 직전 상태를 새 안전 복구점으로 남기고 `복구점에서 복원` 이력을 추가한다.
- 마지막 전체 불러오기는 7일 안에 `불러오기 취소`할 수 있도록 별도 안전 복구점을 유지한다.

### P0-03. 단일 JSON 수동 저장

- 기본 버튼 명칭은 `전체 데이터 JSON으로 저장`으로 한다.
- JSON 파일을 입력할 때마다 자동 생성하거나 외부 폴더에 자동으로 덮어쓰지 않는다. 작업자가 백업 버튼을 누른 때만 만든다.
- 기본 파일명은 `BOF_Coach_Backup_YYYY-MM-DD_HHmm.json`으로 한다.
- 다운로드 전에 메모리에서 만든 파일을 같은 복원 경로로 다시 읽어 구조·해시·건수·참조를 검증한다.
- JSON에는 다음을 포함한다.
  - 차지, 단계, 조업 이벤트, 샘플, 분석 결과, 종점 실제값
  - 정정·무효·채택·취소·출강 정정 이력
  - 강종·재료·설비·단위·계산계수와 모든 계수버전
  - 예상 스냅샷, 종점 오차, 학습 제외 사유, 추천·검증 이력
  - 작업자 표시명과 operation log
  - 내부 복구점 메타데이터와 보존된 복구점
  - 앱 버전, 백업 스키마, 생성 시각, 데이터 건수, 무결성 정보
- JSON은 UTF-8이며 계산에 사용하는 숫자는 단위 정규화값과 원 입력값을 구분한다.
- 백업 파일 안에 회사명·사업소명 같은 식별정보를 자동으로 만들어 넣지 않는다. 사용자가 현장 프로필을 만들었을 때만 해당 값이 포함됨을 저장 전에 알린다.

### P0-04. JSON 안전 불러오기

- 기본 버튼 명칭은 `JSON 백업 불러오기`로 한다.
- 파일 선택 직후 적용하지 않고 다음 미리보기를 먼저 표시한다.
  - 생성 시각, 앱·스키마 버전, 작업자, 차지 수, 진행 차지 수
  - 강종·설비·계수버전 수, 완료 오차 수, DEMO/실제 구분
  - 해시·스키마·참조·수치 검증 결과와 경고
- JSON 텍스트를 코드로 실행하지 않고 데이터로만 파싱한다.
- 허용 필드 목록에 맞춰 새 객체를 구성하며 `__proto__`, `constructor`, `prototype` 같은 위험 키를 상태 객체에 병합하지 않는다.
- v0.6 단일 파일 불러오기 한도는 50MiB로 시작한다. 초과 파일은 브라우저를 멈추게 하지 않고 적용 전에 거부하며, 실측 성능시험 뒤 한도를 조정한다.
- 형식, SHA-256, 필수 필드, 중복 ID, 참조 관계, 유한 숫자, 시간 순서, 단계, 설정 범위 검사를 모두 통과해야 한다.
- 검증 실패 시 현재 작업공간을 한 건도 바꾸지 않는다.
- 빈 작업공간에서는 확인 후 전체 복원한다.
- 데이터가 있는 작업공간에서는 자동 병합하지 않는다. `현재 상태 안전 복구점 생성 → 비교 요약 → 전체 교체 재확인`을 거친다.
- 불러온 결과는 새 storage revision으로 저장하고 `backup_restored` 이력을 추가한다.
- 임의 병합, 일부 행만 복원, 같은 ID 자동 덮어쓰기는 v0.6에서 지원하지 않는다.

### P0-05. 백업 상태와 알림

자동저장과 외부 백업을 같은 의미로 표시하지 않는다.

| 상태 | 의미 | 작업자 행동 |
| --- | --- | --- |
| 자동저장 완료 | 현재 브라우저 안에 저장됨 | 계속 작업 가능 |
| 외부 백업 최신 | 마지막 중요 변경이 JSON에 포함됨 | 추가 행동 없음 |
| 외부 백업 필요 | 차지 완료·계수 변경 등이 JSON에 미포함 | JSON 저장 권장 |
| 저장 실패 | 브라우저 자동저장이 실패함 | 입력 중지 후 재시도 또는 비상 JSON |

다음 시점에 외부 백업 필요 상태로 바꾼다.

- 새 차지 출강 완료
- 확정 종점 분석 지정·정정
- 계수 새 버전 적용·복구
- 전체 JSON 또는 구형 ZIP 불러오기
- 마지막 JSON 저장 뒤 24시간이 지나고 데이터 변경이 있는 경우

`외부 백업 필요`는 안내 상태이며 조업 입력을 막지 않는다. 작업자가 지금 백업하지 않아도 IndexedDB 자동저장은 계속된다. 단, 브라우저 데이터 삭제·PC 교체에는 복구할 수 없다는 설명을 함께 표시한다.

브라우저는 다운로드 폴더에 실제 보관되었는지 알 수 없으므로 `파일 생성·재읽기 검증 완료`와 `승인 폴더 보관 확인`을 별도로 기록한다.

### P0-06. 학습 데이터 재현성

- 학습 원본은 완료된 실제 차지의 출강 직전 예상 스냅샷과 확정 종점 실제값이다.
- DEMO, 취소, 필수값 누락, 종점 미확정, 비교군 불일치 데이터는 제외하고 사유를 남긴다.
- 비교군은 최소 `강종군 + 설비군 + 계산식 버전 + 계수버전 + DEMO/실제`로 분리한다.
- v0.5 관문을 유지한다.
  - 1~9건: 오차 원장
  - 10~29건: 편향 경향
  - 30~49건: 임시 후보, 적용 불가
  - 학습 50건 이상: 보정 후보
  - 이후 독립 검증 20건 이상: 기존 계수와 성능 비교
- 추천을 만들 때 다음을 `training run`으로 고정한다.
  - 사용·제외한 차지 ID와 제외 사유
  - 데이터 기간과 비교군
  - 문헌모델·계수·설정 버전
  - 데이터셋 SHA-256
  - 학습·검증 분할, 편향, MAE, 중앙절대오차, 목표 적중률
  - 후보값, 생성자, 검토 결과, 적용·보류 사유
- 과거 차지 정정으로 학습 데이터가 바뀌면 기존 실행을 삭제하지 않고 `오래된 결과`로 표시하고 새 실행을 만든다.
- 같은 데이터셋 해시·비교군·모델·계수버전의 실행이 이미 있으면 중복 실행을 만들지 않고 기존 결과를 재사용한다.
- 승인 계수는 활성화 이후 새로 시작하는 차지에만 적용한다. 진행·완료 차지의 저장된 예상과 기준 스냅샷을 소급 변경하지 않는다.
- JSON 저장·불러오기 뒤 같은 데이터셋 해시와 같은 계수버전에서는 같은 후보와 지표가 나와야 한다.

학습 선순환은 다음 경로로 고정한다.

```text
문헌 기본예상
→ 조업·샘플 수동 입력
→ 최신 유효 샘플로 해당 차지 예상 갱신
→ 출강 전 예상 스냅샷 고정
→ 확정 종점 실제값과 오차 계산
→ 비교군·품질 관문 통과 데이터 누적
→ 계수 후보와 검증지표 생성
→ 작업자 검토·승인
→ 새 계수버전으로 이후 차지 예상·설명 개선
```

### P0-07. 예상 설명 개선

C·온도·P·Mn·Si·S 각각에 다음 근거를 숫자 가까이에 표시한다.

- 문헌 최초예상
- 최신 유효 샘플 보정량과 사용한 샘플 시각
- 승인된 사업소·설비 보정량과 계수버전
- 최종 참고예상과 예상 범위
- 적용한 비교군, 유효 완료 차지 수, 검증 지표
- 입력 누락·범위 밖 조건·낮은 신뢰등급과 fallback 이유

설명 문구는 오프라인 규칙형 템플릿으로 생성한다. 생성형 AI가 사실처럼 자유 문장을 만드는 구조는 사용하지 않는다. 데이터가 적을 때는 `문헌 참고`, 충분하지만 미승인일 때는 `현장 후보`, 검증·승인된 경우에만 `현장 보정 적용`으로 구분한다.

### P0-08. 기존 파일 호환

- v0.6의 기본 저장·복원은 단일 JSON이다.
- 기존 v0.5 CSV ZIP 불러오기는 v0.6에서 유지한다.
- CSV ZIP 저장은 `호환용 CSV ZIP` 보조 버튼으로 유지한다.
- XLSX는 계속 사람이 보는 보고서이며 복원 입력으로 사용하지 않는다.
- v0.6 첫 실행에서 v0.5 IndexedDB 상태를 마이그레이션하고, 원본을 안전 복구점으로 남긴다.
- v0.5 프로그램은 v0.6 JSON을 읽을 수 없으므로 첫 마이그레이션 전에 v0.5 호환 ZIP 저장을 한 번 안내한다.

## 4. JSON 백업 계약 초안

최상위 구조는 다음처럼 고정한다. 실제 구현에서는 필드별 스키마 문서를 별도로 만든다.

```json
{
  "format": "bof-endpoint-coach-backup",
  "schemaVersion": "0.6.0",
  "appVersion": "0.6.0",
  "export": {
    "exportId": "EXP-...",
    "createdAt": "2026-08-23T15:30:00+09:00",
    "storageRevision": 123
  },
  "summary": {
    "heatCount": 0,
    "eventCount": 0,
    "coefficientVersionCount": 0,
    "trainingRunCount": 0
  },
  "payload": {
    "workspace": {},
    "recoveryPoints": [],
    "modelRegistry": [],
    "trainingRuns": []
  },
  "integrity": {
    "algorithm": "SHA-256",
    "canonicalization": "sorted-json-v1",
    "contentSha256": "..."
  }
}
```

- 해시는 `integrity`를 제외한 전체 문서의 키를 정렬한 canonical JSON UTF-8 바이트를 기준으로 계산한다.
- SHA-256은 파일 손상·변조 탐지용이며 작성자의 신원을 증명하는 전자서명이 아니다. 스키마·범위·참조 검사를 함께 통과해야 한다.
- 스키마가 더 최신이면 억지로 복원하지 않고 지원 버전을 표시한다.
- 이전 스키마는 순차 마이그레이션하며 각 단계의 변환 전·후 건수와 경고를 기록한다.
- 알 수 없는 필드는 원칙적으로 보존하되 계산에 사용하지 않는다. 안전에 영향을 주는 필수 필드가 불명확하면 복원을 중지한다.

## 5. 화면 구성 확정안

### 5.1 전역 저장 상태

- 상단 우측에 `자동저장 완료 · 15:30:21`을 항상 표시한다.
- 클릭하면 저장 revision, 브라우저 저장 상태, 마지막 JSON, 복구점 수를 펼친다.
- 오류는 색만으로 표시하지 않고 상태명과 다음 행동 버튼을 함께 표시한다.

### 5.2 분석·리포트 화면의 저장·복구 구역

위에서 아래 순서는 다음으로 고정한다.

1. 현재 자동저장 상태
2. `전체 데이터 JSON으로 저장` 주 버튼
3. `JSON 백업 불러오기` 주 버튼
4. 최근 JSON 저장 시각·건수·해시
5. 내부 복구점 목록과 미리보기·복원
6. `호환용 CSV ZIP`, `Excel 보고서` 보조 버튼

### 5.3 불러오기 화면

- `파일 선택 → 검사 중 → 검사 결과 → 현재/백업 비교 → 전체 교체 확인 → 완료` 순서로 진행한다.
- 현재 작업공간이 비어 있지 않으면 빨간 경고만 띄우지 않고 `현재 상태는 안전 복구점에 보관됩니다`와 `불러오기 취소 가능 기한`을 설명한다.
- 버튼은 `취소`, `현재 데이터 JSON 저장`, `검증된 백업으로 전체 교체`로 구분한다.

### 5.4 학습·계수 화면

- 추천값보다 먼저 비교군·데이터 단계·제외 건수·데이터 기간을 표시한다.
- `왜 이 값인가`를 열면 문헌 기본값, 샘플 보정, 현장 편향, 학습/검증 지표를 보여준다.
- 추천 전달은 계속 `설정 초안으로`만 가능하고 즉시 적용하지 않는다.
- 계수버전별 생성·적용·중지·복구와 그때 사용한 데이터셋 해시를 조회한다.

## 6. 모듈 분리 원칙

하나의 파일에 저장·복원·학습을 몰아넣지 않는다.

| 책임 | 권장 모듈 |
| --- | --- |
| IndexedDB 현재 상태 | `storage/indexedDb.js` 유지·스키마 확장 |
| 자동저장 조정 | `storage/autoSaveCoordinator.js` 또는 전용 hook |
| 복구점 저장·정리 | `storage/recoveryStore.js` |
| JSON 직렬화·해시 | `reports/jsonBackup.js` |
| 백업 스키마·정합성 | `domain/backupSchema.js` |
| 복원 미리보기·교체 계획 | `domain/restorePlan.js` |
| 학습 실행·데이터셋 해시 | `domain/trainingRun.js` |
| 예상 설명 생성 | `domain/predictionExplanation.js` |
| 화면 구성 | 기존 화면과 작은 저장·복구 구성요소로 분리 |

기존 `useCoachState`에는 저장 세부 구현을 더 쌓지 않고, 상태 변경과 저장 조정을 분리한다.

## 8. 필수 검증

### 저장·복구

- 같은 Chrome·Edge 프로필에서 단일 HTML 종료·재실행 후 동일 revision과 차지를 복구한다.
- 저장 중 즉시 닫기, IndexedDB 읽기·쓰기 실패, quota 부족, 복수 창 충돌을 시험한다.
- 복구점 20개·30일 정리와 보호 복구점 보존을 시험한다.
- 전체 불러오기 뒤 마지막 불러오기 취소가 원상태를 새 revision으로 복구하는지 시험한다.

### JSON

- 한글·영문·특수문자·소수·0·빈 선택값을 포함해 JSON 왕복 후 의미가 동일해야 한다.
- 내보낸 파일을 즉시 다시 읽어 SHA-256, 건수, 참조를 검증한다.
- 한 글자 변조, 잘린 파일, 중복 ID, 잘못된 단계·시간, NaN 대체값, 미지원 스키마를 모두 거부한다.
- 실패한 불러오기가 기존 IndexedDB를 바꾸지 않는지 시험한다.
- v0.5 ZIP과 v0.5 IndexedDB 마이그레이션을 시험한다.

### 계산·학습

- JSON 왕복 전후 6성분 예상, 예상 범위, 적용 계수버전, 오차대장, 추천값과 지표가 동일해야 한다.
- DEMO/실제와 서로 다른 강종·설비·계수버전이 섞이지 않아야 한다.
- 정정된 완료 차지 때문에 기존 training run이 오래된 결과로 바뀌고 새 실행이 생성되는지 시험한다.
- 목표 범위가 예측 입력이나 자동 학습값으로 사용되지 않는지 회귀시험한다.

### UI·접근성·환경

- 1920×1080, 1366×768, 960×540 논리 화면과 200% 확대에서 핵심 조작을 완료한다.
- 저장 상태가 색 없이도 구분되고 키보드로 저장·불러오기·복구점 선택을 수행한다.
- Chrome·Edge 설치형 브라우저에서 `file://` 단일 HTML을 실제 실행한다.
- 네트워크 요청과 외부 글꼴·스크립트가 없는지 검사한다.
- 실제 회사 PC 정책 적합성은 별도 현장 검증으로 남기고 개발 PC 결과로 PASS 처리하지 않는다.
