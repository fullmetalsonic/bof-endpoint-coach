# 취련 코치 v0 UI 기능 구성 초안

## 설계 원칙

이 문서는 색상·폰트·그래픽이 아니라, 현장 사용자가 **무엇을 보고, 무엇을 누르고, 다음에 무엇을 기록하는지**를 정한다.

정정·무효·단계 복귀·출강 후 정정의 현재 버튼 배치와 화면 흐름은 [정정·이력 관리 화면 흐름](정정이력_화면흐름_버튼배치_2026-08-23.md)을 우선 적용한다.

1. 현재 진행 중인 차지의 입력·확인 행동이 첫 화면의 중심이다.
2. 목표 대비 상태, 데이터 신선도, 다음 행동을 한 상태값으로 합치지 않는다.
3. 설정·백업·이력은 필요하지만, 진행 중 차지의 입력을 방해하지 않게 분리한다.
4. 기준 미승인·데이터 누락이면 계산값을 꾸며서 표시하지 않고, 먼저 부족한 항목을 보여 준다.
5. 색상만으로 `높음/낮음/정상/미확인`을 구분하지 않는다. 항상 텍스트·아이콘·범위값을 함께 표시한다.

## 전체 화면 구조

```text
상단 공통 바
  [현재 차지] [차지 이력] [기준값 설정] [백업·보고서] [도움말]

현재 차지 화면
  상단: 진행 중 차지 목록과 현재 작업 대상
  좌측: G0~G8 진행 게이트
  중앙: 최신 분석/목표 비교 + 다음 행동 + 이벤트 입력
  우측: 확인 필요 목록 + 데이터 신선도 + 계산 근거
```

v0은 공용 PC에서 여러 차지를 진행 상태로 관리한다. 사용자는 `진행 중 차지 목록`에서 한 건을 선택하고, 선택된 현재 작업 대상의 입력·품질 비교·게이트·확인 항목만 본다. 다른 차지의 이벤트는 목록 전환만으로 현재 차지에 섞이지 않는다.

## 1. 상단 공통 바

| 메뉴/버튼 | 기능 | 배치 이유 |
| --- | --- | --- |
| `현재 차지` | 진행 중 차지의 입력·확인 화면 | 기본 진입점 |
| `차지 이력` | 완료/취소 차지 검색·비교·재열람 | 진행 중 입력과 분리 |
| `기준값 설정` | 강종군·재료·게이트·단위·버전 관리 | 변경 작업을 일반 입력과 분리 |
| `백업·보고서` | CSV 백업/복원, XLSX 보고서 생성 | 파일 작업을 현장 입력과 분리 |
| `도움말` | 상태 용어·단위·CSV 규칙·안전 경계 | 사용 중 혼동 해소 |

상단에는 `진행 중 차지 N건` 목록, 현재 작업 대상 차지 ID, 강종군, 진행 게이트, 마지막 저장 시각을 항상 표시한다. 목록을 클릭하면 현재 작업 대상이 바뀌며, 미저장 입력이 있으면 저장/취소/유지 확인을 거친다. 기준값 설정에는 현재 적용 버전이 직접 보이는 링크를 둔다.

## 2. 현재 차지 화면

### 2-1. 좌측 — G0~G8 진행 게이트

- G0~G8을 세로로 표시한다.
- 각 게이트는 `미시작 / 진행 중 / 확인 필요 / 완료 / 예외 기록` 상태를 텍스트와 아이콘으로 보인다.
- 현재 게이트를 누르면 필요한 입력 항목과 완료 조건이 중앙에 열린다.
- 다음 게이트로 이동은 필수 입력이 갖춰졌을 때만 제안한다. 강제 이동은 하지 않는다.

### 2-2. 중앙 상단 — 지금 판단해야 할 핵심 정보

중앙 상단에는 숫자를 많이 나열하지 않고 아래 네 블록만 둔다.

| 블록 | 내용 |
| --- | --- |
| `다음 행동` | 예: 분석 결과 입력, 재샘플 검토, 출강 전 확인 |
| `최신 분석` | 샘플 ID, 채취/입력 시각, 기본 품질 6개(C·온도·P·S·Mn·Si)와 강종별 관리 성분 |
| `목표 대비` | 각 관리 항목의 높음/낮음/목표 범위 내/미확인 |
| `데이터 상태` | 최신 분석의 경과 시간, 단위/기준값/필수 입력 누락 여부 |

### 2-3. 중앙 중단 — 품질 정보의 밀도와 확장

- 첫 화면의 품질 범위표는 기본 후보 6개(C·온도·P·S·Mn·Si)를 표시한다. 실제로는 강종군 설정에서 활성화된 항목만 보인다.
- 강종 특화 합금·잔류·청정도 항목은 `성분 상세` 표에 추가한다. 목표가 승인된 항목은 범위 막대도 표시할 수 있다.
- 샘플 채취/분석 입력 시각, 기준 버전, 참고 예상의 계산 조건은 품질값 가까이에 둔다.
- 누적 산소량, 취련 시간, 재취련, 투입 이력은 품질 성분과 합산하지 않고 별도 공정 참고 정보로 표시한다.

세부 정의는 `../domain/품질관리항목_초안.md`를 따른다.

### 2-4. 중앙 하단 — 이벤트 입력 버튼

이벤트는 큰 버튼으로 분리하고, 버튼을 누르면 해당 입력만 받는다.

```text
[장입/투입 기록] [샘플 채취] [분석 결과 입력]
[취련 체크포인트] [재취련 기록] [출강 시작/완료]
```

- `장입/투입 기록`: 재료 선택 → 수량 → 단위 → 시각 → 로트(선택)
- `샘플 채취`: 샘플 ID → 채취 시각
- `분석 결과 입력`: 샘플 ID 선택 → 수신 시각 → 성분/온도 → 단위
- `취련 체크포인트`: 경과 시간·실제/계획 풍량 패턴·누적 산소량·단계명·메모처럼 현장에서 확인 가능한 값. 적용 시작 시각은 현재 시각을 기본값으로 하되 수정 가능
- `재취련 기록`: 시작/종료·사유·후속 샘플 연결
- `출강 시작/완료`: 시각·출강량·최종 결과·예외 메모

각 버튼은 현재 게이트에서 논리적으로 가능한 경우에만 활성화한다. 예를 들어 존재하지 않는 샘플에는 분석 결과를 입력할 수 없다.

### 2-4. 우측 — 확인 필요와 계산 근거

위쪽은 `확인 필요 목록`이다. 우선순위는 다음과 같다.

1. 계산을 막는 누락/미승인 기준
2. 샘플 시점·단위·범위 이상
3. 목표 범위 이탈
4. 일반 메모/선택 입력 누락

아래쪽은 `계산 근거`다. 참고 계산이 가능할 때만 사용한 입력값, 재료 기준 버전, 환산 규칙, 계산 시각을 보여 준다. 계산 불가라면 결과 숫자 대신 불가 사유와 연결된 설정 메뉴를 보여 준다.

시간 경과형 참고 예상이 활성화되면 `계산 기준 시각(PC 로컬 시간)`, `마지막 수동 입력 시각`, `실제 입력 기준/계획값 포함`을 계산 근거에 함께 표시한다. 세부 규칙은 `../domain/시간경과형_참고예상_입력규칙_초안.md`를 따른다.

## 3. 상태 표시 체계

### 3-1. 목표 대비 상태

성분·온도마다 독립적으로 표시한다.

| 상태 | 조건 | 표시 문구 예 |
| --- | --- | --- |
| 범위 내 | 최신 유효값이 목표 최소~최대 안 | `목표 범위 내` |
| 낮음 | 최신 유효값이 목표 최소보다 낮음 | `목표보다 낮음` |
| 높음 | 최신 유효값이 목표 최대보다 높음 | `목표보다 높음` |
| 미확인 | 값/단위/목표가 없음 또는 유효성 미확인 | `비교 불가` |

`안정권`은 성분/온도만으로 표시하지 않는다. 모든 필수 관리 항목이 범위 안이고, 최신 분석이 현장 승인 유효 시간 안이며, 필요한 게이트 확인이 끝났을 때만 `조건 충족 — 출강 검토 가능`으로 표시한다.

### 3-2. 데이터 신선도 상태

| 상태 | 표시 문구 예 |
| --- | --- |
| 최신 | `최신 분석: 채취 HH:MM / 수신 HH:MM` |
| 확인 필요 | `분석 시점 확인 필요` |
| 오래됨 | `최신 분석 이후 이벤트 발생 — 재확인 검토` |
| 누락 | `샘플/분석 데이터 없음` |

시간의 정확한 경고 기준은 설정 화면에서 현장 승인값으로 넣는다.

### 3-3. 위험 표현 원칙

- `위험`은 설비·안전 경보처럼 사용하지 않는다. 도구의 데이터·목표 비교 상태에는 `확인 필요`, `목표 이탈`, `계산 불가`를 쓴다.
- 현장 안전 절차에 해당하는 위험 신호는 도구가 만들거나 해제하지 않는다.
- 색상은 보조 수단이다. 예: 범위 내/높음/낮음/미확인은 서로 다른 색과 함께 텍스트·아이콘·수치를 병기한다.

### 3-4. 목표 범위 막대와 예상 종점값

각 관리 성분과 온도는 **가로 목표 범위 막대**로 표시한다. PC 화면에서는 항목명·단위·수치·상태 문구를 한 줄에 함께 보여 주기 쉬워, 수직 막대보다 가로 막대를 기본으로 한다. 필요하면 요약 카드에서만 세로 막대를 보조적으로 쓸 수 있다.

```text
C (%)   낮음                 목표 범위                 높음
        ────────|════════════════════|────────────
              ● 현재 분석값        ○ 예상 종점값
        0.00   최소              최대

상태: 현재 분석은 범위 내 / 예상 종점은 상한 접근 / 분석 채취 HH:MM
```

| 요소 | 표시 방식 | 의미 |
| --- | --- | --- |
| 목표 범위 | 막대 중앙의 채워진 구간 + 최소/최대 기준선 | 승인된 목표 최소~최대 |
| 현재 분석값 | 채워진 원 `●` | 실제 최신 분석/온도 값 |
| 예상 종점값 | 빈 원 `○` | 승인된 기준과 충분한 입력으로 계산한 참고 예상값 |
| 예상 범위 | 가는 선 또는 옅은 띠 | 예측 불확실성 범위. 계산할 근거가 있을 때만 표시 |
| 막대 밖 | 낮음/높음 영역 | 목표 이탈 방향을 즉시 확인 |
| 데이터 상태 | 막대 아래 텍스트 | 채취/수신 시각, 최신성, 계산 가능 여부 |

예상 종점값 표시 규칙:

1. 현재 분석값과 예상 종점값의 **모양을 반드시 다르게** 한다.
2. 계산 허용 기준을 충족하지 못하면 빈 원·예상 범위 대신 `예상 계산 불가: 사유`를 표시한다.
3. 최신 분석이 현장 승인 유효 시간을 벗어나면 예상값을 흐리게 유지하지 않고 숨기며, `재확인 검토`를 표시한다.
4. 예상값은 `예상` 또는 `참고`라는 텍스트와 계산 시각·기준 버전을 함께 표시한다.
5. 막대 범위를 벗어나는 값은 잘라내지 않는다. 막대 끝 바깥 방향 화살표와 실제 수치를 표시한다.

한 화면에 모든 원소를 같은 막대에 합치지 않는다. C, 온도, P, Mn 등은 각각 단위와 목표 범위가 다르므로 **항목별 막대**를 세로 목록으로 둔다. 사용자가 스크롤 없이 확인할 핵심 항목만 강종군 기준에서 선택한다.

### 3-5. 강종군별 관리 항목의 동적 행 구성

기본 품질 후보는 C·온도·P·S·Mn·Si 여섯 항목이며, 고정 공정 기준은 아니다. 실제 화면에는 강종군 설정에서 활성화되고 분석 가능한 항목만 표시한다. 강종군 설정에서 `관리 항목 추가`를 하면 차지의 성분 상세 표와, 목표가 승인된 경우 목표 비교 표·범위 막대에 해당 항목이 추가된다.

| 설정값 | 화면 동작 |
| --- | --- |
| 기본 품질 표시 | 현재 차지 첫 화면에 기본 후보 중 활성 항목을 최대 6개 표시 |
| 추가 표시 | `성분 상세`에서 강종 특화 합금·잔류·청정도 항목을 펼침 |
| 필수 입력 | 샘플/분석에 없으면 `비교 불가`와 확인 필요 목록에 표시 |
| 선택 입력 | 값이 있으면 비교하지만, 없다고 계산을 막지는 않음 |
| 표시 순서 | 강종군 설정의 순서대로 행을 배치 |
| 중지 항목 | 새 차지에서는 숨기되, 과거 차지의 기록·결과에는 유지 |

목표 방식도 항목마다 다르게 처리한다.

| 목표 방식 | 막대 표시 |
| --- | --- |
| 범위 | 최소~최대 사이를 목표 구간으로 채움 |
| 상한만 | 상한선 왼쪽을 허용 영역으로 표시 |
| 하한만 | 하한선 오른쪽을 허용 영역으로 표시 |
| 목표값±허용차 | 중심 목표값과 양쪽 허용 범위를 함께 표시 |

행을 무제한으로 한 화면에 늘리지는 않는다. 기본 품질 6개를 먼저 유지하고, 강종 특화 항목은 접어서 펼치는 방식으로 입력 버튼과 출강 전 확인 정보가 화면 아래로 밀리지 않게 한다. 세부 기준은 `../domain/품질관리항목_초안.md`를 따른다.

## 4. 기준값 설정 화면의 기능 배치

설정 화면 첫 단계에는 다음 일곱 탭을 둔다.

```text
[강종군] [재료] [관리 게이트] [단위·환산] [설비·조업 조건] [계산·보정 계수] [버전·승인]
```

- `강종군`: 추가, 복제, 새 버전, 중지, 관리 성분/목표 범위
- `재료`: 추가, 조성/수율/단위, 로트 정책, 사용 중지
- `관리 게이트`: G0~G8별 필수 입력, 경고 문구, 확인 역할
- `단위·환산`: 허용 단위와 자동/금지 변환 규칙
- `설비·조업 조건`: 전로/랜스/저취 프로필, 조업 단계 템플릿, 설비 상태·현장 특화 영향인자
- `계산·보정 계수`: 계수 출처·적용 범위·가상 검증·그림자 검증·승인 상태
- `버전·승인`: 초안, 검토 요청, 승인, 중지, 변경 이력

`새로 추가`와 `승인`은 같은 위치에 두지 않는다. 새 설정은 항상 초안으로 시작하고, 승인 작업은 검토 화면에서만 가능하게 한다.

## 5. 차지 이력 화면

- 검색: 차지 ID, 기간, 강종군, 상태, 재취련/재샘플 여부
- 목록: 목표 대비 결과, 출강 시각, 적용 기준 버전, 예외 여부
- 상세: G0~G8 타임라인, 원본 입력/환산값, 계산 근거, 변경 이력
- 비교: 같은 강종군의 차지 2~3건을 나란히 비교. v0 초기에는 선택 기능으로 둔다.

완료 차지는 수정 대신 정정 이벤트를 추가한다. 원본을 숨기거나 덮어쓰지 않는다.

## 6. 백업·보고서 화면

| 버튼 | 기능 |
| --- | --- |
| `전체 CSV 백업 만들기` | 복원용 CSV 백업 묶음 생성. 생성/검증 상태와 데이터 건수 표시 |
| `백업 묶음 복원` | 빈 저장소에서만 검사 → 미리보기 → 전부 반영/취소 |
| `선택 차지 데이터 내보내기` | 열람용 CSV 생성. 복원 입력으로 사용하지 않음 |
| `XLSX 보고서 만들기` | 선택 기간/차지의 사람이 보는 보고서 생성 |
| `최근 백업 확인` | 마지막 저장·생성·검증 백업 시각과 파일 정보 표시 |

`백업 묶음 복원`과 `XLSX 보고서 만들기`는 인접시키지 않는다. 복원과 보고서는 목적이 다르기 때문이다.

## 7. 대표 사용자 흐름

```text
현재 차지 열기
→ G0 누락/기준 확인
→ 장입·투입/샘플/분석을 사건 순서대로 입력
→ 목표 대비 + 데이터 상태 확인
→ 필요한 경우 재샘플·재취련 기록
→ 출강 검토 및 출강 결과 기록
→ 완료 차지 이력/보고서로 확인
```

## 현장 확인이 필요한 UI 가정

1. 진행 중 차지 목록을 공용 PC 화면에서 몇 개까지 한 줄에 보여야 하는지
2. 각 이벤트를 입력하는 실제 역할과 입력 가능 시점
3. 분석 결과를 입력할 때 필요한 성분 항목의 수와 순서
4. 현장에서 쓰는 상태 용어: `출강`, `추출`, `종점`, `재취련` 등의 표준 표시명
5. 화면에서 경고를 확인한 뒤 확인 버튼/사유 입력이 필요한지
