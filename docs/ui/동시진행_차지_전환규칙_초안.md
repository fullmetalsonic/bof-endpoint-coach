# 동시 진행 차지·전환 규칙 초안

상태: 개발 기본안. 공용 PC에서 여러 차지를 병행하되, 한 번의 입력은 선택된 차지 한 건에만 기록되게 하는 규칙이다.

## 1. 기본 구조

```text
상단 공통 바
진행 중 차지 (N)  [차지 A] [차지 B] [차지 C] … [전체 목록] [새 차지]
현재 작업 대상: 차지 A · 강종군 · G6 · 마지막 저장 HH:MM

좌측 게이트 / 중앙 품질·입력 / 우측 확인 필요
    └ 모두 차지 A의 데이터만 표시·입력
```

- 여러 차지를 동시에 진행 상태로 둘 수 있다.
- 사용자는 진행 중 차지 목록을 클릭해 현재 작업 대상을 전환한다.
- 중앙 화면, 좌측 G0~G8, 우측 확인 패널, 하단 이벤트 버튼은 항상 선택된 차지 한 건에만 연결된다.
- 목록 자체에 실제 분석 수치를 모두 나열하지 않는다. 차지 ID, 강종군, 현재 게이트, 마지막 기록 시각, 확인 필요 건수만 요약한다.

## 2. 차지 목록 표시 규칙

| 항목 | 표시 규칙 |
| --- | --- |
| 목록 대상 | `초안`, `진행 중`, `결과 검토` 상태의 차지 |
| 정렬 | 확인 필요가 있는 차지 우선 → 마지막 기록 시각 최신순 |
| 기본 표시 수 | 화면 폭에 맞는 수만 가로 표시하고 나머지는 `전체 목록`에서 검색·선택 |
| 현재 작업 대상 | 파란 테두리/배경과 `현재 작업 중` 텍스트를 함께 표시 |
| 확인 필요 | 수치 대신 `확인 필요 N건` 텍스트 표시 |
| 완료·취소 차지 | 진행 목록에서 제거하고 차지 이력에서 열람 |

애플리케이션 내부에 임의의 동시 차지 수 상한은 두지 않는다. 실제 공용 PC의 화면·성능 검증으로 적정 표시 수를 확정한다.

## 3. 전환 안전 규칙

1. 차지 전환 전, 이전 차지의 저장 성공 여부를 확인한다.
2. 저장 완료된 이벤트는 즉시 해당 차지에 고정된다. 다른 차지로 전환해도 이동·복사되지 않는다.
3. 입력창에 아직 저장하지 않은 값이 있으면 `저장 후 전환 / 입력 취소 후 전환 / 현재 차지 유지`를 선택하게 한다.
4. 전환이 끝나면 상단 고정 영역에 `현재 작업 대상: 차지 ID`를 크게 보인다.
5. 이벤트 저장 버튼을 누를 때마다 저장 대상 차지 ID를 버튼 위 또는 확인 문구에 표시한다.
6. 다른 차지의 미결 샘플·확인 필요 항목은 목록의 건수로만 알리고, 선택하지 않은 차지에 자동 입력·자동 게이트 이동을 하지 않는다.

## 4. 새 차지·완료·취소 규칙

- `새 차지`는 진행 중 차지 목록에서 만들 수 있으며, 차지 ID가 기존 유효 차지와 중복되면 생성하지 않는다.
- 새 차지는 생성 직후 `초안`으로 목록에 나타난다.
- 출강 완료·취소 차지는 목록에서 사라지지만, 해당 차지의 이벤트·정정·적용 기준 버전은 이력에서 유지한다.
- 진행 중 차지를 숨기거나 강제로 종료할 때는 사유를 기록한다.

## 5. 백업·복원 규칙

- 복원용 CSV 백업은 모든 차지·샘플·분석·기준 버전을 포함한 전체 묶음으로만 만든다.
- 선택 차지 데이터 내보내기는 열람용이며 복원 입력으로 사용하지 않는다.
- 복원 미리보기에는 차지별 건수·오류 건수와 진행 상태를 구분해 보인다.
- 복원은 빈 저장소에서만 하며, 기존 이력 덮어쓰기·자동 병합·로컬 삭제는 하지 않는다.

## 6. 수용 기준

- [ ] 진행 중 차지 2건 이상을 만들고 클릭 전환할 수 있다.
- [ ] 전환 후 품질값·게이트·하단 버튼의 저장 대상이 선택 차지와 일치한다.
- [ ] 미저장 입력이 있는 상태에서 전환하면 저장/취소/유지 선택이 나온다.
- [ ] 다른 차지의 이벤트나 샘플이 현재 차지에 섞이지 않는다.
- [ ] 전체 복원용 백업과 선택 차지 열람용 내보내기의 용도를 화면에서 구분한다.
